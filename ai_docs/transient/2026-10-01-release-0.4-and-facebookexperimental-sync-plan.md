# Hermit/Reverie 0.4 release and the facebookexperimental sync: plan (2026-10-01)

Requested by the owner on 2026-10-01 (thread Y_MLb9Vqy0o): bump to a 0.4 floor on a clean, tested commit; in a release commit, pin hermit→reverie and the other internal dependencies to crates.io versions instead of git; have a clean release candidate on main, imported from the rrnewton fork into facebookexperimental; put an off-main single commit on a release branch for the cargo pins; point the release at facebookexperimental.

Prepared by coord2's `release-plan` research subagent. Nothing was pushed, tagged, published or opened. Evidence was read at rrnewton/hermit main `1139c661ede3165cf3d41486f688f898b6a0829a`, rrnewton/reverie main `dbf2b5c8880bac5fd6a06fa1f296b3eec3590569`, facebookexperimental/hermit main `6b3f7ef0c209d4e7eba55e4333305158b76c77ac` and facebookexperimental/reverie main `f86ceae20a1368dc2fca6ef75b5882fb189b4dfe`. Scratch is on devbig030 under `/var/tmp/release-plan/`. It holds the bare clones, the API answers, the transform script `release-transform.py`, the package logs and the 18 `.crate` files. This doc builds on [the crates.io assessment](2026-10-01-crates-io-release-assessment.md).

## Verdict: does the owner's plan work?

**Mostly yes. One part has to change: the main of facebookexperimental cannot be made equal to rrnewton main.**

- **The part that works:** a 0.4.0 bump on rrnewton main (still git dependencies) with an exact-head validation, then one off-main commit on a `release/0.4` branch that switches to crates.io versions.
  - I built that release commit in scratch. All 18 crates in the minimum release package. All 18 also compile from their packaged tarballs (`cargo package --workspace`, 2 min 54 s on devbig030).
  - The release crates can point at facebookexperimental. Every manifest's `repository` already does.
- **The part that does not work as written:** "import rrnewton fork => facebookexperimental" cannot be a push or a fast-forward.
  - facebookexperimental `main` is ShipIt-owned. Its ruleset "Meta CodeSync ShipIt Enforcement" blocks creation, update and deletion of `refs/heads/main`. It requires linear history and squash-only pull requests, and `current_user_can_bypass` is `never`.
  - Our bot has only `pull` on both repositories.
  - All 26 commits on facebookexperimental main since the fork point carry `fbshipit-source-id`.
  - The only route in is the one already being tried: a pull request on facebookexperimental, then a CodeSync import into fbsource, a reviewed internal landing, and a ShipIt export.
  - That export arrives as one squashed commit whose tree is fbsource's view: autocargo manifests, inserted license headers, and no GPL vendor trees. So facebookexperimental main will **never be byte-equal to, or an ancestor of, the rrnewton RC**.
- **The real long pole is the fbsource import, not the release.**
  - The import diffs have been Unpublished since 2026-09-22: D121022025 (Hermit) and D121064651 (Reverie).
  - The Reverie diff's license check is RED on GPLv3 findings.
  - The import lane's latest regeneration (H19, hermit de130c04) still has 279 Buck failures.
- **Recommendation:** decouple the two.
  - Publish 0.4.0 from `release/0.4`, cut from the validated rrnewton RC.
  - The owner pushes that same branch to facebookexperimental as `release/0.4`, so the published source exists at the `repository` URL. The CLA ruleset exempts `refs/heads/release/**`, and the ShipIt ruleset covers only `main`. This needs the owner's own write access; the bot cannot do it.
  - Let the fbsource import carry the RC tree into facebookexperimental main whenever it lands.

How this interacts with the release, from the import lane's receipt (`ignored/hermit-import-migration-20260925/RESUME-RECEIPT-import-opus4.md`):
- **What the export will carry:**
  - **Autocargo owns the exported manifests.** ShipIt exports the `public_autocargo` manifests, and Hermit's root `Cargo.toml`, which is an autocargo virtual manifest, over GitHub's copies. Every mapped manifest differs from the hand-edited upstream one.
  - **Reverie's ShipIt config strips every other `Cargo.toml`.** `defaultStrippedFiles` removes every non-`public_autocargo` `Cargo.toml` under reverie. reverie-kvm, reverie-liteinst, reverie-preload and reverie-rpc-transport have no ShipIt mapping (hermit: common/test-workdir and hermit-resources). This is the deferred "A6 export decision". Until the configerator and autocargo mappings change, an export would give facebookexperimental an incomplete Cargo workspace.
  - **Versions come from internal autocargo project configs.** The receipt records "reverie.toml 0.2.0". The 0.2.0 change https://github.com/rrnewton/hermit/pull/1196 says the Buck target version has to be bumped too. **A 0.4.0 bump on rrnewton main must be mirrored in fbsource's autocargo configs, or the next export writes the old version back.**
  - **License headers get rewritten.** The import runs `apply-license-headers.py` / LICENSELINT and changed 428 Hermit files and 221 Reverie files. The exported tree differs from rrnewton by those headers.
  - **The GPL vendor trees stay out of fbsource.** Coordinator decision A2: 1,925 files across the four GPL trees (e9patch, SaBRe, DynamoRIO and others). facebookexperimental main will not contain them after an export.
- **Effect on the plan:**
  - The release does not depend on any of this, as long as the release branch is off-main and is not managed by ShipIt.
  - The release does make the drift visible: crates.io source with `repository = facebookexperimental/...` will not match facebookexperimental main. That is why the plan puts `release/0.4` itself on facebookexperimental.
- **Import status:** the import lane, import-opus4, is idle by design. Its plan is to regenerate at Reverie dbf2b5c8 (or newer) plus the current Hermit main once https://github.com/rrnewton/hermit/issues/3260 lands.
  - The 0.4 RC should be the SHA it regenerates from, so that one import carries the RC.

## 4. The release recipe, made concrete

### (a) The 0.4.0 bump on main, still git-based: two pull requests, Reverie first

These are ordinary edits that need validation. The stage cannot be split by repository in reverse: Hermit's reverie git dependencies carry `version = "0.2.0"`, and a requirement of `^0.2.0` does not match 0.4.0. So Hermit can only bump in the same commit that advances its Reverie pin.

1. **Reverie pull request:**
   - All 26 `[package] version = "0.2.0"` lines become `0.4.0`.
   - So do the 59 first-party dependency `version = "0.2.0"` keys.
   - Leave the third-party `0.2.0` lines alone; check each by name.
   - Regenerate `Cargo.lock`, because validation builds with `--locked`.
   - Optionally add a `0.4.0` entry to `CHANGELOG.md`, which stops at "0.1.0 (December 1, 2021)".
   - Validate, then land with `git rebase -S`; Reverie main forbids merge commits.
2. **Hermit pull request**, on top of the new Reverie SHA:
   - All 17 package versions and the 39 first-party dependency version keys become `0.4.0`.
   - Leave `fbinit = "0.2.0"` and `tracing-log = "0.2.0"` alone. They are third-party, and a blanket `sed` would break them.
   - Every reverie `rev =` advances to the new Reverie SHA, along with the `reverie` submodule gitlink.
   - In `hermit-cli/BUCK`, `hermit_build_env` gets `CARGO_PKG_VERSION: "0.4.0"` and `HERMIT_REVERIE_PIN: <new sha>`. `scripts/check-reverie-pin.rs` parses the pin.
   - Regenerate `Cargo.lock`.
   - **No validation code asserts the crate version.** The literal `"0.2.0"` strings in `detcore-model/src/build_info.rs:46` and `ci/manifest-plan/src/runner.rs:14179,14230` are JSON test fixtures; change them only for tidiness.
   - `scripts/check-reverie-pin.rs` (ancestry and monotonic advance, all revs equal) and `scripts/check-git-pin-uniformity.rs` pass by construction if every rev moves together.
   - Leave `tests/reproducible-builds/build-time-0.1.3` alone unless its test is checked; it is a showcase fixture.
3. **Optional but recommended before the RC:** land the fbsource license-header insertions upstream on both mains.
   - Then the import becomes byte-preserving, and facebookexperimental main converges on the RC except for manifests and GPL trees.
   - The receipt notes "PR 3300 adds no fbsource license headers, so fbsource still applies them".

### (b) Exact-head validation

- **Run:** `ci-hub-cli validate-run` on the Hermit bump head, with the Reverie pin at the bumped SHA. Run Reverie's own validate on its head first.
- **Recent costs, for scale:**
  - Hermit full validation: 10 min 05 s for 3,915 of 3,915 tests (https://github.com/rrnewton/hermit/pull/3467, 2026-10-01).
  - Reverie validation: 1,005 s (fba351a5, 2026-09-29).
- **The release candidate** is the landed Hermit main SHA with a PASSED receipt and its Reverie pin.
- **Tag** `v0.4.0-rc1` on both RC SHAs. This needs owner approval; the bot can push tags to rrnewton.

### (c) The sync to facebookexperimental: the mechanism that actually works

- **(c1) Main (Meta-internal; owner action):**
  - Open a new import pull request on facebookexperimental from the RC; https://github.com/facebookexperimental/hermit/pull/94 and https://github.com/facebookexperimental/reverie/pull/42 are the precedents.
  - import-opus4 regenerates D121022025 and D121064651 from it.
  - The owner then has to clear several internal gates:
    - the PR-association killswitch;
    - the GPLv3 license disposition;
    - the RADAR/size approval;
    - human review;
    - the Buck failures;
    - the land itself.
  - The fbsource autocargo configs must carry 0.4.0. The A6 ShipIt mapping for the four unmapped Reverie crates and the two unmapped Hermit crates has to be decided.
  - ShipIt then exports one squash commit to facebookexperimental main and closes the pull request.
  - No date can be promised: none of the September diffs is published yet.
- **(c2) `release/0.4` on facebookexperimental (owner action, minutes of work):**
  - Push the release branch from (d) to `refs/heads/release/0.4` on both facebookexperimental repositories with the owner's own account.
  - Neither ruleset covers that ref: the CLA rule excludes `release/**`, and the ShipIt rule is `main` only.
  - The bot cannot do this; it has pull access only.
  - **First confirm with Meta Open Source** that non-ShipIt release branches are acceptable. Precedent: 21 non-main branches already exist on facebookexperimental/hermit.

### (d) `release/0.4`: one commit on top of the RC, per repository

What I built in scratch (`/var/tmp/release-plan/release-transform.py`, applied to `/var/tmp/release-plan/pkg/`):

- **Versions:**
  - Every first-party manifest is already at 0.4.0 from step (a).
  - Remove `git =` / `rev =` from every first-party dependency and keep `version = "0.4.0"`.
  - In-workspace `path =` dependencies keep `path` plus `version`; `cargo package` strips the path.
- **fbinit:** `{ version = "0.2.0" }`, dropping the rust-shed git `branch = "main"`.
- **liteinst2:** `{ version = "0.1.1" }`. Publish liteinst2 0.1.1 from rrnewton/liteinst2 at 2032b49 or later first, because the 0.1.0 already on crates.io does not build reverie-liteinst.
- **Renames:**
  - `reverie-util` → `reverie-utils`. Dependents keep the `reverie-util = { package = "reverie-utils", … }` key, so no source changes.
  - `nostd-print` → `reverie-nostd-print`, or `publish = false`. Only the SaBRe crates use it, and they are out of the minimum release.
  - Hermit's CLI package `hermit` → `hermit-run` (reserved) or `hermit-cli` (unreserved). Either way it must keep `[lib] name = "hermit"`: 196 `use hermit::` sites break otherwise. The packaged manifest shows `name = "hermit_cli"` without it. The binary stays `hermit`.
- **Publishability:**
  - `hermit-test-workdir` loses `publish = false`, because hermit-cli needs it at run time.
  - The dev-only `detcore-testutils` and `test-allocator` drop their `version` key, so `cargo package` strips them.
  - Remove the optional `detcore-dbt` and `reverie-dbt` dependencies and the `dbt` feature from hermit-cli; `third-party-backends = ["sabre", "e9patch"]` remains. That leaves 19 harmless `unexpected cfg: dbt` warnings; a `[lints.rust] unexpected_cfgs` check-cfg entry silences them.
  - Mark `publish = false` on reverie-dbt, reverie-e9patch, the experimental SaBRe crates, riptrace and reverie-host, so `cargo publish --workspace` skips them.
- **Repository and links:**
  - `repository` is already `https://github.com/facebookexperimental/<repo>` in every manifest; keep it.
  - Repoint the 3 `github.com/rrnewton` links in hermit's `README.md` at facebookexperimental, in the release commit only.
- **License:** copy the root `LICENSE` into each published crate directory, or set `license-file`. Today none of the 18 `.crate` files contains a LICENSE. The header comments point to "the LICENSE file in the root directory", and Reverie's LICENSE carries an Indiana University copyright that BSD requires be reproduced.
- **Pin checks:** `scripts/check-reverie-pin.rs` and `check-git-pin-uniformity.rs` will refuse this branch, because it has no Reverie git rev. That is expected on an off-main branch; do not run main's validation gate against it. The evidence for the branch is the RC receipt plus the package build below.

**Scratch result.** The two repositories cannot be packaged separately before Reverie 0.4.0 is on crates.io: cargo's local overlay only covers one workspace. So I combined liteinst2, the 12 Reverie crates and the 6 Hermit crates into one scratch workspace. Results:

- **`cargo package --workspace --no-verify`:** rc=0; all 18 crates packaged.
- **`cargo +nightly package --workspace`** (nightly 2026-07-11, Hermit's pinned compiler; verifying, `-j 32`):

- **Sizes:** the largest crates are hermit-detcore (1.8 MiB compressed), reverie-kvm (1.1 MiB) and hermit-cli (1.1 MiB). All are far under the 10 MB limit.
- **GPL check:** none of the 18 `.crate` files contains GPL text, a COPYING file, or e9patch/SaBRe/DynamoRIO vendor files. hermit-cli carries only its own first-party `e9patch.rs` and `sabre_*.rs` dispatch code.
- **Scratch-only shortcut:** I added `path =` hints for the cross-repository Reverie dependencies so the combined workspace could resolve them. The real release branch has no such paths. Its published manifests are identical to the normalized ones I inspected: `version = "0.4.0"`, no git, no path.

## 5. Risks

- **Autocargo regeneration** (internal) overwrites manifests on every ShipIt export: versions, `repository`, descriptions, dependency forms.
  - It cannot touch rrnewton main unless someone merges facebookexperimental main back. It cannot touch an off-main `release/0.4`.
  - Mitigation: bump the version in the fbsource autocargo project configs together with the import. Never base `release/0.4` on a ShipIt export.
- **The fbsource import rewrites trees:**
  - license headers (428 Hermit and 221 Reverie files);
  - the `@fb-only`/`@oss-only` marker swap in `rust-toolchain.toml`;
  - BUCK files;
  - stripped GPL trees.
  - Mitigation: upstream the header insertions to rrnewton main before the RC, so the import is byte-preserving.
- **License and copyright:**
  - Hermit's LICENSE is BSD-3-Clause with "Copyright 2020-2022 (c) Meta Platforms, Inc. and affiliates".
  - Reverie's is BSD-2-Clause with an Indiana University copyright.
  - Neither file ships in any `.crate` today; fix this in the release commit.
  - liteinst2's copyright line is "liteinst2 contributors" in a rrnewton repository, not Meta. Its publication is independent of Meta OSS but should be confirmed.
- **GPL vendored code:**
  - reverie-e9patch declares GPL-3.0-only; reverie-sabre declares GPL-3.0-or-later and GPL-2.0-only; reverie-dbt declares LGPL-2.1-only and BSD-4-Clause.
  - Keep all three out of crates.io for 0.4 (`publish = false`). The minimum release contains none of their code (checked above).
  - The fbsource license check is RED on exactly these trees, and they will never reach facebookexperimental main through ShipIt.
- **CLA and ownership:**
  - facebookexperimental needs a "Meta CLA Check" on every non-exempt branch. The open import pull requests carry the "CLA Signed" label.
  - `release/**` is exempt, but the push itself needs a write-capable owner account.
  - Publishing Meta-owned code to crates.io needs Meta OSS approval of the owning account.
- **Toolchain:**
  - reverie-ptrace needs nightly (`#![feature(internal_output_capture)]`), and so does every downstream crate.
  - liteinst2's `deny(warnings)` breaks its own verification on Hermit's pinned nightly.
  - Workspace-level profiles, such as the `iced-x86 overflow-checks = false` stanza for https://github.com/rrnewton/hermit/issues/3462, do not travel with a published crate. Release-profile `cargo install` builds wrap arithmetic anyway, so that one is harmless.
