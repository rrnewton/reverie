Pipe FIONREAD now reports the unread byte count for actual host-backed pipes and FIFOs while retaining unsupported ENOTTY for other descriptor classes. This component is based on preserved composition 89a9f0217b2f3ab6106aac12ea2a650eee7972d6 (refs/rescue/astra-reverie-vector-signal-composition-89a9f021). It changes only executor dispatch and a narrow helper in production; it adds no memory API, scheduler rule, signal operation or Hermit capability setting.

The Linux syscall uses an unsigned-int descriptor and command. The helper recognizes the low 32 command bits, resolves the descriptor before the output pointer, requires raw host S_IFIFO, queries one supervisor-local int, and stores exactly four bytes through the existing permission-aware GuestMemory::put_user_i32. Host ioctl errors remain errors. The count is observed under the host kernel's pipe mutex and consumes no bytes. Existing CLONE_FILES synchronization protects the guest descriptor lookup. There is no cached count or new polling loop. Linux v6.17 fs/pipe.c:617–635 supplies the operation for anonymous pipes and named FIFOs; fs/ioctl.c:584–604 supplies argument width and descriptor ordering. Sources: https://github.com/torvalds/linux/blob/v6.17/fs/pipe.c and https://github.com/torvalds/linux/blob/v6.17/fs/ioctl.c.

Captured output is deliberately excluded. CapturedOutput stores guest bytes in vectors; querying a host stdout/stderr backing pipe could reveal unrelated supervisor bytes. Direct output aliases are refused, and raw (st_dev, st_ino) equality also refuses transferred aliases whose OutputAlias metadata was cleared. Guest close, dup, fork and exec do not physically replace host stdio, so the host reference retains that identity after the last sending guest alias closes. An unrelated real pipe placed at virtual fd 1 or 2 remains supported. If necessary capture backing identity cannot be established, the operation refuses. Concurrent external host replacement/closure of inherited stdout/stderr during execution is outside this model. Supporting that different lifetime would first require retained capture backing ownership; neither this change nor its tests claims it.

The withdrawal in 345681e44bf9d07f8c9f52138ce2682633adfffe remains in effect for general FIONREAD. The original change from https://github.com/rrnewton/reverie/pull/533 lost synthetic proc semantics through SCM_RIGHTS, including queued receive after the last sender closed. Its original strict 16384-byte regressions remain unchanged at d3aede09d301b71d7cc36c5846c3ad1013b62033. Synthetic proc contents remain host memfds even after transfer, so the S_IFIFO guard excludes them independently of the lost side-table marker. This component neither repairs general transported descriptor identity nor presents that old failure as fixed.

Measured native/KVM differences are explicit. A seven-byte regular file and ordinary memfd at position zero return 7 natively but remain ENOTTY under KVM. A synthetic /proc/self/status descriptor positioned at 3 returns -3 natively, including duplicated, transferred and last-sender-closed cases; KVM refuses each. A socket with four buffered bytes returns 4 natively and remains ENOTTY under KVM. A controlled host capture backing pipe contains 11 supervisor bytes natively, while capture aliases are refused. Eventfd, signalfd, timerfd, pidfd and a proc directory return the measured native ENOTTY and retain KVM refusal. These excluded classes are unsupported-operation evidence, not general native parity. A helper-level missing-backing control also proves conservative refusal for an unrelated pipe when capture identity is unavailable; it is not an end-to-end host-fd-replacement test.
