=== 1. HOW executed_tests IS DERIVED, AND AT WHAT SCOPE ===
Source: ci-hub/validate/aggregate.py:324 -> nonzero_result.executed_test_count(banner_text), where banner_text = every test-runner banner across the WHOLE run (all gates joined). It SUMS every "running N tests" banner in the run.
=> executed_tests is a PER-RUN SUM over all gates, NOT per-gate. Its SCOPE is unambiguous (always whole-run).
=> But its VALUE is a running-total-until-halt: it counts only the tests that ran BEFORE the DAG stopped. safe-ci-dag-runner eager-exits on the first node failure (aborts queued nodes, lets in-flight finish), so accumulation stops partway. A run where all nodes complete sums ~765; a run halted after a mid-DAG failure sums 350-520. Same commit 17b59fc6 yields 359 (halted at command_strict_verify) and 760 (halted at liteinst_strict) across two runs -- same field, same scope, different STOP POINT. The band is the eager-exit stop-point, not truncation.
CLASSIFIER IMPLICATION: a band count does NOT mean "verdict untrustworthy". It correlates with "a node failed and the DAG short-circuited" -- a proxy. The real signal is already in the log: "safe-ci-dag-runner: FAIL - N passed, 1 failed, K aborted" plus a named "X FAIL <node> (exit C)". Keying needs-rerun on executed_tests alone re-introduces the proxy defect the classifier exists to fix.
