## What the extended oracle observes, and why

The old oracle could not detect a checker that evaluated nothing. A guarded checker deliberately prints a column-zero `NO-RESULT-CASE:` line and exits 0 when it cannot reach the authority. A checker that runs all its cases successfully also exits 0. Worse, a checker that skips before fetching makes fewer authority calls. Exit status plus a low fetch count therefore passed most easily when the checker did the least work.

The final oracle in `scripts/test-authority-obtained-once.sh` closes that blind spot for every current guarded checker by observing two results together for every planted authority response:

1. The real checker's exit status.
2. The exact count of column-zero `NO-RESULT-CASE:` lines in that checker's output.

For each of the five guarded checkers, it requires:

| Planted authority response | Checker exit | Marker count | Meaning |
| --- | ---: | ---: | --- |
| HTTP 504 | 0 | 1 | Authority could not be reached; checker explicitly evaluated nothing. |
| `dial tcp ... socket: operation not permitted` | 0 | 1 | Real Go-client connection failure; no result. |
| `error connecting to api.github.com; check your internet connection` | 0 | 1 | Real `gh` connection failure; no result. |
| `dial tcp: lookup ... no such host` | 0 | 1 | Real DNS failure; no result. |
| HTTP 404 | 1 | 0 | Authority was reached and refused the request; stays red. |
| HTTP 403 | 1 | 0 | Authority was reached and refused the request; stays red. |
| Unknown command failure | 1 | 0 | Unknown text defaults to a refusal; it cannot silently skip checks. |

This specifically catches the old failure mode. A checker that skips a 404, 403, or unknown response would emit a marker or return 0 and fail the expected pair. A checker that runs nothing under a reachable, correct authority is caught by the earlier obtainable-authority arm, which requires exit 0 and no marker. A blanket failure cannot pass because the correct-authority arm requires success; a blanket skip cannot pass because refusal arms require failure with no marker.

The first-success/later-504 race arm also now requires exactly one `gh` call per checker. Zero calls fails because it bypasses the planted ordering. More than one fails because a later fetch reopens the race. The obtainable-authority arm additionally rejects any marker, so one fetch followed by skipping the actual cases cannot pass.

The same distinction is checked at the real `check.check_outcome_consumers` DAG wrapper:

- 504 and the three real connection/DNS forms: exit 75 with exactly two markers.
- 404, 403, unknown text, and wrong pinned bytes: nonzero with zero markers.
- Correct pinned authorities: exit 0 with zero markers.

The two markers on the outage arm come from the two guarded checks the wrapper runs. Exit 75 is `no_result`, not pass. The correct-authority arm prevents a wrapper that simply fails everything from satisfying only negative cases.

The oracle also plants a `tee` that forwards output but exits 1 without writing the capture file. Both `ci/check-outcome-consumers-node.sh` and `ci/lint-checks-node.sh` must return 1 even though their markers remain visible on stdout. This proves neither wrapper can classify an empty or partial capture as pass. These are exactly the two consumers of `ci/node-run-classification.sh`.

A separate wrong-bytes arm serves a modified pinned authority through `gh`. The real checker must fail and emit no marker. This protects the content pin from being reported as an outage.

## Fixture recipes

The tracked test contains the exact implementation. These recipes explain the properties that matter when rebuilding a smaller manual fixture.

### Controlled PATH

Create a temporary `bin` directory and symlink every entry from `/usr/bin`, `/bin`, `/usr/local/bin`, and `${HOME}/.cargo/bin` except `gh` and `with-proxy`. Put the temporary directory first and set `PATH` to it for the checker. Do not use an empty `PATH`: that hides `bash`, `python3`, `grep`, and `rust-script`, causing exit 127 before the authority path is exercised.

### Response fixture

Install a temporary `gh` script in that directory which writes the chosen `AUTHORITY_RESPONSE` to stderr and exits 1. Run a real guarded checker with `DEV_HERMIT_PARENT` pointing to a new empty directory. Capture combined output, preserve the checker status immediately, and count only lines beginning exactly `NO-RESULT-CASE:`. Use the response/status/marker table above.

### First-success/later-504 fixture

Materialize both real pinned authorities first:

```text
scripts/check_outcome_adapter.py --materialize-authority AUTHORITY_DIR
scripts/review_contract_adapter.py --materialize-authority AUTHORITY_DIR
```

The temporary `gh` uses a byte-counted state file. On its first call it appends one byte and prints the correct authority payload. On every later call it appends another byte, prints `gh: HTTP 504 Gateway Timeout` to stderr, and exits 1. Point the checker at an empty `DEV_HERMIT_PARENT`; do not pre-point it at `AUTHORITY_DIR`, because that bypasses the obtain path and makes the test vacuous. After the run, require the state file to contain exactly one byte and require no marker.

Do not initialize the counter with `mktemp` and then use `cat file || echo 0`: reading an empty file succeeds and produces an empty value. The tracked test avoids that trap by using the file's byte count.

### Correct and wrong authority fixtures

For the pass arm, set `DEV_HERMIT_PARENT` to the directory containing both materialized, digest-verified authorities and run the real node wrapper. Require exit 0 and zero markers.

For the integrity arm, copy the pinned authority payload, append one line, and have temporary `gh` print the modified file. Point `DEV_HERMIT_PARENT` to an empty directory. The checker must return nonzero and emit no marker.

### Failed capture fixture

Replace `tee` in the controlled `PATH` with a script that runs `cat` and then exits 1 without writing its file argument. Under the 504 response, `check-outcome-consumers-node.sh` must return 1 while two markers remain visible.

For `lint-checks-node.sh`, also provide:

- a `git` script whose `submodule status` response is a clean initialized `agent-utils` line;
- a `make` script whose `lint-checks` target prints one column-zero marker and exits 0.

The lint wrapper must return 1 while the one marker remains visible. Returning 0 means it ignored the failed capture and classified missing evidence as pass.
