## Register preservation follow-up — source inspection only

**L** = LiteInst2 `95ee5e6917fa33191eb41c3f1606ea8b03c1b78c`, the dependency
pinned by R. References here describe immutable source read with `git show`,
not a mutable worker branch. No tests or guests were run for this follow-up.
Earlier execution evidence remains separate in `paired-execution.json`;
host-hybrid results do not qualify the intended architecture.

- **Save and restore guest registers:** L `src/trampoline.rs:660` reserves the
  128-byte red-zone, saves RFLAGS and all 15 non-RSP general registers, then
  saves extended state. It clears DF before calling the callback. Restoration
  at `:690` restores extended state, pops registers and flags, and restores the
  original RSP by frame arithmetic. Callbacks must follow the SysV ABI, preserve
  actual callee-saved registers (including R12 holding the frame address), and
  must not unwind. Adequate writable guest-stack space is required.
- **Important RSP limitation:** L `src/trampoline.rs:126` explicitly makes
  `HookContext.stack_pointer` and `instruction_pointer` metadata. Restoration
  at `:694` does not load RSP from `stack_pointer`; continuation is the fixed
  generated jump at `:603`. R `reverie-liteinst/src/tool_host.rs:855` writes
  `context.stack_pointer` in `set_regs`, but that write does not switch the
  actual restored stack. A fallback or timer implementation must not assume
  these fields implement arbitrary register restoration.
- **XSAVE coverage:** L `src/trampoline.rs:47` selects FXSAVE64/FXRSTOR64 or
  XSAVE64/XRSTOR64 with `XCR0 & 0x2e7`: x87, SSE/MXCSR/XMM, YMM upper halves,
  AVX-512 opmask/ZMM state, and PKRU. At `:75`, storage is aligned and XSAVE
  reserved header bytes are cleared. The selected vector state survives
  callback/libc AVX clobbering, provided execution remains compatible with the
  CPU/XCR0 settings sampled when code was generated. AMX, MPX and other omitted
  components are not preserved. Callbacks must not alter excluded state.
  The code does not establish a separate clean FP environment for callbacks.
- **TLS and flags limits:** no FS/GS-base save/restore or TLS-memory snapshot
  appears in these instructions. Callbacks must preserve bases; TLS changes
  such as `errno` are not automatically undone. PUSHFQ/POPFQ are not a literal
  copy of every asynchronous flag: the pushed RF/VM bits are cleared and
  restoration has architectural privilege restrictions.
- **Syscall versus timer:** R `reverie-preload/src/trap.rs:218` redirects saved
  RIP or writes RAX, relying on signal return for other state. R
  `reverie-liteinst/src/runtime.rs:2620` sets RAX to the syscall result, RCX to
  site+2, and R11 to saved flags. Those syscall clobbers must not be applied to
  an arbitrary-PC timer interruption. Reusing the save/restore code still
  requires explicit continuation, stack, signal-frame ownership and nesting
  handling; `HookContext` alone is insufficient.

Existing L tests cover flags/red-zone (`src/trampoline.rs:2406`), XMM clobbering
(`:2457`), and AVX2-gated YMM upper-lane clobbering (`:2475`). Inspection found
no exhaustive preservation test for GPRs, x87/MXCSR, ZMM/PKRU, TLS, stack
switching or arbitrary-PC timers. These are coverage limits, not tested guest
failures. No assertion, tolerance, comparator, skip or acceptance denominator
was changed. Third-slot approval remains pending; no provisioning or product
edits were performed.
