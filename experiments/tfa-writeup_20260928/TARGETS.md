# TFA experiment: all 30 targets

Written 2026-09-28. Companion to [README.md](README.md). The same data, with full
Buck labels, is in [targets.csv](targets.csv) (one header row, 30 data rows). Nothing was
re-run to write this; every cell below is read from records or from read-only queries.

## How to read this table

- **Target**: one Buck test target plus the one test case that was selected for it. The
  30 rows are the fixed registry, 3 targets from each of 10 service families, in registry
  order.
- **PFS**: TestInfra's Probabilistic Flakiness Score on 2026-09-17. It was used only to
  rank candidates.
- **Native fail**: failures / executed results in the trailing week before 2026-09-17
  (CI runs, not Hermit runs). A planning prior only.
- **Likely cause**: our bucket for why the test is flaky in CI. It is an **inference** from
  CI failure text (queried 2026-09-28) and test source, not a proven root cause.
- **Pilot** is the kernel-6.13 run of 2026-09-20 (older Hermit, 1 seed per target).
  **Main** is the kernel-7.1 campaign of 2026-09-21.
- **Trial**: one seed tried once under strict verify, which runs the test twice with that
  seed and requires both runs to match exactly. **Configuration**: the fixed binary, Hermit
  flags and host within which only the seed changes.
- **Success** (the records call it WORKING): the campaign's strict form of the owner's rule
  ("Hermit produced a passing seed and a failing seed"). In one configuration, one seed
  passes twice and another seed fails twice with the failure declared in advance. The
  looser owner wording gives the same 3 successes, because no other attempted target produced
  both a passing and a failing seed, but it would have taken less effort.
  Under it, AsyncSSL qualified in its 3rd configuration instead of its 10th
  (`sched-continuation`: seeds 4, 11, 12 and 14 passed, and 11 seeds failed at
  `AsyncSSLSocketTest.cpp:3592` with both runs matching, `BitwiseInfoV1=matched`), and HTTPCoro
  across its first two configurations (16 line-1685 aborts, then 8 passes at clock 0.125)
  (K71 records of those configurations).
- **Easy-fix judgement**: EASY means an existing Hermit flag or setting, or a small local
  code change whose mechanism is proven from logs and source. None of these fixes was
  tried, so every judgement is untested. "Pass the stop" means get past the point where the
  run stopped; it does not mean the target would then produce a failing seed.
- **Seed names**: "sched" is Hermit's `--sched-seed` (the thread-scheduling seed).
