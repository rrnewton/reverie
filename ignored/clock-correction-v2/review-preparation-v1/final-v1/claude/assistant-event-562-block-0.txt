# 1. Findings

**No blocking defect.** Five non-blocking findings, in descending severity.

### A1 — LOW. A *returning* tail injection with no pending original is unexercised, and its `set_ret` behaviour differs from the adjacent arm

`reverie-ptrace/src/task.rs:5581-5590` (new `None => self.untraced_syscall(...)` arm of `inner_tail_inject`).

The three neighbouring arms each finish the guest's return value explicitly: the injected-frame arm calls `write_injected_syscall_result` (`task.rs:5555-5559`), the already-skipped arm calls `set_ret` (`task.rs:5562-5570`), and the LiteInst mapping-tail arm calls `set_ret` (`task.rs:5573-5580`). The new `None` arm does neither. It is reached only from a callback that owns no seccomp entry — `handle_post_exec`, `handle_signal_event`, `handle_timer_event`, `handle_rdtsc_event`, `handle_cpuid_event` — and the one selected control that reaches it, `Mode::PostExecTail`, tail-injects `Exit(27)`, which never returns: `untraced_syscall` → `status_to_result` → `Wait::Exited` → `self.exit(...)` → `abort` (`task.rs:5641`, `5662`), so the run loop short-circuits before RAX matters.

**Impact.** Two sub-behaviours are unverified rather than wrong. (a) After `untraced_syscall`, `restore_context(&stopped, Some(oldregs), None, false)` (`task.rs:5613-5617`) restores RIP, args, `orig_rax` and the syscall clobbers but *not* `ret`, so RAX carries the injected call's result — defensible as tail-inject semantics, but nobody asserted it. (b) A *returning* tail-inject from those callbacks would hang: `do_tail_inject` sets `cancel_handler` then awaits `future::pending()` (`task.rs:5628-5634`), and none of those five callbacks is wrapped in `cancellable()` (unlike `handle_seccomp` at `task.rs:4112-4118` and `handle_injected_syscall` at `task.rs:2254-2260`). **This is not a regression** — under the base the same call took `private_inject` and additionally executed-and-rewound a guest instruction before hanging — but the asymmetry is new.

**Required correction.** None for landing. Either add `set_ret` for symmetry or a one-line comment recording why it is deliberately absent; separately, consider refusing a returning `tail_inject` outside `handle_syscall_event` rather than hanging.

### A2 — LOW. Unconditional post-exec clearing of two fields is correct but has no direct control

`task.rs:2932-2933`: `pending_syscall_already_skipped = false` and `injected_syscall_frame = None` move out of the `liteinst_runtime.is_some()` branch and become unconditional. After `PTRACE_EVENT_EXEC` the address space is gone, so a retained frame address is meaningless and a "this entry was already converted" flag refers to a consumed entry — the change is strictly safer. But in every selected scenario the execve is tail-injected, so all three fields are already at their cleared values; no control distinguishes the old and new code here. **Required correction:** none.

### A3 — LOW. `TimerImpl::cancel`'s new guard is redundant

`timer.rs:907-913` returns `Ok(())` instead of `self.timer.disable()` while `initial_command != Ordinary`. The sampling counter is created `disabled=1` (`perf.rs:231`) and `prepare_notification` is its only enabler (`timer.rs:848-861`), which is unreachable in that state — so the disable would already be a no-op. `Timer::cancel` is `#[allow(dead_code)]` with no production caller. Defensive, not wrong. **Required correction:** none.

### A4 — LOW (evidence tooling, carried forward unchanged)

`qualification-v2/phase.py:112-114` writes `compiler-diagnostics.json` *after* `require([...] == [True], 'missing successful Cargo completion')`, so a compile that never emits `build-finished` produces no diagnostics file — exactly the qualification-v1 situation, whose compiler messages had to be extracted by a separate packet. `HELPER-CONTINUITY.json` shows all eleven runtime/orchestration helpers byte-identical to the predecessor, so this is inherited, not introduced, and it did not bite in Q2. **Required correction:** none for this change.

### A5 — INFORMATIONAL. setuid exec destroys the counter

`fs/exec.c:1264-1265` (bound): after `commit_creds`, `if (get_dumpable(me->mm) != SUID_DUMP_USER) perf_event_exit_task(me);`. For a setuid initial command the clock event is destroyed at the very exec that would enable it, and the next `read_clock()` would panic through `ctr_value_fast_loop`'s descheduled check (`perf.rs:645-651`). Pre-existing in kind — the event existed and was enabled before this change too — and a ptraced setuid exec drops privileges anyway. Unmeasured in both directions.

# 3. Determinism

**Sound.** Stated against the grounded scheduler rather than the author's summary.

**Allowed inputs.** Exactly two. (1) `TracedTaskOptions::command_bootstrap`, set `true` at precisely one site — `TracerBuilder::spawn`'s `postspawn` call (`tracer.rs:2530`) — and `false` at `spawn_fn_with_config` (`tracer.rs:2497`), `cloned` (`task.rs:1234`) and `forked` (`task.rs:1292`). That is a static property of which entry point was used, not a runtime observation. (2) The guest's own successful `execve`.

**When time becomes eligible.** At `perf_event_exec()`, `fs/exec.c:1217`, inside `begin_new_exec` — a fixed point in the guest's own successful exec, identical on every run. `event_enable_on_exec` clears `attr.enable_on_exec` unconditionally at `core.c:4673` *before* the state test, so the transition is once-only by kernel guarantee and later execs keep counting continuously. Not host-timed.

**When notifications become eligible.** At `Timer::finish_initial_exec()` (`task.rs:3054-3056`), immediately before `handle_post_exec` and after `tracee_preinit`. This is a fixed point in the ptracer's single-threaded program order for that task, reached only via `handle_exec_event`, which is entered only on `PTRACE_EVENT_EXEC`. Both the ordinary route (`handle_stop_event` → `Event::Exec`) and the injected route (`status_to_result` → `Event::Exec`) go through it, and both are exercised (`injected_exec in [false, true]` across all five clock tests).

**Affected task states.** Only the Command root's own `TracedTask`, and only in the window between construction and its first successful exec. `InitialCommand` advances monotonically `WaitingForExec → InitializingExec → Ordinary`; `retire_initial_event` takes the `Option`, so each held record retires exactly once and no retired record can be revived (unit-asserted: `begin_initial_exec` twice, then a *new* request during `InitializingExec`, then `finish_initial_exec`).

**Run-queue / blocked-pool membership.** **None.** `reverie-ptrace::Timer` is not the Detcore scheduler; it owns no queue, no pool and no turn. Detcore consumes this layer only as `Guest::read_clock` (a monotone counter read, turned into a *delta* by `update_logical_time_rcbs`) and `Guest::set_timer*` (a *relative* request that `request_event` converts to an absolute target in the same counter). No `detcore/**` file is in the diff.

**Turn / clock behaviour.** The only quantity that changes is the first delta the consumer observes from the Command root: from (launcher branches + two tracer-injected replays) to 0. Every later delta is a difference of two later reads and is untouched. `committed_clock_value <= clock_value` cannot break: both start at 0, the counter only counts up, and `enable_on_exec` *starts* counting — it never resets. Nothing is rounded, frozen, coarsened, reset or compensated; there is no fixed subtraction anywhere in the diff.

**Host-arrival leakage — strictly reduced.** Before this change, a short start-time request on the Command path called `prepare_notification`, which either enabled the sampling counter or set `send_artificial_signal`, and `finalize_requests` then issued a real `tgkill`. A host-timed PMU overflow or signal delivery could therefore land at an arbitrary launcher instruction and produce a `handle_timer_event` whose clock value depended on host timing. After the change, `request_event` early-returns before `prepare_notification` (`timer.rs:830-836`), `finalize_requests` early-returns (`timer.rs:942-945`), and `generated_signal` returns `false` outright (`timer.rs:925-926`) while the hold is in force. The `fail_next_notification` seam proves the physical path is untaken: an injected `EIO` survives three requests and both transitions and only fires on the first `Ordinary` request. That is a direct witness, not an inference.

**Callback-order leakage.** `begin_initial_exec` and `finish_initial_exec` are called from the single ptracer thread in fixed program order inside `handle_exec_event`. There is no concurrency and no arrival-order input.

**Backend scope.** ptrace only. KVM and DBT clocks are untouched. No new scheduler or signal activation is present, and none is approved here.

# 4. Linux and POSIX semantics

**Faithful.** No guest-visible Linux interface changes. `Guest::read_clock` is a Reverie-internal counter with no POSIX counterpart.

**Exec failure ordering — now established from bound source, resolving my old F5.** `binfmt_elf.c:907` opens the `PT_INTERP` target; `909-911` preserve `PTR_ERR` and `goto out_free_ph`. `begin_new_exec(bprm)` is at **line 1010** — after that cleanup. So a missing interpreter fails before `begin_new_exec`, therefore before `perf_event_exec()` (`fs/exec.c:1217`) and before `ptrace_event(PTRACE_EVENT_EXEC)` (`fs/exec.c:1719`, reached only when `search_binary_handler` returns ≥ 0). The runtime control witnesses the same thing on the real host: test-06 asserts `inject(execve) == Err(ENOENT)`, then `is_command_bootstrap()` still true (so `handle_exec_event` never ran ⇒ no `PTRACE_EVENT_EXEC`), `!*thread_state()` (no `handle_post_exec`), `read_clock() == 0`, and empty `post`/`timer`/`boundary`. Exit 27.

**The injection repair restores, rather than changes, Linux semantics.** `skip_seccomp_syscall` documents its precondition explicitly — "*Ptrace tracee is in a (seccomp) stopped state. The tracee was stopped with the RIP pointing just after a syscall instruction (+2)*" (`task.rs:5147-5150`). The base violated it whenever `pending_syscall` was `None`, executing one guest instruction and rewinding RIP; register restoration cannot undo a retired branch or a memory side effect. The head routes that case to `untraced_syscall`, which executes on the private page and leaves the guest untouched. The `test-38` trace shows the repaired shape directly on an *unchanged* test: `[tool] beginning inject of syscall: mprotect` is immediately followed by `[scheduler/tool] untraced syscall: mprotect`, with no intervening skip.

**The distinctions contract 3 asks for are each separately controlled:**

| case | code path | control |
|---|---|---|
| present, same original, ordinary | `Some(o) if o == (nr,args)` → `syscall_stopped` to sysexit | `SameThenPrivate` first inject |
| present, different original, ordinary | `Some(_)` → `private_inject` | `Replace` |
| no pending original, ordinary | `None` → `untraced_syscall` | `PostExec` (2× Getpid + EBADF Close), `SameThenPrivate` tail |
| present, same original, fast tail | `Ok(Ok(0))`, callback cancelled, kernel runs it | `TailSame` (stdout `"O"`) |
| present, different original, tail | `private_inject` | `TailOther` (stdout `"R"`) |
| no pending, nonreturning tail | `untraced_syscall` | `PostExecTail` (exit 27, shared-mapping word still 0 **after process death**) |
| emulated return, then later instruction callback | epilogue `take()`s before the skip | `Emulate` / `EmulateErrno` |
| already-converted stop, injected frame | unchanged branches | `pre_ready_*` neighbours |
| legacy vsyscall | unchanged special case | test-38 (real `time` interception) |

The legacy-vsyscall handling is preserved exactly: the new epilogue computes `emulate_legacy_vsyscall = is_legacy_vsyscall && pending_syscall.is_some()` from the *taken* value and adds `&& !emulate_legacy_vsyscall` to the skip condition, which is truth-table-identical to the old `if/else if`. Errno and partial results are preserved (`EBADF` and `EPERM` asserted as exact values; `status_to_result`'s `ERESTARTSYS`-on-signal path and `restore_context`'s `rcx`/`r11` restoration are untouched).

**Ownership and cancellation, not just names.** `pending_syscall` now has a stated ownership contract in its doc comment (`task.rs:986-990`), and every consumer takes it exactly once: `handle_seccomp`'s epilogue, `inner_inject`, `inner_tail_inject`, and the unconditional post-exec clear. The stale-`Some` defect the V2 observation predicted ("*a patch that only tests Some versus None without fixing this epilogue would be incomplete*") is the one the `Emulate` control targets: the Tool returns `Ok(123)` without injecting, the guest stores it, then executes `RDTSC`; under the base `pending_syscall` would still hold `(getpid, args)` and the Getppid injection from `handle_rdtsc_event` would take `private_inject` and single-step the guest at an instruction trap. The test asserts RIP and the memory word unchanged across that injection.

**Divergence retained:** the `#[cfg(all(test, target_arch = "x86_64"))]` launcher seam in `pre_exec` is test-only; in a non-test build the field does not exist and the closure is byte-for-byte the prior `init_tracee(intercept_rdtsc)` behaviour plus an `Ok(())`.
