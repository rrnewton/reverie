The signalfd site is necessary, not unrelated cleanup. `execute_basic_syscall_with_output` calls it before `write` (355–359). Changing only `write` would let a high-bit signalfd bypass the current checked-conversion preflight and reach its owned eventfd carrier; an eight-byte write can then have a real carrier effect. The proposed existing signalfd regression writes eight bytes through both high-bit original and duplicate descriptors, requires EINVAL, then retains the existing no-readability/EAGAIN/poll and real eventfd controls. The demonstrated old fixture has no signalfd; this additional risk is a source-derived consequence of an incomplete patch, not a claimed measured failure.
