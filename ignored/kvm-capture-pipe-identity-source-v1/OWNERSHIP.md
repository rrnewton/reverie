The only retained objects added by this candidate are two private anonymous-pipe read endpoints. They exist to keep each pipe inode alive. Output bytes still go exclusively to the existing buffers. No guest table, weak signal binding, Tool object, process-action payload or descriptor-entry marker receives these endpoints.

Construction and failures

* `CapturedOutput::try_new` calls `CapturedPipeIdentities::try_new` before allocating/publishing its shared buffers. The latter prepares stdout, then stderr. On second-stream failure, the first local CapturePipe drops before returning the error; no Arc/partial capture was published.
* `CapturePipe::try_new` immediately owns both successful pipe2 returns, then closes the unused write end. If the remaining end is below 3, it duplicates with F_DUPFD_CLOEXEC(min=3), closes the original, and only then performs fstat. Thus success and every error leave no temporary endpoint in 0–2. There is no close retry on a possibly reused number. Each error is materialized before RAII drops can change errno.
* Standard descriptors open: first pipe peaks at two extra descriptors and leaves one; second peaks at three and leaves two. Closed standard descriptors: unused closes before the relocation duplicate, so its peak is also two for the first stream / three including the first keeper for the second. No duplication occurs during fork/thread/exec.
* The real relocation failure control fills all high slots, closes 0/1, obtains a successful pipe2 in 0/1, closes its unused endpoint, and then gets EMFILE from F_DUPFD_CLOEXEC(min=3). The keeper closes on error, leaving both standard numbers closed. Test-only counters assert that this actual branch occurred. It is not silently classified as an earlier pipe2 failure.

Root entry and stdin

* The private `KvmBackend::prepare_captured_output` checks image presence and either returns None without host descriptor work or performs fallible capture preparation. Both direct capture and Tool completion call it before `static_elf.take`. Tool completion also calls it before GlobalState, failure context, Tool, subscription and thread-state initialization. Its existing incompatible thread-observation configuration check remains first.
* The Tool root's capture_owner is declared before loaded state and executor; later Tool state and child/executor cleanup therefore run first on ordinary return, error or Rust unwind. The direct root has the same ordering. A live worker/executor clone independently keeps the identities alive; the root local is an extra lifetime owner, not the sole safeguard.
* Explicit loaded stdin is unchanged. The existing capture-default `/dev/null` open happens afterward only if stdin was absent. Capture setup cannot occupy an implicit standard slot or create a logical stdin entry. `FileTableState` initial reservation, local/authoritative entry markers and install paths are unchanged. If `/dev/null` itself allocates an originally closed fd 0, it is an intentionally owned stdin File under the existing behavior, not a leaked capture endpoint. Existing stdin epoll/replacement/fork/exec controls remain selected.

Sharing and retirement

* Fork/thread constructors clone CapturedOutput's two Arcs after their existing fallible snapshot preparation. The parent's root/executor retains ownership throughout. An error before this clone cannot retire the capture; an error/drop afterward releases only the new clone.
* `replace_after_exec` replaces LoadedStaticElf and synchronizes the table while retaining the executor output. No capture endpoint is closed, fstat'd or duplicated in the locked replacement. CLOEXEC removes guest descriptor aliases as before, while the run capture object remains available to surviving output aliases.
* Guest close, dup, open, install rollback and descriptor retirement act only on the existing guest/host file-table objects. A keeper is never in those containers, so those locked paths cannot be its final owner. Existing marker and destructor controls remain unchanged.
* `take_output` still drains the two buffers and keeps both Arcs. Captured stdout/stderr aliases select the same reserved identity by OutputAlias. A descriptor replaced with an ordinary object follows its native identity; a retained dup or private-fork alias keeps the capture identity. Internal GuestFileIdentity bookkeeping remains separate.
* `ElfExecutor::drop` holds transaction/lifecycle guards in its Drop body; those locals release before Rust drops fields, including output. Root locals normally keep the capture alive beyond even that field destruction. No production keeper Drop hook holds a table/transaction guard or reenters Tool code. The test-only pre-field-drop hook verifies that both actual guards can be acquired while both keepers are still alive; the isolated child then verifies EBADF after final ownership release. The normal/unwind control uses real parent/worker executor destruction, not a manually drained surrogate queue.
* Ordinary async runtime failure, external cancellation and child cleanup semantics otherwise remain the existing runtime's. This change does not claim to improve child joining or arbitrary cancellation guarantees. Surviving output clones keep their own endpoints alive; their executor Drop body releases its local guards before fields. The endpoints have no guest writer, no buffered pipe data, no exported OFD and no SO_LINGER/general-descriptor behavior. Do not extrapolate this reasoning to arbitrary File retirement or to the unresolved TCP-close design.

Metadata routes

Direct fstat and followed stat/newfstatat/statx receive a Copy metadata view while CapturedOutput remains owned by the executor/root. Captured readlink renders that same stream inode. AT_EMPTY_PATH, numeric guest-pid paths and existing `/dev/fd`, `/proc/self/fd`, `/proc/thread-self/fd` routes remain under their prior validation/order. No-follow symlink functions do not take capture metadata and are byte-identical. Ordinary descriptor helpers retain their original native calls and timestamp sanitation. Existing invalid statx flags/mask and guest-memory error behavior remains selected.

The keeper's native inode can vary across runs, as ordinary pipe inodes already do at the raw backend boundary. It cannot be recycled into another live ordinary pipe while its endpoint remains owned. This is the inode reservation missing from the discarded device-only candidate. Hermit's existing deterministic remapping is unchanged; no new raw-ID normalization or whole-parity claim is made.
