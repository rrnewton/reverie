The new file adds four real public run_with_tool cases, each using the installed real-mode private hypercall followed by HLT: the response is pending in an actual GlobalTool RPC after the original syscall effect, or the response has been written and the next real CountedVcpu entry is refused. Each position has a fresh reopen neighbor and a global-failure neighbor. Two additional public Host run cases close after its handler wrote the response, with reopen or typed gate poison. The pending-RPC cases are direct Tool cases; no ELF outstanding-RPC/frame-result coverage is claimed.

The syscall is a guest write through the direct public API's actual executor. It reads the exact guest buffer through GuestMemory, performs one actual libc write into an isolated memfd, and returns that syscall's byte count. The controller requires one dispatch, exact file length, exact bytes and EOF. A repeated write would append a second copy rather than be hidden by an idempotent effect. The injected request must equal the request emitted by the installed guest. The executor verifies the original Mapping's host address and gate identity. Observations retain only that address and an EntryGate Arc; they do not retain GuestMemory or substitute a second Mapping.

The only clock.rs additions are cfg(test): a read-only HypercallProbe/HypercallSnapshot and its construction method. The probe obtains the real KVM_RUN mapping address before the run, with no ioctl and no response modification. Its unsafe snapshot checks KVM_EXIT_HYPERCALL before reading the active union and records actual hypercall number, return-slot address and value. It does not retain a VcpuFd reference or own the mapping. Direct Tool reads occur on the driver thread between public future polls, in the same-thread before_run hook, or after its future returns while backend still owns the mapping. The Host controller never reads the mapping concurrently: its hook records a copied snapshot on the driver thread, and its stopped comparison is after the actual worker joins. No snapshot is read after HLT or backend destruction. This intentional read-only mapping observation is not an ioctl-capable saved fd escape.

At pending RPC, close.finish must be immediately Ready while the borrowed backend, live callback, response slot and Mapping remain owned. The exact pending slot must differ from the chosen byte count so the fixture can distinguish a response write. The actual response and mapping identities remain unchanged through close. Normal resume reopens before releasing the RPC, preventing a test-created dependency on gated cleanup or copies while closed. At after-response close, RunProbe::before_run runs after the production handler return and response write, before entry preparation. The captured slot must contain the exact byte count. The weak hook capture cannot keep a Fence/RunProbe ownership cycle alive on an early assertion failure.

RunProbe counters arm only after the first real Hypercall exit, so startup setup and the original run do not contaminate the measured completion interval. With the fence closed, and after stop selection through backend Drop, the tests require zero shared-fd access, mask installs, tracked/untracked KVM_RUN, clock begin, interval creation and additional exit. Shared-fd access is an access witness, not a numeric upper bound on ioctl calls. The audited paths retain no ioctl-capable VcpuFd/raw-fd reference: direct callbacks use DirectSyscallExecutor only for clock reads and executor calls, and both public loops access the vCPU only through CountedVcpu. The new HypercallProbe performs memory reads only. No VmFd/Kvm call lies on these selected post-close paths. This supports zero KVM ioctls for these cases, not unrelated fork/thread/exec preparation.

A Tool failure must wake the actual registered future waker and reach a real on_exit_thread consuming RPC Pending with status 255 while the fence remains closed. That observation precedes reopen. The original ordinary RPC and callback must each drop once, before backend failure reporting; the before-response case must not return its callback value. Failure leaves the exact response slot unchanged; no completion-only entry is allowed. Failure reporting is checked for presence and ordering, not an invented exactly-one publication count. The thread and process consuming hooks are each once with exact status. Returned errors retain RunAborted; Host poison retains the exact shared cause Arc. The Host terminal result must arrive before reopen, then its physical worker is joined. No guest worker handle may remain.

Each positive case requires exactly one completion entry and exactly one actual Hlt after the one original Hypercall. Tool entries must have one tracked run, one clock begin and one created interval; Host entries must have one untracked run and no clock interval. The controller checks real post-HLT RAX equals the actual write's byte count. This final get_regs ioctl is explicitly outside the measured completion interval. It proves response consumption and continuation through actual guest HLT without another original syscall or effect; it does not exercise the separate prepared process-action parking continuation.

Every waiting observation and terminal result uses a five-second bound; failed waits are failures, not passes. Tool rescue reopens and releases owned ordinary/consuming channels before the public future is dropped. Host rescue reopens, poisons and joins its real owned worker. Root's enclosing process bounds remain necessary for unrecoverable host failures. No sleep is used as ordering evidence. The fixture intentionally does not demand that a synchronous memory operation or constructor complete while holding Closed.
