Background: an epoll descriptor stores a set of watched open file descriptions and returns their ready events. Reverie's KVM backend translates guest descriptors to supervisor descriptors. A supervisor descriptor is not sufficient evidence that polling it represents the guest object: captured output and virtual signalfd use carriers with different meanings.

# Recommendation and scope

Do not add syscall 441 by forwarding to the existing epoll_wait helper. A bounded zero-time epoll_pwait2 increment is feasible, but it first needs shared epoll-description provenance and a documented refusal boundary. The smallest candidate identified here accepts newly created, unescaped epolls whose registrations are proven native eventfd descriptions and whose relevant descriptor bindings remain intact. It can execute the unchanged seven-check eventfd fixture in captured sessions. It must never infer provenance from the event's user-supplied data payload, an inode, or a currently reused host descriptor number.

I withdraw my intermediate recommendation to port the preserved inotify PR as a smaller alternative. Its closure records substantive unfixed defects, and rename cookies introduce an additional determinism obligation. Neither proposal is a one-dispatch-arm implementation. Among the remaining source-audited cells, epoll remains the more bounded candidate if the descriptor-provenance work below is accepted as part of that unit. This is preparation, not implementation authorization or an approval.

# Linux's actual contract

The source is https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/fs/eventpoll.c . The relevant order is:

1. epoll_pwait2 at line 2521 copies the complete timespec first. An unreadable timespec gives EFAULT; invalid seconds/nanoseconds give EINVAL. A zero timespec is input only and is never written back. epfd and maxevents are signed C ints: only the low 32 register bits matter.
2. do_epoll_pwait at line 2489 calls set_user_sigmask before resolving epfd. A null mask ignores sigsetsize. A non-null mask requires the kernel's eight-byte size and then a readable eight-byte value. See https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/kernel/signal.c#L3272 . A new zero-time/unmasked implementation must not install a supervisor mask. Valid non-null masks and nonzero/null timeouts remain unsupported; this is not a claim of complete error precedence for all refused calls.
3. do_epoll_wait at line 2451 resolves epfd first (EBADF), then ep_check_params at line 2406 validates maxevents, numerical access_ok for the *full requested array*, and epoll file type, in that order. The maximum is INT_MAX / sizeof(epoll_event), or 178,956,970 packed 12-byte events on this ABI. access_ok is a numerical user-address check, not proof that the pages are mapped or writable. An inaccessible but numerically valid output address can therefore return zero if nothing is ready.
4. ep_poll at line 1936 tries already-ready events and returns for a zero timeout before its ordinary signal_pending check. Do not copy pselect's general pending-signal refusal into this syscall. Ordinary guest pending signals need not be consumed, reordered, or turned into fabricated EINTR. There is a narrower fatal-signal check in ep_send_events at line 1763. Linux's fatal_signal_pending predicate concerns pending SIGKILL, not every signal with a fatal default disposition; see https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/include/linux/sched/signal.h#L398 .
5. ep_send_events first copies the four-byte event mask and then the eight-byte data field, through epoll_put_uevent: https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/include/linux/eventpoll.h#L84 . Only after both stores succeed does it count the event and disable EPOLLONESHOT. If a later event faults, earlier complete events remain a positive return; the failed event stays queued. Exact scalar cross-page effects require native controls, rather than an inferred bulk-copy oracle.

Current producer signal paths defer ordinary guest signals but reject SIGKILL in deferred admission; a self kill exits directly and a sibling kill is refused. References are executor.rs lines 4550, 5683, 5703, 17971 and 18049 at the pinned Reverie commit. These reads do not establish a full scheduler theorem. The recommendation makes no scheduler, delivery or wakeup change; any extension that introduces a representable pending SIGKILL must revisit ep_send_events' fatal-signal boundary. I did not complete a new full-paper/full-scheduler DSR review in this bounded task and claim none.

# Why current state and helper reuse are insufficient

The current implementation is https://github.com/rrnewton/reverie/blob/2475b71bce56235663eb7d556c46aa4aa0550ee2/reverie-kvm/src/executor.rs .

- epoll_create1 at line 10588 creates only a generic File. epoll_ctl at line 10605 resolves raw host descriptors and rejects virtual signalfd ADD/MOD, but receives no capture flag and keeps no registration state. FileTableState at line 2035 has no shared epoll-description map.
- epoll_wait at line 10634 uses a temporary Vec, consumes kernel events, then writes guest bytes. A guest copyout fault can consequently lose a one-shot event. Its full-u64 maxevents conversion, MAX_HOST_IO cap, ignored requested timeout, and mask handling cannot become the new handler's contract by reuse.
- GuestFileIdentity and the inode cache are not open-file-description identity. Linux anon_inode_getfile deliberately shares an inode among independent anonymous instances: https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/fs/anon_inodes.c#L143 . Linux epoll keys are (struct file *, numeric fd), as ep_find/ep_cmp_ffd in eventpoll.c show. Neither (dev, ino) nor a descriptor-entry token is that pair.
- Descriptor-entry tokens correctly distinguish replaced table bindings, but duplicates get fresh entry tokens. FileTableState synchronization, local dup2/dup3, fork and exec need deliberate epoll metadata propagation. The kernel's numeric registration key can still differ after translating a guest replacement to a newly numbered host duplicate. Relevant paths are executor.rs lines 2814, 3494, 4410, 9824, 9909, 9974, 15945 and 16036, and elf.rs lines 864, 920, 938, 954 and 1080.
- Outgoing SCM_RIGHTS at executor.rs line 12486 rejects virtual signalfd and some other private objects, but not epoll or captured output. Incoming rights at line 12680 become generic Files and clear output-alias metadata. An imported carrier must therefore not acquire positive native provenance merely because it lacks a capture tag. An exported epoll can be mutated through an untracked alias; treating the original alias as still private would also be wrong.

# Smallest candidate design and its explicit limits

This is a concrete candidate for implementation review, not a proved patch.

1. Mint a dedicated Arc description at epoll_create1 and eventfd creation. Add per-descriptor references to LoadedStaticElf and FileTableState; propagate them through duplicate, table synchronization, fork, exec and close/replacement. Minted identity is separate from the inode cache and guest entry generations. Unknown imported Files receive no such identity.
2. Keep epoll's proof state shared by every known alias. Serialize every epoll_ctl affecting that description with the new wait's membership/provenance check and host wait. Record successful registrations, their origin table, guest descriptor entry generation, native eventfd description, and the kernel key used. Never inspect event.data as identity. An ordinary captured session remains eligible; a selected captured carrier, unknown object, nested epoll, or virtual signal source does not.
3. Avoid pretending the existing numeric-key lifecycle is repaired. The bounded admission can require that all recorded registration bindings still match the originating table and that the wait occurs through that table. A closed/replaced watched binding or a control operation through another table makes new waits unsupported. Known epoll dup aliases within the same table can share proof. Forked/exec/unshared tables must propagate identity and use an explicit admission decision, rather than accidentally treating a copied descriptor as a fresh safe epoll. This intentionally leaves native same-description replacement and cross-table epoll control outside the new subset; the historical failures stay failures, not passed tests.
4. Mark a description unqualified *before* any operation can add an unsafe registration or export that epoll through SCM_RIGHTS. A simple conservative implementation makes this marker permanent, even if that attempt later fails, and documents the reduced admitted history; it changes no send or old epoll return value. A less restrictive export-in-flight counter with rollback is possible, but adds a failure/unwind protocol and is not needed to establish the narrow fixture. Received epolls remain unknown. No inode-based registry may reunite them. Every outgoing-rights path must participate. Do not retain a hidden extra host File as a key without accounting for its effect on Linux last-close removal.
5. Refusal is ENOSYS before host polling or guest output mutation once the supported boundary fails. It is not a claim of Linux parity outside that boundary. Preserve the provable Linux preflight prefix, and explicitly distinguish a known non-epoll descriptor from an unknown imported type; otherwise EINVAL versus unsupported-type ENOSYS can be mislabeled. A valid mask remains refused without touching the supervisor mask.
6. For an admitted epoll, reuse the checked writable-alias mechanism from getdents64 (executor.rs line 15676; memory.rs line 1958), not epoll_wait's Vec/copyback. The alias maps writable guest backing at the same page offset and leaves inaccessible pages protected, letting the host kernel decide actual writes and one-shot consumption. Validate the original numerical guest range separately, since the alias address itself passes host access_ok. Capture the syscall result/errno before finish. Release any new epoll/table guards before alias finish can publish a terminal cleanup failure and notify a waker. No guest continuation or second copyout may follow a terminal alias failure.
7. Bound the alias without weakening maxevents: after validating the *original* count and numerical range, use host count max(1, min(requested, proven registration-count upper bound)). With no unknown/nested/escaped registration and membership serialized, at most that many distinct epitems can be returned in one zero-time scan. The kernel still performs the poll, including the empty case. This preserves output and ordering while avoiding a two-gigabyte alias solely because maxevents is huge. The proof depends on the registration upper bound remaining sound through all paths; if it is not established, this optimization must not be used.

Before coding, settle three implementation details explicitly: the lock order relative to the existing file-table transaction and alias guards; how every known alias/SCM export invalidates shared proof before native mutation; and the numerical guest-user address predicate used for the full original array. No listener graph, global quota, host blocking, host mask mutation, or scheduler change is required for this restricted candidate. General pipe/socket/nested-epoll, cross-table control and transferred-epoll support remain separate work, not silently accepted.

Planning estimate: this spans at least the descriptor model in elf.rs, its authoritative snapshots/lifecycle in executor.rs, the ctl/SCM paths and the new wait, plus strict unit/real-KVM tests. It is a medium implementation, not a one-function alias. Existing KVM test/build artifacts may be reusable if their bindings permit, but no new build size, duration or runtime pass was measured here.

# Required evidence before enabling the cell

The unchanged original fixture is https://github.com/rrnewton/hermit/blob/0f028322361f7357203ed4ef841dc63a770a2180/tests/c/epoll_pwait2_readiness.c . Its seven checks are successful ADD, eight-byte eventfd write, one ready event, exact data.fd, EPOLLIN present, successful DEL and a zero result after DEL. Its exact final line is `epoll_pwait2 ok=7`. The disabled row is https://github.com/rrnewton/hermit/blob/0f028322361f7357203ed4ef841dc63a770a2180/tests/e2e/manifests/c-programs.yaml#L11446 . Hermit's consumer already dispatches syscall 441 through its recorded/injected syscall path (detcore/src/lib.rs line 2349 and detcore/src/syscalls/io.rs line 1284); this fixture needs no new blocking scheduler semantics.

Keep all seven checks and original time bounds. Add native-paired controls for low-32-bit arguments, timeout/mask/fd/count/range order, readonly zero timeout, empty-invalid-output versus ready-invalid-output, partial second-field/second-event fault, retained readiness and one-shot re-poll after fault. Include ordinary pending-signal state unchanged with empty and ready epolls; do not infer fatal-SIGKILL parity from it. Cover dup aliases, descriptor close/reuse and same-OFD replacement, fork/shared-table synchronization, exec/CLOEXEC, SCM export/import and nested epolls, using either exact supported behavior or the documented refusal with unchanged memory/signal/capture state. # Why PR540 is not a smaller safe port

https://github.com/rrnewton/reverie/pull/540 was substantively closed, not superseded or fixed. Read-back of its closure is retained as PR540-CLOSURE.json/.md, SHA256 of body cc7de3aef8caaecea71030750b3f6b96d802107eece52829c37c3e165685e4af. The authoritative comment is https://github.com/rrnewton/reverie/pull/540#issuecomment-5631401018 . It retains measured wrong-namespace watches, missing OPEN/CLOSE events on synthetic proc files, no-follow identity errors, zero-read behavior, stale description binding and numeric epoll MOD/DEL failures. Green historical suites did not contain or clear those later counterexamples. The closure explicitly rejects blanket synthetic/no-follow refusal as a complete repair and requires coherent guest watch identity, event delivery and descriptor lifetime.

Linux rename cookies are additionally global: https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/fs/notify/notification.c#L38 defines one atomic counter; fsnotify_get_cookie increments it; https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/include/linux/fsnotify.h#L249 uses it for MOVED_FROM/MOVED_TO. Consequently unrelated host renames affect raw event bytes even for a private guest filesystem. A lifecycle-only pass is not deterministic read evidence.

An explicitly restricted mask policy could reject MOVED_FROM/MOVED_TO-containing requests rather than silently clear bits or normalize cookies, but it needs correct prefix errno order and proof that imported/inherited instances cannot already carry those events. It also leaves the independently measured virtual-proc/path/synthetic-event defects unresolved. Generic read/readv/poll/epoll would newly expose these queues; capture metadata, aliasing, transfers and last-close behavior need source-grounded treatment. I did not establish a complete deterministic inotify design and recommend no port of its production patch now.
