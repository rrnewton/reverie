- panic_promotes_wrapped_abort_and_publishes_its_complete_effects_subtree: the same wrapped abort/effects/cleanup subtree is first refused as a real source by actual FailureContext publication. ToolPanics then promotes a real destruction panic, retains the entire original subtree, and passes the actual is_peer_cancelled_tool_worker check as non-cancellation. Actual RunFailure/FailureContext publication records exactly one event with original pid/tid/phase and wakes run/process subscriptions. Also checks ToolPanics itself publishes nothing before the explicit outer publication.
- no_panic_preserves_success_and_typed_errors_without_new_wrappers: a non-Copy success value retains Arc identity; typed HostIo and wrapped abort/effects errors retain their exact original SharedFailure wrapper/Arc; no payload is invented.
- take_transfers_only_pending_payloads_once_and_accepts_a_later_batch: earlier appended and newly caught payloads transfer in exact order; a no-panic completion does not drain them, the second take is empty, and a later batch remains independent. The absent-output plus real-panic branch remains a typed failure. Payload Drop probes try_lock on the actual owner mutex. Cell payload state is deliberately Send but not Sync, while ToolPanics is required to remain Send + Sync.
