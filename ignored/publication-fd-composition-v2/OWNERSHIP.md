The queue holds only File or Arc<File> ownership and test-only probe state. It has no Tool, G, publisher handle, task, or callback reference. Its short mutex is released before any destruction or test probe. Nested scopes prevent an inner helper from draining while its outer executor still owns the table guard. `drain_unlocked` is called only after explicit release and before existing possibly blocking operations. It does not make those operations cancellable. Scope order is part of the private contract, not a runtime assertion that silently tolerates a held guard.

The source covers the retired local/authoritative table and the staged installation paths above. It does not promise that every host operation under every existing mutating dispatch is bounded. Raw received ancillary-data sanitization still uses its existing direct close path; open preparation and unrelated native operations remain unchanged. This is not a generic host-close or blocking-I/O framework. Allocator abort, deliberately leaked ownership, and unrelated corrupted internal state are not recoverable guarantees of the retirement helper.

The four structural controls use actual `execute`, `thread_child`, `replace_after_exec`, and `release_files_on_exit` paths. A cfg(test)-only probe observes fstat-valid descriptors still owned by the retirement batch and waits for another host thread's immediate attempts to acquire both actual mutexes. It asserts the expected local and authoritative old descriptor identities were in the batch for close/dup and exec. The probe is outside the queue mutex. The exit control proves local/stdin/pending-executable retirement and guard availability; the old authoritative table's last Arc drop is established by source order, since the probe itself retains an Arc to that table. The partial-install control injects EMFILE after two real clone successes to isolate cleanup; it does not replace the unchanged separate real-EMFILE subprocess control. The accept control performs a real ready Unix-socket accept and checks EOF after second-install failure.

The two original component changes are composed semantically, not by taking either whole helper. `insert_file` keeps the FD entry marker and returns replaced ownership. `install` retains the FD repair's all-clones-first behavior, now with staging ownership. All previous descriptor and signal assertions remain unchanged. `V1-TO-V2.patch` identifies the retirement correction and five additive controls; the two component deltas make the complete conflict resolution reviewable.

The private publisher's lock order is initial released registry/image lookups, then file table → transaction → lifecycle → run failure → process signals. Image validation briefly reacquires image below transaction; child provenance lookup briefly reacquires registry below lifecycle. Those short guards end before later acquisition. Failure is not innermost: it remains held after process/lifecycle release through readiness I/O and serializes publications across processes. The changed poison branch refuses before pending mutation and leaves the existing first publication-failure latch untouched.

Before activation, authoritative and local signalfd readiness carrier resolution must be reconciled with a sibling close/reuse control outside execute/install. Selection/readiness notification must not be confused with recipient authorization or guest resumption. Ignored alarms, all actual shared removals, and terminal-after-commit failure still require their separately reviewed owner protocol. This candidate adds none of them.
