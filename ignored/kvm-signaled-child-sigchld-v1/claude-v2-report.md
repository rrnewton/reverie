## Determinism and Linux/POSIX assessment

What changes:
- `validate_child_exit_signal_event` now admits `CLD_KILLED`/`CLD_DUMPED` with class-specific status domains: exit byte `0..=255` for `CLD_EXITED`; `1..=64` with default action *terminate* for `CLD_KILLED`; the x86-64 core-default set (`SIGQUIT, SIGILL, SIGTRAP, SIGABRT, SIGBUS, SIGFPE, SIGSEGV, SIGXCPU, SIGXFSZ, SIGSYS`) for `CLD_DUMPED`. This matches Linux: `si_status` holds an unsigned exit byte only for `CLD_EXITED` and the raw killing signal otherwise; the kernel reports `CLD_DUMPED` only when a core was actually written and `CLD_KILLED` (with the same core-capable signal) when it was not, which is exactly the documented overlap. The `CLD_DUMPED` set equals Linux's `sig_kernel_coredump` membership on x86-64 (no `SIGEMT` on this arch). Excluding default-ignore/stop signals (`SIGCHLD, SIGURG, SIGWINCH, SIGCONT, SIGSTOP, SIGTSTP, SIGTTIN, SIGTTOU`) from `CLD_KILLED` is correct: no Linux task exits with those as its killing signal, and the exclusion is fail-closed and pinned by negative tests (`child_exit_signal_tests.rs:231-244`).
- Because `prepare_filtered_signal_delivery` (`executor.rs:3890-3896`) reuses the same validator, initial publication and Tool-return now accept and reject identically — the asymmetry that broke a Tool-returned `SIGCHLD/CLD_KILLED` at the delivery boundary (`runtime.rs:4631`) is gone.
- `encode_signalfd_siginfo` now fills `ssi_pid/ssi_uid/ssi_status/ssi_utime/ssi_stime` for all three terminal classes, matching Linux's `SIL_CHLD` branch. This also repairs a real producer/receiver mismatch: `process_signal_publication.rs:935-936` and `executor.rs:15596-15597` (waitid) already emitted `CLD_DUMPED`/`CLD_KILLED`, which previously encoded as a kill-style record with no status.
- `signal_has_core_default` is an extraction from `terminating_signal_status`; the fatal-exit path is byte-for-byte semantically unchanged (`dumpable && core-default`, same list, same order).

What does not change: process-vs-thread pending ownership, first-complete-siginfo coalescing, pending generations, `SIG_IGN`/`SA_NOCLDWAIT` policy, lifecycle/fork/exec behavior, lock order, the `RejectedBeforeCommit`/`FailedAfterCommit` split, and the `CLD_EXITED` `0..=255` domain (unchanged bounds, just re-expressed as `i32::from(u8::MAX)`).

Determinism: the validator and encoder are pure functions of the event bytes; no host time, no map iteration, no host-scheduling dependence introduced. The two new tests iterate fixed arrays with a fresh `ElfExecutor` per case and compare zero-initialized ABI structs, so padding and ordering are deterministic. Producer/receiver stay consistent: `ExitStatus::Signaled` is only produced where disposition is `Terminate` (or forced `SIGSEGV`) — `vm.rs:3983-3998`, `executor.rs:15164-15168,15241-15249` — so every producer-generated `CLD_KILLED`/`CLD_DUMPED` event passes the new receiver validation.
