# Reverie dequeue-observation correction for independent review

This is an authored, uncommitted successor to frozen-v2 on Reverie `f97b7be1de4e2ef10ecc24cee5d8cc47f2fd254f`. The full patch changes 17 paths; the correction against frozen-v2 changes 12. Both patches reconstruct the same complete after-files. No SCM commit/push, independent approval, Hermit integration or general timer-delivery claim is made. Previous frozen proposals and all original measurements remain unchanged.

The actual corrected component passed 49 distinct library and 13 distinct static-ELF tests, with no ignored or zero-selected result. The exact inventories were 486 library and 298 static-ELF declarations. Formatting and Clippy (`-D warnings`, library and static_elf target) also qualified. These are finite component results, not a full-workspace or full-DAG receipt. Source and executable identities, individual selectors, raw results, limits and measured costs are in QUALIFICATION.json; repeated historical groups are separate from the final 62-name union.

## Adjudication of the actual Claude v2 findings

- **H1: pending cleanup and caught-worker panic.** `parked_signal_runtime.rs:220` polls the actual cleanup future first, retaining an already-ready result; a pending FIFO/notification future is canceled by the real run failure subscription. It does not acknowledge, roll back or steal any pending effect. `vm.rs:3333` transfers the panicking worker's own irreversible journal into its typed failure before retirement and resumes the original panic payload. The positive-v1 real two-owner test exposed a further loss: a waiting callback had already transferred its own effects into `HandlerSignal::RuntimeError`, but `drive_handler` replaced that error with `RunFailed`. The correction at `runtime.rs:1489` retains that terminal object when failure wins, while failure still prevents ordinary callback completion and child-start release. Original panic payload and cancellation controls also passed.
- **H2: independent sibling progress.** The added real guest control uses an independent worker acknowledgment delay and observes a later owner waiting until it completes. The panic control makes the worker fail while another owner waits, then requires both distinct owners' removals in the failed completion. Original cooperative controls remain. The Tool contract explicitly requires an acknowledgment to finish without waiting for the later blocked owner to progress or relinquish a scheduler token. Process FIFO alone is not a deterministic scheduler/recipient proof.
- **M1: internal bookkeeping cannot become guest errno.** The actual locked dequeue preflight records its typed admission/capacity/sequence/allocation failure separately in private `LoadedStaticElf.signal_dequeue_failure`, before removing a pending event. Both injection completion and the unsubscribed path consult it before returning a private raw errno or a partial positive result to Tool/guest execution. Any earlier irreversible removals and original raw copyout result remain in the terminal error. Real guest copyout EFAULT retains its existing notification/acknowledgment behavior. Controls cover both signalfd and rt_sigtimedwait paths, identity/capacity/sequence refusal, a partial signalfd read with all earlier removals, and both return paths. Allocation refusal shares this source branch but was not fault-injected.
- **M2: proposed foreign-journal deletion is rejected on the supported paths.** Normal leader exec cancels/joins owned workers and checks teardown failure before replacement (`vm.rs:1821` onward). `prepare_exec` and `exec_process` independently refuse worker/nonleader exec before discarding its shared image; lifecycle direct exec is initial or post-exec, while lifecycle clone/fork and worker exec are refused. A successful supported exec with an abandoned foreign journal was not established. Clearing/filtering those records would discard irreversible evidence. The correction preserves them, and the actual worker-exec refusal/teardown-error controls passed. This is not a claim that KVM implements Linux nonleader exec.
- **L1: no-effect local error.** `executor.rs:3577` returns a truly empty owner-local wrapper before poisoning the process dequeue stream. A sibling's pending journal stays unchanged. Run-wide failure publication remains the responsibility of the existing run owner; an actual effect transfer still poisons and wakes the stream. The control checks the sibling's real stream state and entry, not merely an error label.
- **L2: watermark documentation.** Error acknowledgment describes the process-wide contiguous watermark, including sibling-owned removals, rather than a thread-local count.

Two concrete boundaries were also resolved without broadening delivery support. Effective `ThreadOwnership`, including a caller override, is statically resolved in `run_static_elf_with_tool_completion` before GlobalState initialization, installed-image consumption or guest execution. Opt-in dequeue observation with Host ownership now returns `SignalObservationRequiresToolThreads` there. A real admission control requires no GlobalState/guest start on refusal, retains the installed ELF, and then proves explicit Tool override and non-observing Host behavior. This rejects only a combination lacking a removing Tool Guest; it does not force ownership or hide removals.

Caught selection reserves the event/disposition, not a completed frame. The actual frame consumes the current posthook mask and altstack. The added guest changes both after caught selection, requires one delivery on the new stack even though the selected signal is now blocked, checks the frame's saved mask/stack and restoration, and retains the existing disposition-write refusal. No new mask/altstack exemption was introduced.

## Actual failures and qualification

Negative-before-v1 retains four terminally accounted raw-101 failures: pending cleanup ignored a published failure; raw bookkeeping error was not terminal; no-effect wrapping poisoned the sibling stream; worker panic lost one of two owners' removals. Positive-v1 retains its real raw-101 two-owner failure after the first correction (the other owner's transferred error was lost). Negative-before-v2 retains two further raw-101 failures: callback-poll terminal error loss and late acceptance of incompatible Host observation. Each is distinct from the final positive-v2 evidence. Read-only retained ELF copies identify each executed source version; old compiler output paths are historical provenance and may be overwritten by later compilation.

The nine test groups together used 21.539206 aggregate CPU seconds and 7.132628 payload wall seconds; those sums cover 49 library and 13 static-ELF identities exactly once. The 62-name union includes 43 original component controls, seven existing terminal/exec boundary controls and 12 new correction controls. Some library tests initialize KVM without executing guest instructions; the static-ELF controls execute real guest code with `REVERIE_REQUIRE_KVM=1`.

Its raw137, accepted=false, accounting_complete=false and missing payload remain recorded. Two fresh exact-unit/process checks proved owned lifecycle quiescence. A one-plan/one-proof-hash continuation lease branch consumed only that cleanup proof, without fabricating CPU accounting or a format pass. Fresh unchanged formatting and Clippy then both qualified. Canonical observer/before-exec sources and all resource bounds remained unchanged. The continuation is test infrastructure, outside the product patch.

No limit was widened. Full source/dependency/toolchain/loader/ELF identities and actual selection/count/terminal evidence are bound by the plans and qualification records.

## Scope and goalpost check

No scheduler choice, virtual clock, timer precision, INFO record, syscall comparator, accepted errno, test skip, tolerance or assertion was weakened. Existing exact effect/count/state checks remain, including the failed positive-v1 two-owner assertion. Added tests were first exercised against the defective behavior where practical; original negative runs remain failures.

The per-process sole-signal-receiver restriction remains. Separate single-threaded processes use their existing per-tgid state. A general deterministic multi-thread recipient snapshot/selection and arbitrary parked request resumption are separate changes owned by the Hermit integration work; this packet provides no such API expansion. It neither clears outstanding effects to avoid deadlock nor invents a callback after unwinding. All public Guest/Tool signatures match frozen-v2; the public KVM error enum gains the setup-refusal variant described above.
