The smallest coherent increment is a **run-scoped failure notification received by KVM's existing Tool-future driver before physical joins**, followed by the existing consuming retirement path. It requires a real multiwaiter wake and a distinct failed-run outcome. A final error field, a normal `ThreadExited` RPC reply, or host-thread interruption alone cannot supply this progress. ## Proposed patch, in dependency order

1. **Private Detcore terminal state.** Keep the first terminal transition/cause in a run-owned object shared with Scheduler. Linearize it under the existing scheduler admission/commit mutex. Publish the wake after releasing that mutex. Later failure notices are idempotent as transitions and preserve distinct cleanup diagnostics; they do not overwrite the primary cause. The event aborts this GlobalState instance, not a PID selected from an external registry. Scheduler-originated refusal uses this same producer directly. Stop before further ordinary grants, and wake/finish the daemon's startup/quiescence/request waits. If a tentative selection was opened, close it without committing, using the existing transaction discipline. Preserve already-observed timer/clock effects; no rollback or new guest turn.

2. **Two additive, defaulted GlobalTool hooks, not a new RPC envelope.** Proposed shapes are a synchronous `report_backend_failure(event)` (default no-op) and an asynchronous `wait_for_backend_failure()` (default pending forever). The report carries backend-owned pid/tid/phase metadata; the original typed backend Error remains in its execution result. Detcore implements publication/subscription against its terminal object. Neither hook consumes ThreadState, asserts guest waitability, nor waits on guest RPC/join. `on_backend_child_wait_event` cannot be reused: its current contract reports an actual committed wait state/status. Other backends retain their defaults.

   Install a private failure reporter in each Tool-driven KVM process context before callbacks can execute. Low-level `vm.rs` cleanup helpers must receive/use that reporter before their first join, including pending-start failure. A weak reference to the existing Arc GlobalState avoids retaining it past `Arc::try_unwrap`; the invocation's root Arc owns its lifetime. Each child invocation binds its actual pid/tid, and exec remains within that run. No PID-generation registry or host-PID lookup is needed: this is run failure, not retirement authority. Absence of the reporter in the non-Tool path remains explicit. A Tool invocation must not silently drop a required notice.

3. **Receive in `drive_handler`, not by filling normal response ivars.** Poll the terminal subscription before the Tool future, and check it again before accepting a ready result or releasing pending starts. Return a distinct private failed-run outcome. Dropping the parked Tool future releases the outstanding direct `receive_rpc` future; it never returns a fake `Go`, `Signaled`, `EINTR`, or an operation-specific success to the Tool. If a normal grant already linearized before failure, retain that fact; prohibit later scheduler grants. Keep request/response identities and partial admission state available for actual consuming cleanup. This avoids changing every RPC helper or the generic wire response type.

   The failed-run arm cancels owned unstarted gates and follows error teardown; it does not use the existing cancellation arm that starts children. It also does not tail-inject `exit(0)`. Existing host-worker cancellation/owned joins still stop physical workers and release resources; the new wake specifically closes the parked-Tool-future gap. Publish at each existing **fatal** callback/runtime/owner-hook error before dependent cleanup, not for an ordinary guest errno, normal exit, normal exec, or a peer already cancelling because of the same run failure. Report an owner-hook error before joining descendants. Preserve worker-before-leader hooks and the backend's actual group status.

4. **Keep consuming cleanup out of the interrupted callback future.** The backend still owns and consumes each ThreadState once. Detcore's real `on_exit_thread` atlib2808–2935 sends final robust-list clock/wake requests and DeregisterThread through `KvmGlobal`, outside `drive_handler`. Those current nonblocking handlers remain available after run failure with all sender/MmId checks intact. `recv_deregister_thread:1792–1846` already deduplicates final accounting via `note_deregistration_accounted`; retain it. Do not prematurely tombstone every task or blanket-reject cleanup RPCs: that would suppress real final clocks and robust-list accounting. Do not let their wake bookkeeping restart ordinary grants after failure. Custom Tool exit hooks that themselves block indefinitely are not proven safe by this Detcore-specific path.

5. **Return the error with its GlobalState.** The current outer `run_static_elf_with_tool` at runtime1885 uses `?` before returning GlobalState; Hermit run_kvm2096–2101 then stringifies the backend error. A final latch check alone therefore loses cleanup access on Err. Extract a small completion-returning variant that preserves the owned global state and the execution `Result` after all owned joins; keep the existing public convenience method as a wrapper. Hermit consumes the completion, finishes the terminal daemon/global cleanup, and returns the retained typed failure plus any backend cleanup cause. Cancellation's internal0/255 is never returned as successful qualification. Keep real global-ownership failure an error, not an invented successful completion. `hermit-cli/src/error.rs:133–179` currently recognizes only UnsupportedSyscallError for policy refusal; the later virtual-signal refusal must gain its own typed case before that serializer. Do not disguise it as an unsupported syscall or classify by Display text.

The bounded source slice is Reverie `reverie/src/tool.rs`, `reverie-kvm/src/runtime.rs`, `vm.rs`, plus focused runtime/vm controls; Hermit `scheduler.rs`, `tool_global.rs` (a private terminal helper module if useful), `hermit-cli/src/lib.rs` and the typed error consumer when the signal refusal is wired. No ordinary scheduler selection, signal disposition, group-exit status, inode, clock or comparator redesign is required. A defaulted notification API and a completion result are genuine new interface work; the current API does not already promise them. They need normal source ownership and independent review, not a new design authority or speculative registry.

## Decisive controls and bounded next step

The existing no-VM `failure_and_join_order` atvm6598–6640 and its two tests6643/6648 spin on `GuestThreadGroup.cancelled`. They do not park a Tool RPC, so they cannot establish this fix. Preserve them unchanged.

Add a native control using the **actual driver and actual owned join path**. Existing runtime tests3240–3312 construct a KvmGuest with GuestMemory/test executor without creating a VM; reuse that facility, not a mirrored notification algorithm. Put a real OS worker's Tool callback inside an admitted, pending `send_rpc` future. Use barriers to prove (a) that future was polled Pending and (b) the joiner took the worker's actual handle. Then trigger the production fatal-error reporting boundary from another controlled participant. Require notification -> failed-run outcome -> one consuming cleanup -> actual join completion, with the exact primary diagnostic retained and no new guest continuation/start-gate release. The worker must not poll the cancelled flag as an alternate escape. A private watchdog may release a stuck test worker only to reap it **after recording failure**; that rescue must never satisfy the assertion. Moving publication back after the join, or removing the driver subscription, must make this negative control fail.

The matching normal-retirement control supplies the original normal RPC response, requires no terminal notice, exact ordinary status37, one worker hook before the leader hook, no leftover owned handle, and no invented error. A queued child stays behind its intended gate. This is a native lifecycle control, not a canonical Hermit guest/parity result.

Add focused real-GlobalState controls for two concurrently parked subscribers (catching the single-Waker mistake), before/after-publication arrival, ready-response versus failure linearization, a pending startup/resource/futex/replay wait, daemon tentative-selection cancellation, and exact robust-list/deregistration accounting after failure. Exercise both restricted and ordinary driver callers and pending-start refusal. Preserve normal errno returns and normal group/exec cancellation controls. The original strict fork-tree and the49 census classifications remain untouched; neither a native pass nor this notification delivers SIGCHLD.

Uninterruptible host I/O and arbitrary panics are not solved by this returned-error/RPC design; the native control must demonstrate the specific historical dependency shape without claiming a replay of its measured cause.
