2. fdinfo must observe a guest task's descriptor at the Linux observation point.

Linux v6.12 fs/proc/fd.c seq_show at23–71 resolves task plus fd under the files lock, combines file->f_flags with that descriptor's O_CLOEXEC, takes a file reference, then emits file position, mount ID and inode. seq_fdinfo_open at74 only installs single_open. fs/seq_file.c seq_read_iter and seq_lseek determine when the record is generated or retained. The copied upstream files and Git blobs are bound in source-binding.json. This host runs 7.1.3-0_fbk0_rc18_0_gd373cd4b8dbf; the upstream source is a semantic design reference, not a claim that the proposed native observations have run on this kernel.

Required behavior and controls:

| Operation sequence | Required source-derived behavior |
| --- | --- |
| Open fdinfo, change target offset/status/CLOEXEC, first read | Observe the then-current target descriptor and OFD state, not the open-time values. |
| Open fdinfo, close target, first read | ENOENT; retaining the old object must not make the closed entry readable. |
| Open fdinfo, replace target guest number, first read | Resolve the replacement in the original target task, never a reused supervisor number. |
| Partial read, mutate/replace target, continue reading | Consume the retained seq record; do not regenerate each chunk. |
| Rewind to zero then read | Generate a new record; close/reuse must be reflected. |
| Seek to a changed nonzero position | Linux traversal may generate the record during seek, with errors then; SEEK_END remains EINVAL. |
| Dup/fork an open fdinfo descriptor | Share its description/cursor/record and preserve the originally addressed task and fd; a child's own same-number fd is not the target. |
| Target exits, execs or PID is reused | Respect the original task lifetime/generation and its current table; do not bind to a new task with the same numeric ID. |

A minimal safe private representation is an fdinfo open description shared by descriptor aliases, holding the target task identity/generation plus guest fd, a sequence cursor/buffer, and a checked weak reference to that task's current file table. At each generation point, resolve and pin an actual owned file under the table lock, sample guest CLOEXEC with the mapping, and release the table lock before host I/O. Generate from that pinned file, using a short-lived owned /proc/self/fdinfo/<resolved host fd> read while the source File remains alive. Do not retain that raw proc descriptor or raw fd number for subsequent guest reads. The resulting bytes may retain native object-specific fields, subject to the backend's established virtual-object rules; Detcore's unknown-field/lock/epoll/inotify normalization refusals remain untouched.

This needs an explicit private lifecycle slice beyond metadata helpers: LoadedStaticElf descriptor metadata and fork/exec initialization in elf.rs; FileTableState snapshot/install; ordinary dup/fcntl/dup2/close/close_range/exec ownership; and the executor's scalar/positioned read and seek routes. The existing synthetic-proc vectored ENOSYS boundary must not be silently bypassed. New fdinfo support should either implement a coherent seq readv/preadv path with actual import/error-order controls or keep the existing explicit unsupported boundary, stated as incomplete vector support. Do not forward its backing storage to write/mmap/sendfile as though it were an ordinary memfd. A generation-qualified task-to-table association can reuse the existing lifecycle registry style; it must be weak to avoid ownership cycles and must be updated across exec and removed on exit. A direct reference to the opening table alone is insufficient across exec. The source review must cover lock ordering and avoid holding a source table lock while acquiring a second table or blocking on guest progress.

Initially support ordinary real files, pipes and sockets whose metadata belongs to an actual owned file. Preserve explicit refusal for captured-only sinks, synthetic proc descriptions and virtual anonymous objects whose private carrier is not the guest object, until their complete fdinfo representation exists. This is preservation of a previously unsupported surface, not permission to remove an existing positive control. Do not fabricate a mount ID for those objects, expose capture backing stdout, or expose a virtual signalfd's private eventfd identity. The existing descriptor-reuse test remains selected and unchanged; its ordinary files and pipes must all pass.

3. Use the actual backend filesystem namespace for both mountinfo and ordinary fdinfo.
