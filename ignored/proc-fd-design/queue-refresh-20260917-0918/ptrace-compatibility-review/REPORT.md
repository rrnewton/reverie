This changes the old blanket post-start exec refusal into supported reactivation plus specific refusal cases. Exec before activation and successful nonleader exec remain refused; failed exec keeps the original image and errno.
- [tracee_preinit](https://github.com/rrnewton/reverie/blob/4db9ddb68126ce97ff929c7f30b61a633e48513e/reverie-ptrace/src/task.rs#L1609) now obtains the held-stop lease through the existing session-root predicate. - [wait_after_exit_event](https://github.com/rrnewton/reverie/blob/4db9ddb68126ce97ff929c7f30b61a633e48513e/reverie-ptrace/src/task.rs#L4661) retains the actual Wait instead of immediately assuming death. After the old run-loop future is dropped, it re-arms the actual stop, calls the existing safeptrace revoke_owned_exit_stop, and publishes the precise nonleader-exec refusal. This is a new consumer of an existing exact-generation cleanup capability. That API transfers claimed ptrace exit-stop ownership; it does not cancel an arbitrary Tool RPC. Its exclusive-ownership safety contract and the existing cleanup consumer in tracer.rs are unchanged by this increment.

The already-existing LiteInst session failure mechanism is material to interpreting the change. record_liteinst_failure writes the shared failure slot and notifies its root. The root selects that notification against its run loop and, after exit, against tool_exit. These selects and the pre/post tool_exit checks already exist at base596 task.rs:4886-5047; the new head extends the exec cases that can reach them. Non-root orderly Tool exit may still be pending, while the separate root failure notification can transfer control to its cleanup guard. This is not evidence that returning a final result alone can release a blocked hook or dependent join.
