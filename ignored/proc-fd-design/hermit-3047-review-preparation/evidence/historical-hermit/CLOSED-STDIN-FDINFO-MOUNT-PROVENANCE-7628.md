A correct owned-descriptor fdinfo implementation also needs a coherent KVM mount-identity contract in Hermit. This is an additional source finding, not a new executed failure. The retained candidate KVM run stopped at openat EACCES before any fdinfo bytes were read.

At exact Hermit 7628b6d5, run_kvm in hermit-cli/src/lib.rs clears mountinfo_mount_ids, sets mountinfo_mount_ids_captured=false and clears fdinfo_unlisted_mount_ids at lines1978–1986. Its comment explicitly ties that choice to the unsupported fdinfo surface. It also clears mountinfo root rewrites and records an equivalence between the backend's synthetic root device0:1 and actual root metadata. The pinned backend supplies a synthetic mountinfo table with raw root ID1 and parent0.

The ordinary and verify CLI paths already capture an exact mount-ID order after entering the completed container: run.rs4076–4085 and4680–4684 invoke the execution closures there; lines4902–4912 and4974–4984 pass IdentityGuard's captured identity order and root rewrites. container.rs302–318 documents the completed, quiescent namespace and held-descriptor resolution. The helper capture_mountinfo_identity_order in lib.rs3185 reads /proc/self/mountinfo and preserves its row order plus otherwise absent parent IDs. Public library and no-namespace callers may have no producer-owned snapshot, so keeping only the supplied vector does not cover every entry point.

If fdinfo becomes readable with a nonzero real mount ID while captured remains false, Detcore files.rs1284 tries /proc/{guest.pid()}/mountinfo. KVM's Guest implementation returns its guest PID from runtime.rs733, and Hermit sets the root PID from ROOT_DETPID rather than a supervisor task identity before execution. That fallback cannot be assumed to identify the actual descriptor's mount namespace.

Simply retaining the captured outer namespace vector is also incomplete: MountIdPool enforces the declared raw mountinfo order (or an ordered visible subset when captured), and the unchanged synthetic row1/parent0 is not proven to be a member of that actual namespace order. The fdinfo and mountinfo representation, root/device rewrites and producer snapshot therefore need to agree. A fabricated fdinfo mnt_id=1 or disabling the existing provenance validation would conceal this disagreement rather than implement Linux semantics.

Its eventual mountinfo/provenance contract must be specified before the narrow Hermit integration delta is implemented.
