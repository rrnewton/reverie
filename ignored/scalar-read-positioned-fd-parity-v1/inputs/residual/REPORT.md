The vectored hypothesis fails at a concrete second guard. Dispatch first calls `virtual_signalfd_write_error` (358). That helper still uses checked conversion for `writev` (6767), so upper bits cause it to decline interception. However, `vectored_io` then selects the guest fd using its low 32 bits (5312), resolves the descriptor, and checks `signalfd_mask(state, guest_fd)` (5354). For current-position writes it returns `EINVAL` at 5358, before `decode_guest_iovecs` at 5387 or any payload write. This covers `writev` and `pwritev2` with offset -1, including duplicate descriptors present in the same signalfd-mask map.

For explicitly positioned vectors, signed offset validation occurs first (5305; helper 5155), followed by a zero-vector host seekability call (5338–5351). It supplies a null iovec and count zero; it cannot copy the proposed eight-byte payload into the carrier. The expected nonseekable-host result is `ESPIPE`. The scalar `pwrite64` companion guard is necessary for a different reason.
