The CLI now normalizes `Config::backend_rejects_host_signals` to exactly `Backend::Kvm`, including stale true/false inputs. Native backend values are reset to false. DBT's existing `backend_requires_thread_directed_process_signals` setting remains distinct and unchanged.

`finish_kvm_tool_completion` first awaits the owned scheduler naturally, then examines the recorded refusal. This order matters: checking the refusal before the existing normal cleanup join could miss a refusal published while joining and then write a successful summary. After the join, a backend error, scheduler JoinError or retained refusal takes consuming `clean_up_after_backend_failure`; its actual first join outcome is preserved instead of replaced by the second no-handle join's `Ok(())`. Only an actual successful backend result with successful scheduler join and no refusal enters normal summary cleanup. KVM uses `GlobalTool::init_global_state`, which calls `GlobalState::initialize(cfg, true)`; this proposal does not assert quiescence for arbitrary external scheduler owners.

The error composition retains actual values. When the backend returned `Ok`, a refusal becomes the typed cause itself; no `reverie_kvm::Error` is fabricated. A real scheduler JoinError without a backend error similarly remains the actual typed cause. When the backend returned `Err`, that complete backend value, including its existing shared cleanup structure, remains downcastable. The typed refusal, scheduler JoinError and recording failure are added without flattening or replacing the backend error. The first diagnostic line includes the actual primary description and any separately retained refusal, preserving the existing exact first-line behavior when no refusal exists.

Classification uses the existing `FailureKind::PolicyRefusal`, before `SerializableError` erases types. Refusal alone, or refusal plus **bare** `RunAborted`, is a policy refusal. Any independent backend error, scheduler JoinError or partial-recording error stays `FailureKind::Error`, with the refusal still retained. A private typed context records that compound distinction. Neither display text nor `error.primary()` is used to discard a whole aggregate: a `WithCleanup` whose primary is `RunAborted` and whose secondary is real EIO remains an error. The classifier reaches through transparent `reverie::Error::Tool` wrappers for both refusal and compound-failure context, and preserves existing unsupported-syscall recognition. Equal-looking untyped prose is not a refusal.
