Bounded implementation design

Ten declarations: three Host ELF main controls (group stop before retry subscription, group stop after both real subscriptions/before predicate, and close 1 reopened then close 2 before retry); five Tool ELF main controls (both windows crossed with group cancellation and scoped GlobalTool failure, plus same-run close 2); two parking declarations (before/after subscription), each exercising both group cancellation and a real one-shot stop future.

Main controls reuse actual RunProbe.before_run to arm all descriptor/mask/RUN/clock observations and complete close 1 after ordinary setup. They first require the existing ObservedChange/PrepareProbe actual Pending notice. This may include an immediate retry because the initial close itself wakes the preexisting subscription; therefore the controller records the actual baseline closed-admission/wait counts rather than inventing a first-poll count. It then arms one action and wakes the same closed run. A cfg(test) hook fires before actual gate.subscribe or after the actual gate and cancellation subscriptions, before the unchanged stop predicates. The former publishes stop before registration; the latter publishes it within the requested window. Both retain close 1 through terminal selection and require zero later descriptor access, mask installation, RUN, clock begin/interval and exit. Tool's real consuming hook is held by a controller release so terminal selection is observed before reopening, and ordinary cleanup completes only afterward.

The same-run positive drops close 1 and, at the retry's before-subscribe hook, obtains a separate completed close 2 from the unchanged Mapping. The actual next subscription must become Pending again. Exactly one new denied admission and actual pending wait is required relative to the recorded baseline, with all dispatch counters still zero. Reopening close 2 then yields exactly one real finite ELF exit, one mask and one untracked (Host) or tracked (Tool) RUN, with Tool clock accounting unchanged.

Parking controls use the real park_process_action future, closed before preparation, with the existing real-mode fixture. Its only awaited suspension on this path is the actual select of gate/cancellation/stop. A first delegated Pending plus observed before/after subscription and zero activity proves that actual wait; no fake pending future replaces it. Wake the unchanged gate and inject stop in the chosen retry registration window. Group cancellation must return exactly Ok(false), the actual non-fused oneshot async stop must return exactly RunAborted and complete once. Keep the close through that terminal return. Then reopen before inspecting unchanged trampoline bytes/registers. These are helper registration controls, not prepared caller or internal-HLT proofs; the existing helper and four caller controls remain separate.

Hook implementation is a cfg(test) current-host scope with RAII restoration. It calls observer closures outside its TLS borrow and outside production gate/group locks. Tool main hooks are the only authorized runtime.rs edits; root receives an exact separate Host/parking vm.rs patch because the action author owns that file. Every original non-test statement and existing test remains. No raw Host loop stop contract is changed.

All successful control ordering comes from actual wakes, exact boundary hooks and finite five-second waits, not sleeps. Assertion paths release every close/consumer/stop dependency before bounded completion and joining host actors. No ordinary gated memory operation is demanded while Closed. Counters are never reset to hide work; parking's explicit post-terminal inspection occurs only after the no-dispatch assertion and reopen, with observation disarmed solely for that fixture inspection. No test/compiler/formatter/guest/network/SCM execution is authorized to this author. Source, compilation and qualification remain distinct.
