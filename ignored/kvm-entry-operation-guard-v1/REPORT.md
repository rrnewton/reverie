## Mechanism

A Tool can catch EIO from actual MemoryAccess after a fatal private entry cause has been captured, then await an immediately ready RPC or injected syscall in the same callback poll. The outer driver's post-poll check comes too late to prevent those operations. Actual Tool failure publication intentionally follows destruction of that callback, so checking only publication is insufficient.

Each KvmGuest now derives a private watch from its callback-bound memory. A narrowly scoped OperationOrigin accessor upgrades the existing driver owner; it creates neither a callback registration nor a publisher. The watch checks both the current mapping's gate and the existing driver's pending failures, including failures attributed through another retained mapping. Ownerless guests still check their current gate. A retained origin whose owner allocation has disappeared still has its retirement witness checked. Existing EntryDriverWatch fields and all old test literals remain unchanged.

Ordinary RPC admission checks before receive_rpc construction, before each poll, and after each poll. The private notification is subscribed before rechecking sticky state. A failure records HandlerSignal::RuntimeError and suspends nonlocally. The cause is recorded before destruction of a returned response or RPC future, so the existing outer panic catcher can retain destructor payloads without losing that cause. KvmGlobal is unchanged, and notifying_dequeue RPC takes its existing bypass before ordinary checks.

Inject and tail_inject check before invalidating executor state. Inject also checks after signal bookkeeping preparation, after completing already committed signal effects, and before returning ordinary control after process-action completion. Deferred signals, child-exit signal queuing, process-alarm queuing, stack checkout, and parked observation admission are guarded. Synchronous clock reads refuse with EIO while retaining the typed private cause in the handler signal. Stack commit checks before writing and between writes; genuine ordinary copy failures retain EFAULT, while a private failure yields EIO. Already completed bytes are not rolled back.

The parked observation implementation rechecks before a new removal, after the existing dequeue bookkeeping has completed, and after a ready nested structured-signal hook. This prevents a hook that catches EIO from continuing into filtering, delivery reservation, or another removal. Its continuation check retains the real signal ledger before suspending. complete_signal_effects remains unchanged, so notification/acknowledgment of an already removed event still uses its existing continuation path.

The failure-recording helper combines an existing RuntimeError by shared-cause identity. If a nonlocal disposition is already selected, it leaves that disposition in place for existing outer mapping and subsequent sticky-cause folding. A continuation does not copy another signal ledger into a signal slot that already owns a selected result.

## Limits and audit boundaries

This is an admission/resume correction for the identified ordinary adapters. It does not make an already running synchronous operation atomic with an unrelated concurrent poison event. Effects committed before detection remain owned and retained. It does not redesign outer process-action completion, private callback ownership, physical worker joining, or the consuming failure-publication contract.

No new guard is inserted into cancellation, retirement, or prepared fatal-signal selection: those methods transfer an existing nonlocal disposition to the driver and must retain its effects. Register/config/identity queries and the current no-op daemon/timer methods perform no identified ordinary external effect. Complete signal bookkeeping and KvmGlobal consuming hooks are intentionally unchanged.

Guest::memory still returns the existing public UserMemory adapter, and KvmStack's MemoryAccess implementation still delegates to that adapter. A retained healthy mapping's direct MemoryAccess operation is not made owner-wide by this correction; it continues to use its own mapping gate. The new cross-mapping control proves RPC/injection and stack-commit admission observe the common owner, not a universal owner-wide memory-copy property. Further conclusions about arbitrary retained views require their own source and execution evidence.

The fixtures use actual Tool methods and actual MemoryAccess adapters, but the counting executor does not execute a host close or a real guest program. They do not replace the pending full composed tests and independent review. No existing tests, assertions, comparator, limits, public trait, or success classifications were weakened. Source snapshots precede root formatting; later formatting/build source must receive its own hashes.
