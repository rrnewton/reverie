# Owned FIFO read probes

Source-only adapter plan against Reverie `000c15a1161ea2d58749431b5ddaaa97f7aa37d5` (tree `a12d56466eed51cdd7d12087b5fafa9d66d8c864`). Parent owns SCM. No product edits, builds, probes or guest execution. The earlier named-FIFO report and its raw124 failure remain unchanged. This report neither qualifies unresolved imported descriptors nor independently approves the scheduler design.

## Concrete recommendation

For the measured successful O_RDWR FIFO open, introduce a **backend-owned open-description record and retained read operation**, then make that actual description physically nonblocking before exposing its probe capability. Route the logical blocking read through the scheduler's real polling/wait continuation. This can remove the specific raw blocking read; it does not fix blocking open rendezvous, arbitrary imported OFDs, uncontrolled descriptor export, or interrupted-wait semantics by itself.

There are two distinct ownership questions. A fresh successful open normally gives the backend control over this OFD's status flags. It does **not** prove every peer using the FIFO object belongs to the guest. An inherited File, a dup, or SCM_RIGHTS receipt owns a reference but may share its OFD with outside actors. A fresh OFD can also lose exclusive status control when exported. The adapter must represent these facts separately from S_IFIFO and from deterministic internal-versus-external I/O classification.

## Minimal representation and status protocol

There is an **existing stale-OFD source defect candidate**, separate from adding FIFO support. `FileTableState::install:1647–1656` retains an executor's previous File whenever its GuestFileIdentity Arc matches the authoritative slot. `allocate_fd_object_inode:6643–6697` deliberately reuses a Persistent identity for separate opens of a linked `(dev, ino)`. `execute:4161–4178` calls install before each syscall, and `thread_child:2296` shares the authoritative table while retaining private executor Files. Therefore a sibling can close/reopen the same guest fd on the same linked inode, install a new OFD with a different offset/status, and leave another executor using its previous OFD after synchronization. This is a concrete source inference, not a measured failure or attribution to any historical census/readv change. It should be a finite prerequisite identity repair rather than an assertion that only newly managed FIFO entries need correct synchronization.

A deterministic negative-before control can use the existing `FdinfoFixture` and actual `thread_child`/`execute` path, without timing a guest race: open a linked file with known bytes, position its original OFD at 1, keep a dup alias, then create a thread child. Through the child's production execute path close the target slot, reopen the same pathname into that slot as a distinct OFD, position it at 5, and set O_APPEND only on the new description. The parent's next operations must observe position 5 and O_APPEND at the target, read exactly the byte at 5, and advance it to 6; its retained dup must still have position 1 and the old status. Both fstats must retain the same guest inode. Assert these exact expectations unchanged before and after a proposed repair. Add the complementary same-description dup/fork control so a repair cannot replace shared offsets with independent ones. This control is planned, not added or executed here; snapshot refresh must not be manually patched inside the test to bypass install.

Attach an `Arc` record to every relevant descriptor slot: a fresh **open-description identity**, authoritative origin/status-control state, actual FIFO type/access mode from fstat/F_GETFL, the guest O_NONBLOCK bit, whether the backend has physically forced it, and a short mutex for status/probe/ownership transitions. This is separate from GuestFileIdentity (filesystem object identity), guest fd number, and FD_CLOEXEC. A per-slot generation or equivalent Arc comparison distinguishes close/reuse. A pinned File or duplicate pins the same OFD for a read; that duplicate provides lifetime, **not isolation from flag changes**.

Suggested states are `FreshControlled`, `ManagedFifo`, and `ImportedOrEscaped`; provenance is established at production creation/import/export paths, not inferred from pathname, inode, fstat type, current O_NONBLOCK or an arbitrary File constructor. Separate opens of one FIFO receive different records despite sharing a pipe object. Dup/fork share records. Only a current ManagedFifo whose status transitions are all mediated can issue the read-probe capability.

The authoritative file table supplies the current record/File. Order table access before the per-description mutex; never acquire a table while holding that mutex. Independent process tables sharing an OFD must use the same record lock. A retained probe releases table/lifecycle locks before the actual nonblocking host call and never holds a signal transaction or scheduler lock across ordinary I/O. It retains the record guard only for the short flag/probe operation. No lock is held across a Tool hook, guest scheduling wait or arbitrary native blocking call.

At enablement, read actual kernel flags, save the guest bit, set flags|O_NONBLOCK on the privately controlled OFD, and verify success/readback before advertising the capability. Do not call metadata-only `set_physically_nonblocking` proof of the kernel state. Pinning/allocation/preflight precede effects. A failed status update leaves logical metadata unchanged; a later verification failure after a real change must preserve that effect and fail explicitly rather than claim clean refusal.

F_GETFL should report `(actual_flags & !O_NONBLOCK) | guest_nonblock`. F_SETFL must preserve native settable-flag behavior while always ORing physical O_NONBLOCK for a managed FIFO; after success update the shared guest bit. Access mode/creation bits keep native handling. fdinfo applies the same substitution. Do not clear O_NONBLOCK physically just because the guest logically clears it. Aliases/fork see the logical change together; independently opened descriptions do not.

Hermit v27 already has `Arc<Mutex<OpenFileDescription>>` with logical status and physically_nonblocking (`fd.rs:83–113`), but the current backend has no corresponding status provenance. `files.rs:2728–2763` hides the physical bit and forces it only for Socket/Pipe/Eventfd; FIONBIO is handled logically for those forced descriptions (`:2835–2867`). The FIFO adapter must establish **one coordinated source of truth**: for managed FIFO operations pass the original guest flag intent to the backend status adapter, let it keep the physical bit, and update Detcore metadata only from the successful result. Do not pass a Tool-forced flag word and later mistake it for guest intent. FIONBIO's validated logical value must reach the same record; a local Detcore-only update would leave backend fdinfo inconsistent. Other descriptor families and their existing paths remain separate.

## Retained read operation

Preparation proves the current full task/image/callback identity, exact original raw Read/Readv arguments, readable non-O_PATH FIFO, current authoritative description and managed status ownership. It pins that description and records one operation identity. It does not consume bytes or convert invalid pointers, zero counts or wrong access into an artificial success. Actual execution retains the existing scalar/vector argument/fault ordering and performs one read on the pinned File while the physical nonblocking invariant holds.

Return 0 for EOF and every positive short count immediately; do not use Regular's fill-to-request loop. Return a typed would-block result for EAGAIN/EWOULDBLOCK and resume the original scheduler-owned wait. Once a logical blocking read has begun, close/reuse by another guest must not redirect its retries to a new numeric fd: retain the original description as Linux retains the file reference for an in-flight call. A new call resolves the new slot. MM/exec cancellation cannot reuse the old memory/callback token. A caught signal before data uses the separately reviewed prepared-frame/EINTR/SA_RESTART continuation; actual positive bytes are never replaced or replayed. Readv similarly retains complete vector/operation provenance and existing guest-memory fault semantics.

The capability only proves no **data-availability sleep** is taken by this host read. O_NONBLOCK is not a hard wall-clock bound on kernel mutex contention, memory faults, filesystem hooks or host failure. Keep the existing execution resource bounds. It also says nothing about whether a FIFO's other endpoints are internal, or whether external data is deterministically recorded.

## Imported descriptions and escape are real limits

An imported blocking FIFO cannot be made safe by duplicating it and setting flags: dup shares the OFD and changing status mutates the outside owner too. Checking F_GETFL then reading also races an external F_SETFL. Poll says an observation was ready, not that bytes remain reserved; another reader can consume them before the following blocking read. Neither sequence establishes a safe probe.

Fresh-controlled provenance is not permanent. Current `translate_outgoing_control` sends managed-capable Files through SCM_RIGHTS unless they are special fdinfo/signalfd carriers. An outside recipient then shares the same OFD and can clear O_NONBLOCK. It also sees a hidden physical bit that was meant to be invisible. Therefore the adapter cannot simply add a ManagedFifo flag and leave export unchanged.

Before implementation claims arbitrary managed-FIFO lifetimes, it needs a concrete ownership transition: an entirely mediated in-run transfer can preserve the shared record only with authenticated sender/receiver mapping; an uncontrolled export must restore guest-visible physical status before exposure and relinquish managed eligibility. Restoring or exporting while an owned blocking read still depends on the forced bit requires an explicit continuation transition, which current code does not provide. A blanket ENOSYS on all SCM_RIGHTS or silently changing its bytes would narrow existing behavior, not solve the problem. This report selects neither. The initial no-export O_RDWR control is a bounded supported state; export during an outstanding wait and later reads on escaped/imported descriptions remain unimplemented obligations, not passing cases or exclusions added to the product oracle. Unknown/unmediated native descendants have the same ownership problem.

## Primary alternatives and open behavior

Primary Linux reference is upstream v7.1.3 `199c9959d3a9b53f346c221757fc7ac507fbac50`, not authenticated vendor patches. Seven man-pages 6.19 pages and four kernel blobs are retained with URL/byte/blob hashes.

* `open(2)` says open creates a fresh OFD; `dup(2)` and `F_SETFL(2const)` say dup/fork aliases share status. `unix(7)` explicitly describes SCM_RIGHTS as transferring an OFD reference equivalent to cross-process dup. These establish the ownership distinction above.
* A real `/proc/self/fd/N` reopen can create a fresh description, as the existing backend correctly implements for an explicit guest open. It is not an invisible replacement for an imported FIFO: it changes endpoint counts/rendezvous and may fail fresh permission checks or use a different access mode. An internal O_RDWR keepalive would suppress EOF/EPIPE and is not faithful.
* A per-operation alternative was checked rather than assumed. This kernel's pipe read recognizes IOCB_NOWAIT (`fs/pipe.c:374–377`), but anonymous pipe allocation explicitly sets FMODE_NOWAIT (`:969–971`), while named `fifo_open` (`:1121–1242`) calls `stream_open` and never sets it. `stream_open` (`fs/open.c:1574–1580`) only adjusts stream/seek modes, and the ordinary open path does not add FMODE_NOWAIT. `kiocb_set_rw_flags` (`include/linux/fs.h:3433–3435`) rejects RWF_NOWAIT without that mode. `preadv2(offset=-1)` does select ordinary readv (`fs/read_write.c:1184–1193`), but that does not bypass the mode check. Therefore it is not an established named-FIFO solution here; no native probe was run. Anonymous-pipe applicability is separate, not permission to generalize from it.
* MSG_DONTWAIT is a socket operation facility, not an ordinary FIFO read flag. A generic asynchronous/cancellation engine is outside this plan. No alternate API is asserted to solve imported FIFO reads without evidence.
* `fifo(7)` and `fs/pipe.c:1160–1239` distinguish open states. O_RDWR open succeeds without waiting for a peer on Linux. O_RDONLY|O_NONBLOCK succeeds without a writer; O_WRONLY|O_NONBLOCK with no reader gives ENXIO. Blocking one-way opens rendezvous inside open and may return ERESTARTSYS on interruption. Conversion **after successful open** cannot fix an already blocked open. Adding O_NONBLOCK before open changes these semantics; a pre-open path stat is not the atomically opened object. This remains a separate open-continuation problem.
* `anon_pipe_read` (`pipe.c:269–405`, also used by FIFO) returns available positive bytes, EOF when no writers remain, or EAGAIN when physically nonblocking and empty with writers. It enters the interruptible wait only with no bytes and no nonblocking mode. Poll/ppoll readiness has no atomic reservation with that read; poll(2) also documents unaffected O_NONBLOCK and spurious-readiness considerations.

## Finite sequence and controls, all unexecuted

First implement/authenticate the managed record and status/probe seam for fresh successfully opened, non-exported FIFO descriptions. Then compose FIFO classification and existing polling with the real signal continuation. Keep S_IFIFO separate from `Pipe == internal` in Detcore; the adapter cannot certify a bind-mounted host peer as internal. Preserve the original named-FIFO timer oracle and 22 CPU/57 wall limits; moving raw124 to Unsupported is not a pass.

Required nearby controls: actual O_RDWR empty-read probe and EAGAIN; logical F_GETFL/F_SETFL/fdinfo agreement under forced physical flags; FIONBIO coherence; dup/fork/shared-table aliases versus two independent opens of one inode; same-fd same-inode replacement; CLOEXEC and surviving exec alias; close/reuse during an existing read; positive short scalar/vector bytes and EOF; caught signal before bytes versus after a real positive result. Backend controls must inspect physical flags directly, since guest F_GETFL intentionally hides them.

Preserve explicit negatives for imported stdin/SCM_RIGHTS, uncontrolled export, wrong/stale callback/description, O_PATH and inaccessible memory. A query refusal must leave bytes/status flags unchanged and must not be relabelled successful FIFO execution. Blocking O_RDONLY/O_WRONLY open, uncontrolled imports/exports, record/replay ownership and capacity/multiple-writer semantics remain visible follow-up requirements. No generic socket/regular-file admission, errno broadening, timeout widening, comparator change, skipped original case or descriptor-width change is proposed.

This report reuses the earlier measured FIFO diagnosis as historical evidence only; it binds current000c and relevant frozen v27 consumers independently. It contains no new runtime result and no whole-H1 approval. The current complete composed design review remains with the independent reviewers.
