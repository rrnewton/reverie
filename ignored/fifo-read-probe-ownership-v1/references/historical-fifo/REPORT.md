Smallest coherent correction to investigate next:
A. Separate FIFO kind from the assertion that both endpoints are container-owned. A distinct FdType::Fifo (or an equivalent fstat-backed discriminator on the existing shared open-file description) is sufficient; this does not require a general descriptor framework. Do not blindly change every S_IFIFO result to Pipe: helpers.rs:797–810 currently equates every Pipe with container-internal ownership. A named FIFO on a bind mount or an inherited descriptor can have a host peer. The path string and S_IFIFO alone do not prove membership. The actual fixture uses a fresh private /test tmpfs and one O_RDWR description, but this fixture fact is not an existing production ownership field.

B. After a successful ordinary FIFO open and before exposing it to the guest, in the existing sequential strict-run conversion mode, use the actual returned descriptor to read its kernel status flags and set flags|O_NONBLOCK through the backend. Register the original guest flags and mark physical=true only after the kernel reports successful conversion. Reuse the same fstat object for classification; if metadata virtualization is off, acquire the actual type rather than guessing from a path. Exclude O_PATH handles from conversion and retain their native EBADF behavior. maybe_set_nonblocking_fd merely edits metadata and is not a kernel conversion. Preserve access mode and other status bits. If setup fails after open has created a descriptor, do not invent a clean failed-open errno or leave an untracked descriptor: cleanup/typed terminal failure must retain the already performed effect and cleanup outcome.

C. Route FIFO read/readv and write/writev through the corresponding existing nonblocking machinery; update F_SETFL and FIONBIO’s physical-forcing predicate for this same mode. Keep F_GETFL’s existing logical result and FD_CLOEXEC’s per-slot behavior. Descriptor aliases already share Arc<Mutex<OpenFileDescription>> (fd.rs:77–126,298–325,534–543); dup clones the DetFd while fork copies slots with the same description (tool_local.rs:574–582,799–816). A per-descriptor Boolean would be wrong. Two separate opens of one FIFO share a kernel pipe object but not one status-flag OFD; do not merge their flags merely because st_dev/st_ino matches.

D. Preserve the actual stream results. Read/readv’s NonblockableSyscall implementation retries only EAGAIN/EWOULDBLOCK, returns EOF(0), and returns a positive short count immediately; it must replace Regular’s fill-the-buffer loop. Logically nonblocking calls stay one-shot and retain EAGAIN/short results. Physically nonblocking but logically blocking write/writev need the existing completion helpers, including prior-positive-count precedence, original OFD identity checks across retries and writev’s <=PIPE_BUF atomic path (helpers.rs:287–481,496–610). Reusing only the generic one-attempt write helper would leak artificial nonblocking short writes into blocking semantics. This is proposed code reuse, not newly established FIFO end-to-end correctness.

E. Keep record/replay provenance separate. In plain strict run, IOAction physical=true/logical=false already selects retry without requiring internal_fd=true. In record/replay, that predicate chooses between internal per-attempt recording and BlockingExternalIO; selecting it from FIFO type alone is unsound, while declaring every FIFO external can deadlock a guest-owned producer/consumer pair. A first finite setup correction can preserve current record/replay behavior and explicitly leave that gap unqualified, without adding a new flag, exemption or success claim. Full named-FIFO record/replay needs actual endpoint/ownership evidence and equivalent replay behavior, not an incidental type rename.

Boundaries which the small setup correction does not solve:

| State/path | Existing machinery and remaining obligation |
| --- | --- |
| Successful O_RDWR FIFO open | Linux permits this without a peer rendezvous. Post-open physical conversion can remove the measured blocking-read path. The timer still requires the separate continuation/restart corrections. This Linux behavior is not a portable POSIX guarantee. |
| Guest explicitly requests O_NONBLOCK | Preserve the original open/errno and visible flag. Reader-open with no writer and writer-open with no reader have different EOF/ENXIO behavior; do not convert those results into timer interruption. |
| Blocking O_RDONLY or O_WRONLY open | It may sleep inside the original backend open before a descriptor can be classified. Post-open fstat cannot fix this. Blindly adding O_NONBLOCK makes the reader open return too early or makes the writer return ENXIO. Existing generic retry handles fd operations, not an unpublished open transaction and reader/writer rendezvous. Holding a real read endpoint plus polling cannot by itself prove a writer rendezvoused if no data arrived. This needs its own object-bound open continuation/protocol, not a hidden O_RDWR keepalive that suppresses EOF/EPIPE. No such protocol is claimed here. |
| FIFO type discovered by pre-open pathname stat | A pathname is not the opened object; aliases, replacement and error precedence prevent treating that probe as an atomic open result. Authoritative classification belongs to the returned descriptor. |
| External/inherited FIFO | Forcing flags can affect aliases outside the guest if the actual OFD is shared; guest-opened fresh descriptions and inherited discovery require different provenance. SaBRe discovery already labels any S_IFIFO as Pipe (tool_local.rs:704–744); it does not establish generalized ownership. Do not expand that assumption. |
| Capacity and multiple writers | pipe2 pins a fresh pipe’s capacity, but an existing named FIFO may already contain data or have external users. Blind F_SETPIPE_SZ can fail EBUSY or mutate shared state. The measured one-byte read does not qualify capacity-sensitive deterministic writes or multiple-writer ordering. |
| Cancellation / close-and-reuse | Existing write helpers check original OpenFileId before later attempts. Generic read retry reuses a numeric fd and has no equivalent retained-OFD witness; concurrent close/reuse is an existing boundary to retain and test, not a newly proved capability. No returned positive result may be rolled back or replaced by EINTR. |

Polling, futex and signal/restart integration:
- Poll/ppoll already use zero-time probes in strict sequential mode (io.rs:402–434,977–1028); this does not turn a later unconverted read into a nonblocking operation. Keep temporary-mask and EINTR rules, including the existing non-null ppoll-mask limitation, unchanged. Poll cannot stand in for FIFO-open rendezvous.
- Precise futex is a separate scheduler-emulated path: threads.rs:1223–1255 selects Precise under strict defaults and explicitly does not inject the native wait. No futex redesign is implied by this FIFO finding.
- The retry helper returns ERESTARTSYS for an interrupted read/write before data (helpers.rs:953–955,1452–1541). Frozen Reverie v2 runtime.rs:3318–3331 leaves the callback restart loop only when has_eligible_pending_signal(); an already prepared caught signal is consumed later at3523 onward. Therefore a prepared-only selection must be accounted for at the restart decision or the callback can be re-entered before its reserved frame is applied. This is a source integration concern shared with the anonymous-pipe repair, not a new measured result or permission to discard the prepared selection.
- Retained primary signal(7), https://man7.org/linux/man-pages/man7/signal.7.html, lines580–661 of the bound text: interrupted slow-device read/readv/write/writev and blocking FIFO open restart under SA_RESTART; otherwise EINTR, and prior transferred bytes win. Poll/ppoll do not restart under SA_RESTART. Blocked/ignored signals must leave the wait intact; caught signals must run the actual handler exactly once, then apply the original restart decision. No private ERESTARTSYS may reach guest userspace. Local fifo/open man-page copies were absent; no new network fetch was performed, so detailed open-rendezvous claims remain reference/measurement obligations before implementation approval.
