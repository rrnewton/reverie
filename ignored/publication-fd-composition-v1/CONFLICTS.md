The publisher's new private module is wholly byte-identical. Its registration, current-image refresh, failure latch, pending/readiness serialization, and restrictions are not widened. The executor's fork, thread, frame, signal-consumer and retirement control flow is preserved except for the FD marker/retired-file composition described above.

Readiness limitation retained for later correction: executor.rs:7888 collects signal readiness then looks up carriers in `state.files`; outside-execute callers include discard of ignored signals (around 3910) and delivery/return selection through the locked consumer helpers. In contrast, process_signal_publication.rs:246 resolves the current weak image and holds the authoritative FileTableState through pending commit and carrier update. After a sibling closes/reuses a slot, the installed snapshot can still name an old carrier until the next install. An entry marker alone neither detects nor repairs that outside-execute lookup.

A focused follow-up must construct this exact stale-snapshot boundary with authoritative close/reuse, invoke a real outside-execute pending-removal/readiness path before the stale executor executes another syscall, and check the current carrier's readiness, retained old description, pending contents and removal receipt. It must preserve the existing signalfd/thread/fork admission refusals; a test requiring future admitted membership must be labeled as an internal transition control, not present production support. The eventual fix must obtain current carriers under the file-table-before-transaction order (or an equivalently validated binding) without a reverse-lock acquisition. This report is source evidence and a proposed control, not execution or activation approval.

The lock-order documentation is not changed. In actual publish(), short registry/image lookup guards are released before the main acquisition; registry.failure is acquired after file table/transaction/lifecycle and before process signals, and remains held during readiness I/O after process/lifecycle are released. It is not an innermost guard. No owner failure notification is added by this composition.
