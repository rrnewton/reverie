# Bounded pselect6 zero-time design audit

Background: pselect6 asks which descriptors are ready, using three input/output bitmaps and an optional timeout and temporary signal mask. Hermit’s Detcore layer owns deterministic retry turns and virtual deadlines; Reverie’s KVM executor must supply the instantaneous syscall probe underneath that layer. The disabled `c-programs/poll-readiness` verification cell runs a single process through fixed pipe states and requires all eight checks, including libc select calls observed by the parent to reach pselect6.

This is source-only design preparation for https://github.com/rrnewton/reverie/issues/620, not an implementation approval, runtime result, or determinism qualification. Repository/index/ref state was not changed. No build, probe, fetch, or test ran. Network reads retrieved only Linux primary source through `with-proxy /home/newton/bin/gh api`.

## Required execution order

1. Copy the complete outer mask wrapper, if nonnull. Both words must be readable before timeout inspection. Keep the existing split-wrapper fault check.
2. Read the timespec if supplied, then validate signed seconds and `0 <= tv_nsec < 1_000_000_000`. Snapshot whether it was exactly zero; NULL means an unsupported infinite wait, not zero.
3. If the inner mask pointer is nonnull, validate its size against the eight-byte kernel mask and read those bytes. Keep such valid calls unsupported without changing the guest or host mask. If the inner pointer is NULL, **ignore any size**, including `u64::MAX`.
4. Decode `nfds` with `args[0] as libc::c_int`; the kernel consumes its signed low 32 bits. A negative low word returns EINVAL here, after the prior checks. Preserve ENOSYS for values above 64 before fd-set access. This is an explicitly unsupported boundary, not a claim Linux returns ENOSYS.
5. For `nfds == 0`, touch no fd-set byte regardless of pointer values. For 1 through 64, snapshot exactly eight bytes for each nonnull input, in read/write/except order. Read all inputs before any output, including overlapping pointers.
6. After these existing preflight checks, retain ENOSYS for NULL/nonzero timeouts and nonnull inner masks. Only the eligible zero-time unmasked branch validates selected descriptors and measures readiness. Validate every selected guest fd below nfds before output; one absent descriptor requires EBADF and no output even when another is ready. Ignore input bits above nfds and clear them in the full returned word.
7. Translate through the guest fd table, sample readiness once with host `poll(..., 0)` on host-owned storage, and map back to guest bits. Preserve the virtual-signalfd special case: its private eventfd carrier must not leak its always-writable state. Count every ready set bit; one descriptor ready in two sets returns two.
8. Before output, if readiness is zero and the guest has an eligible pending signal, return ENOSYS with every input/output byte and signal state unchanged. Use the exact current-generation, blocked-mask predicate described below. Positive readiness takes precedence. This is an explicit unsupported signal boundary, not a fabricated zero or a synthetic EINTR.
9. Copy result words with `memory.user().copy_to_user`, in read/write/except order. On the first fault, return EFAULT, preserve any already-copied prefix/earlier set, and do not attempt later sets. Keep all remaining bytes unchanged. Never prevalidate all output destinations and turn this into an all-or-none transaction.
10. **Do not write the timeout at all**, even on failure: Linux’s initially zero timeout takes the no-update path. A readable read-only zero timeout is valid. Do not merely rewrite sixteen zero bytes.

These stages follow [Linux pselect wrapper and do_pselect](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/fs/select.c#L728), [null mask handling](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/kernel/signal.c#L3272), [core fd-set ordering and limit clamp](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/fs/select.c#L621), and [zero-time timeout preservation](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/fs/select.c#L295). Linux’s embedded fd table has `NR_OPEN_DEFAULT = BITS_PER_LONG` at [fdtable.h](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/include/linux/fdtable.h#L24); this justifies the existing one-word lower-bound strategy without guessing the guest’s historical grown table capacity.

## What can and cannot be reused

The dispatch currently calls only [pselect6_validation_preflight](https://github.com/rrnewton/reverie/blob/3a196cfb9dbb775900a1acb02890b8ca10aedd0c/reverie-kvm/src/executor.rs#L637); its [validation stages](https://github.com/rrnewton/reverie/blob/3a196cfb9dbb775900a1acb02890b8ca10aedd0c/reverie-kvm/src/executor.rs#L10198) are the appropriate starting point. Change it into a state-aware pselect handler, keep input snapshots instead of discarding them, and add the bounded readiness/copyout tail. Fixed `[u64; 3]` input/output words suffice; at most 64 translated poll entries are needed. A helper extracted from select must accept already-validated snapshots and perform **only** readiness translation; avoid a broad select refactor in this repair.

Do not call [select](https://github.com/rrnewton/reverie/blob/3a196cfb9dbb775900a1acb02890b8ca10aedd0c/reverie-kvm/src/executor.rs#L10264) wholesale:

- It uses full-width `try_from(args[0])`, unlike raw low-word Linux pselect6.
- It guesses fd-set size up to GUEST_NOFILE_LIMIT rather than keeping the live-fd-table boundary.
- It reads fd sets before timeout validation and uses timeval microseconds.
- It copies outputs with `user().write`, which checks readability rather than writability and rejects partial effects; then it rewrites the timeval and can turn a timeout copyout fault into EFAULT.

Reuse descriptor lookup, bit membership, and the signalfd carrier distinction, but faithfully reproduce Linux’s readiness masks rather than copying the reduced masks blindly. [Linux POLLIN_SET/POLLOUT_SET/POLLEX_SET](https://github.com/torvalds/linux/blob/7d0a66e4bb9081d75c82ec4957c50034cb0ea449/fs/select.c#L459) includes normal/band bits and POLLNVAL: request relevant normal/band events through poll and recognize the full corresponding readiness masks. An absent **guest** fd is already EBADF before polling; do not conflate it with POLLNVAL returned for an otherwise open host-backed object. A native O_PATH control is useful for that distinction. The existing select code at lines 10315–10354 requests only IN/OUT/PRI and has narrower result masks.

[copy_to_user](https://github.com/rrnewton/reverie/blob/3a196cfb9dbb775900a1acb02890b8ca10aedd0c/reverie-kvm/src/memory.rs#L2224) selects partial copying under entry admission; [write_user_prefix_admitted](https://github.com/rrnewton/reverie/blob/3a196cfb9dbb775900a1acb02890b8ca10aedd0c/reverie-kvm/src/memory.rs#L2330) checks writable page state and copies the valid prefix under the mapping transaction. Use it rather than raw writes, a host pointer into guest backing, or a new alias mapping. Preserve the existing terminal-memory admission behavior.

## Detcore behavior and limits

At the exact consumer, [handle_pselect6](https://github.com/rrnewton/hermit/blob/5d8cf0cf1d9a087503bfe8b1df368df72b9c44d7/detcore/src/syscalls/io.rs#L456) already injects explicit zero-time calls directly at lines 525–527. For nonzero/infinite unmasked guest calls within the one-word boundary, [handle_internal_pselect6](https://github.com/rrnewton/hermit/blob/5d8cf0cf1d9a087503bfe8b1df368df72b9c44d7/detcore/src/syscalls/io.rs#L572) takes `InternalIOPolling` scheduler turns, writes a zero-timespec scratch probe, restores original input sets on each attempt, injects it, and compares deterministic virtual time against its existing deadline. Returning real zero/readiness results from the backend makes that existing loop usable; it changes backend capability, **not its scheduling policy or deadline calculation**. Do not claim this backend patch implements raw blocking timeouts.

A genuine inner temporary mask remains in each Detcore probe and must still reach the KVM unsupported boundary. The malformed-timeout wrapper-validation injection (lines 500–511) must continue returning EINVAL, never success. Current record/replay also has a distinct `record_or_replay_select_family` path at lines 439–450; zero-time calls request a turn and use the recording machinery. The old shared-checkout comment that no pselect event is modeled is no longer authoritative. This audit did not qualify KVM recording/replay.

**Required signal boundary, now settled by source trace:** Linux core_sys_select lines 681–684 checks pending signals only when readiness is zero, before any fd-set output. Existing KVM return-boundary delivery does **not** make it safe to return a fabricated zero. `execute_checked_inner` (executor.rs:6404–6468) reaches scalar dispatch without pending-signal preflight. The direct VM stages the ordinary syscall result before delivery (vm.rs:4945–4952, then 4267–4305). The Tool runtime constructs/stages returned registers and the frame result (runtime.rs:5835–5847), then filters and delivers pending signals (5960–6017). An ordinary successful zero has no restart classification; it remains zero in the signal frame. The runtime’s ERESTARTSYS classification path at 5687–5713 is separate and does not synthesize the kernel’s pselect ERESTARTNOHAND behavior for zero.

Therefore the bounded implementation needs this explicit admission branch **after input copying, fd existence checks, and readiness sampling but before any output**:

```text
if ready_count == 0 && has_eligible_pending_signal(state):
    return -ENOSYS  // this pending-signal completion is still unsupported
```

Factor/reuse the exact read-only predicate currently in `ElfExecutor::has_eligible_pending_signal` (executor.rs:5703–5715): hold the process-signals lock, then the thread-signals lock; use the process’s `pending_generations` and the thread’s current blocked mask; ask whether either the thread queue or shared queue has an eligible signal. `StandardPendingSignals::any_eligible` (signal.rs:344–351) only reads BTreeMap keys and checks the current generation; it calls no removal or selection operation. Both locks must be dropped before guest-memory copyout. Making the existing method delegate to a narrowly shared state predicate would avoid maintaining a second definition.

This check must **not** depend on having a delivery permit. In controlled mode, `take_pending_signal_for_delivery` intentionally refuses to dequeue without a permit (executor.rs:5683–5687), and runtime.rs:4635–4649 acquires authorization only at the later signal boundary. An eligible event can therefore exist without such a permit. Conversely, blocked or stale-generation events must not refuse an otherwise supported zero result. Do not dequeue an event, ask for a permit, install a mask, append a dequeue/publication effect, inspect only the thread queue, or mutate scheduling state. The read-only query preserves queue order, retained siginfo, generations, and masks exactly; subsequent normal return-boundary delivery stays owned by the existing protocol.

Positive readiness must still return its count and perform ordinary output even with eligible pending state: that is Linux’s precedence. Existing input/descriptor failures must also remain earlier than this guard. A signal admitted after the read-only zero-result decision is a later event, as it can be after Linux’s pending check but before its copyout; the helper need not retain signal locks across guest memory writes.

This explicitly narrows support to signal-free zero-readiness completions plus ready completions. ENOSYS for the excluded pending case is intentionally not a Linux-parity claim. Do not synthesize EINTR or raw ERESTARTNOHAND: that would require reviewing handler/restart/ignored-signal composition outside this increment. Host poll’s signal state is not the virtual guest’s pending state either; never translate a host-interrupted poll into successful zero. A fail-closed refusal remains preferable to inferring virtual interruption from host timing. This is a bounded source trace and admission recommendation, not a full scheduler-soundness approval.

## Focused controls and the unchanged cell

Keep the original preflight errno/ordering cases; do not replace the whole test with success-only checks. Only the newly supported valid cases change their expected outcome. In particular, the existing exactly-64 test’s final word previously held `SIGNAL_MASK` (0x200) from the split-wrapper setup: it is **not** an empty set. Explicitly initialize it for a zero-readiness positive test and separately require EBADF for that selected absent fd; do not relabel the unchanged bytes as a zero set.

Use raw SYS_pselect6 native controls (not libc select, whose syscall lowering varies) against the same prearranged file state:

- Empty pipe versus buffered pipe versus closed-writer EOF; a writable endpoint; one socket selected in both read and write sets; exact count and exact returned words, including ignored high bits.
- `nfds=0` with inaccessible set pointers; 1 and 64 with the eight-byte bitmap at a page boundary; a dirty high 32-bit nfds with a valid low word; a negative low word. Keep nfds=65 ENOSYS as an explicit unchanged unsupported check, without claiming native parity there.
- All existing wrapper/timeout/inner-size/fd-set precedence checks, plus NULL inner pointer with absurd size. All refused unsupported calls retain guest bytes, guest blocked mask, and descriptor table.
- Read-only fd-set output, an eight-byte output crossing writable into read-only memory, a fault in the second/third output after earlier successful copies, and overlapping output pointers. Compare full native and guest snapshots, without a tolerance or accepting either prefix behavior. Initial input remains readable for copy-in; preserve kernel-observed partial-copy effects.
- A readable read-only zero timespec and timeout/output aliasing controls establish the omitted timeout writeback. Exact native full-buffer equality must remain strict.
- An absent selected guest fd must beat any output fault and leave every result destination unchanged. An out-of-range bit above nfds must be ignored.

For the signal guard, add source-level executor controls with both thread-directed and process-shared current eligible events: zero readiness returns ENOSYS before output; snapshot and compare both pending queues, generations, blocked mask, and relevant signal-effect state before/after. A blocked event and a stale-generation event must not trigger refusal. A ready descriptor plus an eligible event must still return readiness and leave the event untouched. Include controlled mode without a delivery permit so an accidental permit-based predicate cannot pass. Also retain EFAULT/EBADF precedence in the presence of pending state. These controls concern an explicitly unsupported branch; do not falsely compare its ENOSYS to native Linux interruption as if they were equal.

A minimal product mutant is to retain validation but restore ENOSYS immediately before the newly supported readiness tail. The positive raw pselect tests and original official cell must fail under it and pass after restoration. A copier mutant (`copy_to_user` back to `user().write`) is an especially direct extra check for the protected/partial-output regressions; it must not be counted as production evidence.

The [original guest](https://github.com/rrnewton/hermit/blob/5d8cf0cf1d9a087503bfe8b1df368df72b9c44d7/tests/c/poll_readiness.c#L108) must still require `poll_readiness ok=8` and exit failure unless all eight checks pass (lines 159–167). Its stdout/exit comparison, timeouts, attempts, and strict verification policy must stay unchanged. The exact [disabled verify row](https://github.com/rrnewton/hermit/blob/5d8cf0cf1d9a087503bfe8b1df368df72b9c44d7/tests/e2e/manifests/c-programs.yaml#L14796) still excludes KVM with a select/pselect6 reason at line 14820. Enable only after the unchanged official cell qualifies with the new producer; do not extend the replay/chaos rows from that evidence.

## Goalpost-moving assessment

No source, assertion, timeout, comparator, manifest row, or gate was changed during this audit. The proposed ENOSYS-to-success changes concern exactly the newly implemented domain, with corresponding native controls; all earlier validation and all other explicit unsupported boundaries remain. Keep the zero-time timeout omission because Linux requires it, not to avoid a failing pointer check. Keep the eight-check manifest oracle, exact errno and byte comparisons, and negative controls. The proposal is not an approval or a claim that any test has passed.
