Public direct/ELF owner panic control: authored source, unexecuted

The only authored product changes are the new vm/public_tool_panic_tests.rs and include!("vm/public_tool_panic_tests.rs") at the end of the existing vm::tests module immediately before terminal_tests. No existing test body or implementation was edited. The included file defines a private nested public_tool_panic_tests module using the existing minimal_test_elf fixture.

One declaration, vm::tests::public_tool_panic_tests::public_direct_and_elf_owners_finish_pending_consumers_before_resuming_panic, runs direct run_with_tool and run_static_elf_with_tool_completion serially. Each uses a real 16 MiB KvmBackend and fails setup if KVM is unavailable. Direct mode installs the syscall transport; ELF mode installs the existing minimal HLT image. The actual handle_thread_start RPC resumes a unique original Send-only Box before the first guest-entry loop. The direct syscall executor itself panics if guest execution nevertheless continues.

The actual on_exit_thread consumes the exact initialized u64 thread state, verifies failure has already been reported, registers a oneshot wait and becomes Pending. The test manually polls the caught public future once and requires Pending, exact Start/ThreadConsumed events, no process/global destruction, both payload drop counts zero, and zero recorded vCPU exits. Releasing the oneshot resumes the thread consumer with a second exact original Box. The process consumer must still execute and return typed ENOSPC. GlobalState destruction records the final event.

After catching the public run, the control requires the exact first Box allocation, exact event sequence through process consumption then GlobalState Drop, no pending backend payloads, cleared tool_failure, and one completed backend record. Its diagnostic tree must have GuestWorkerPanic primary, exactly two GuestWorkerPanic leaves and exactly one typed Reverie Errno ENOSPC leaf. The second exact Box must remain in that record; _run_failure must be present precisely for ELF mode. Dropping the first Box then the backend must increment the two separate destruction counts from [0,0] to [1,0] to [1,1], with one GlobalState Drop overall. The test-private static observation slot is exclusive to this declaration and cleared by a guard.

The control exercises public callback/owner cleanup routing and real setup ioctls when run. Its source routes failure during thread start before KVM_RUN, and the exit collector additionally requires zero recorded vCPU exits. Exit counts alone are not an ioctl invocation counter; no independent syscall trace or executed measurement is claimed. The test does not cover unexpected setup/report-hook/final destructor panics, failed host spawn, fork/thread workers, runtime-error-plus-callback-destructor loss, Hermit/Detcore, or parity. Marker payload destructors count but do not themselves panic.

No compilation, formatter, tests, product payload, network, external model, or SCM operation was performed. The source is released for root formatting and bounded qualification. Input hashes are observations of concurrent root-owned composition, not an exact complete candidate claim. No assertion/tolerance/comparator was weakened, no skip or exemption was added, no prior failure was relabelled, and no existing check was removed.
