Consuming exit-hook panic handling, private source preparation

The free production helper is now notify_tool_exit_with_panics with the original arguments plus a final &ToolPanics. It catches each actual on_exit_thread/on_exit_process future separately with catch_owned_future. It maps only a returned Reverie error, retaining a returned result even when the future's destructor panics, then calls ToolPanics::finish with the existing exact thread exit hook or process exit hook phase. Existing publication runs after that typed completion. A thread-hook error or caught panic therefore does not bypass the process hook.

Each process hook poll checks that the thread hook was destroyed and, on failure, its exact phase was already published. Hook construction, poll and destruction counts are exact; no timeout is used as an expected success result.
