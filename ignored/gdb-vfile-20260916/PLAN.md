GNU GDB Host-I/O protocol (retained URL/body/fetch result alongside this plan) requires exact operation-name comparison through the second colon and an empty response for an unrecognized operation. Current parser treats vFile:lstat as malformed, and the real relay closes its command channel and stream. Captured CLI2 ended its remote exchange at that request; GDB then reported an internal crash before the intended Python injection. This repair addresses the observed unsupported-packet disconnection, not a blanket claim about all GDB crash paths.

Keep all eight existing supported vFile parser branches intact. Only an otherwise unknown nonempty operation with both name delimiters becomes Unsupported; Session writes no payload, using its existing response checksum/ACK framing. Unknown parameters remain opaque. Missing delimiters and all existing known malformed arguments remain errors. There is no lstat filesystem access or F-success reply.

Add parser controls for whole-name matching, unknown operations, missing separators and invalid arguments of all supported operations. Add a real duplex-stream regression through GdbServerImpl::run, Packet parsing and Session::run: exact empty unsupported response followed by an exact OK response to the supported ! request on the same open connection. Its initial stopped-inferior message is typed test data; no guest, ptrace, filesystem request, or external debugger runs. A separate connection control preserves closure for malformed supported operations.
