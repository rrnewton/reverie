The shutdown wait has a separate concrete source cause. Hermit prepare_backend_config at hermit-cli/src/lib.rs:2334 enables cancel_killed_thread_rpcs only for SaBRe and DBT. KVM therefore retains false. The field's documented purpose at detcore-model/src/config.rs:119 is explicit scheduler response for logically killed tasks when the backend cannot rely on kernel-driven ptrace teardown. Scheduler logically_kill_thread at scheduler.rs:1830 records a permanent killed-task marker only when enabled; at 1861–1865 it fills the response of an already-pending request only under that same flag. With the observed false setting it removes the worker from next_turns while the cloned response in tool_global.rs:1362 is still awaited. This matches the trace's removed worker and final waiting response.

KVM cannot rescue that particular wait through its present host cancellation mechanism. runtime.rs:1019–1064 drive_handler polls the Tool future and services its own tail-injection signals and child-start gates; it has no group-cancellation wake/check. vm.rs:294–313 and 404–420 set the cancellation bit and send SIGURG, while vm.rs:2805–2809 joins worker OS threads on root cancellation. A SIGURG used to interrupt host/KVM syscalls does not populate the asynchronous scheduler IVar. The outer runtime group-exit checks at 2085 are not reached until the suspended Tool handler completes.

The existing enabled-flag path is relevant but not yet qualified for KVM. Scheduler cancellation wakes an already-pending request; tool_global.rs:1363–1378 converts the logically removed task to ThreadExited before returning an operation-specific response. send_and_update_time at 2548–2557 tail-injects Exit on that terminal response. Ordinary KVM syscall context accepts the injection; complete_injection at runtime.rs:479–487 reports its pending exit as nonreturning, drive_handler observes the tail signal, and the outer exit path clears child TID and calls the ordinary exactly-once thread exit hook. A narrow experiment enabling cancel_killed_thread_rpcs for KVM is therefore source-motivated, but needs actual stopped-worker/group-exit evidence before publication. It must also inspect lifecycle and signal-hook contexts where KVM intentionally restricts tail injection. This note does not approve a blanket flag change or claim general KVM cancellation correctness.

Required evidence for subsequent authorized work: keep the current ENOTTY/error-exit reproducer and unchanged timeout as failed; separately demonstrate bounded group teardown without allowing a logically removed worker to execute another guest operation; preserve root/worker exit and consuming Tool hooks, clear-child-TID behavior, and unaffected live-thread execution. For the FIONREAD prerequisite, retain exact return/output bytes, copyout permissions, invalid descriptor/error ordering, pipe contents and non-consumption, with native controls and the older synthetic-proc/SCM_RIGHTS failure clearly separated.
