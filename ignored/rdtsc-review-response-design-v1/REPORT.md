# Timestamp review response design, after V4 qualification

This is author analysis and a source-only correction plan, not an independent verdict. V4's 40 phases and 31 declarations passed, but that does not discharge the completed Claude V3 CHANGES REQUESTED report. Its full report and root follow-up facts were read after V4 finished and froze. The active native reviewer received no Claude findings. Live source, SCM, V4 source/results and the existing same-run composition remain unchanged.

## F1: a real terminal injection needs three changes

Confirmed source defect, no measured F1 failure yet. H39ac detcore/src/lib.rs:1337 invokes pre_handler_hook, charges add_rdtsc and reads guest_clock_time, then post_handler_hook. The review overstates one detail: the prehook's resource_request is conditional on an expired timeslice (lib.rs:601–620), not unconditionally performed on every timestamp. The virtualized clock observation itself still uses the normal send_and_update_time transport, and any applicable resource request can also return ThreadExited. tool_global.rs:2718–2740 converts that response to tail_inject(Exit::default()) before an operation-specific caller resumes. recv_request_resources:1513–1549 turns an already parked response into terminal cancellation and logically removes siblings before permitting an exit_group to physically proceed. This establishes the actual normal caller; no Detcore change is proposed.

The current KVM path refuses first at ProcessExecutionContext::tail_injection_allowed (runtime.rs:445), again at ordinary_injection_allowed (455), and again through StaticElfSyscallExecutor::execute's signal_injection_allowed (parked_signal_runtime.rs:4–27; runtime.rs:570). Even if both admission gates were opened, the timestamp HLT branch rejects every TailInjected outcome (runtime.rs:3226). Changing only one predicate cannot repair the path.

Proposed correction, only for the Timestamp context:

1. Make the private GuestSyscallExecutor tail-admission method request-aware. Timestamp accepts only exact SYS_exit or SYS_exit_group. All returning tails, fork/vfork/clone/clone3, exec/execveat and signal-based nonreturning injections stay refused before execution. Existing contexts retain their prior predicate and behavior. SyscallInfo is Copy, so deriving the six-word request does not consume a different call before the existing inject path.
2. Permit only those same explicit terminal syscalls through Timestamp ordinary-injection validation. This is necessary because tail_inject delegates to inject and the concrete executor rechecks. An ordinary inject(Exit) is also terminal under the existing Guest API; it does not return a scalar success. ThreadEntrySignal remains unchanged. SignalGuard, prepared-frame, pending-child-start and effect notification guards remain authoritative and unchanged.
3. Admit only HandlerOutcome::TailInjected with successful result, image_replaced=false and process_exited=true in the timestamp driver. Hide scratch through the existing error path, consume the actual pending executor.take_exit() or fail an invariant if absent, publish group status through request_guest_thread_group_exit for a real group exit, and return that ToolProcessExit into unchanged finish_tool_process. Never resume/write the timestamp frame or invent a timestamp value. Other tail outcomes remain typed failures. No arbitrary refused injection becomes ThreadCancelled.

Why this reuses the actual terminal mechanism: execute_basic_syscall_with_output (executor.rs:358) produces SyscallAction::Exit; ElfExecutor::execute (4408) stores the real status and group flag. Exit has no ProcessAction, so complete_injection (runtime.rs:827–838) sees has_pending_exit and produces DoesNotReturn{process_exited:true}; KvmGuest::inject (1244–1260) emits the private TailInjected signal and never resumes the hook. take_exit (executor.rs:4234) retires the exact generation through TaskLifecycleTable::exit (elf.rs:252–279). First group status wins and final process status is selected only after live own tasks leave (elf.rs:282–301). Existing finish_tool_process retires/releases the task, clear-TID, files/stdin, joins/cancels workers, then consuming hooks and child cleanup, preserving failures (runtime.rs:2156–2246, 2024–2137). Cleanup or scratch errors remain errors; they are not flattened into a successful cancellation.

Planned actual controls, without sleeps or predicate-only substitutes:

- A real static timestamp Tool tail-injects Exit(23), then ExitGroup(29) in a separate mode. Completion must preserve the exact status, one timestamp callback, exactly one thread/process exit hook, and no user instruction/callback continuation after the nonreturning injection.
- Deterministic sibling witness: a Tool-owned worker reaches RDTSC and parks in an actual global RPC. The leader reaches an actual guest exit_group(17) callback; its RPC waits for the worker's timestamp entry, releases that worker with the terminal response, and waits for the worker's consuming on_exit_thread acknowledgment. The worker tail-injects Exit(0); only after its hook does the leader physically tail-inject its original ExitGroup(17). Require final 17, both exact task exits, one process hook, one worker timestamp, no resumed timestamp or root continuation, and no run failure. This models Hermit's logical cancellation before physical group exit. Using a worker for the cancelled callback avoids the existing leader-natural-exit/join cycle. Do not claim this proves every race ordering; the exact deterministic handshake is the control.
- Preserve fork/exec/refused returning-tail effects with actual timestamp hooks: a returning write/getpid tail must refuse before executing; fork/exec remain ENOSYS with no child/image effect. Existing ClockTimestampTool returning/refused-injection control remains unchanged. A real failing consuming exit hook must retain the cleanup error rather than disappear behind the successful terminal syscall.

## F2: establish public non-ELF loop ownership locally

Confirmed missing local invariant, not a measured public-loop failure. runtime.rs:2332 starts run_with_tool with track_clock and no interception-state reset, while vm.rs:3200/3564 explicitly disarm the two other non-consuming loops. The public path still treats HLT as its existing completion protocol and has no timestamp consumer. Add set_rdtsc_interception(false)? at entry. Do not add timestamp emulation, a stepping engine or a new public refusal.

An internal actual KVM control will seed the real backend's TSD/intercept state using the production setter, install a public vmcall program, run run_with_tool, and verify the actual CR4 bit and private interception ownership are cleared, along with the original syscall/output/lifecycle contract. Test both initially false and true. The control must not pretend public CPL0 execution proves CPL3 trapping; it proves the public loop resets its own state while executing its real transport. Keep existing public vmcall tests unchanged and selected. No public API is needed.

## F3: policy investigation stays separate

Do not change the fixed CPUID table speculatively. H39ac detcore/src/cpuid.rs:84 advertises EDX=0x20100800 (bit 27 clear). Current Reverie ptrace nevertheless recognizes unconditional RDTSCP (task.rs:1557,2653) and calls the Tool, writing AUX=retval.aux.unwrap_or(0) (2041–2064). KVM's fixed table also clears bit 27; its subscribed recovery handles RDTSCP #UD deliberately (vm.rs:2646–2700). Therefore setting bit 27 only for KVM would create a concrete cross-backend CPUID difference, while dropping subscribed RDTSCP would remove the existing ptrace instruction-dispatch behavior from this port. Neither is a local consistency fix without an explicit product-policy decision.

Proposed response to evaluate with evidence: preserve the shared fixed advertised CPU profile and the existing Tool timestamp-interposition contract, documenting that subscription virtualizes unconditional RDTSCP independently of that advertised baseline. A zero advertised bit is not to be presented as a new promise that an instrumented Tool cannot emulate the instruction. This is a deliberate compatibility proposal, not a proved architectural theorem or a cleared review finding. Unsubscribed deterministic KVM RDTSCP remains a genuine #UD; host-supported KVM follows the host table. Changing the shared profile across backends would be a separate policy change, not part of the F1/F2 correction.

Prepare a separately bounded same-run witness using one retained program and current actual Hermit binary for ptrace and KVM, plus a separately identified native run. It must retain the full CPUID 0x80000001 registers, an unconditional RDTSCP result (both TSC words and AUX), exact status/output and INFO records, without filtering or adjusting the normal comparator. Native raw TSC/AUX and advertised bit are hardware evidence, not values expected to equal virtual clocks. If current ptrace or KVM does not reach the instruction, preserve the real failure and qualify no policy conclusion. Existing native architecture probes did test RDTSCP on this host but did not run this exact shared-policy witness. No witness was executed in this author task.
