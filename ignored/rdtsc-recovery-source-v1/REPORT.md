The three retained historical timestamp commits are 841107ac, d65ab382 and 96306604. Their 903 patch lines are copied under `evidence/`. Heap-arena and endpoint-identity tail changes are excluded. All six historical static test bodies remain byte-identical; existing current static tests/helpers remain byte-identical after removing only two added imports. The historical decoder control is adapted to the current private decoder and strengthened with lazy fetch and fault-priority assertions.

The active Tool loop sets CR4.TSD from its actual timestamp subscription before any guest entry. Every actual Tool thread/fork consumer admits its own subscription. A newly constructed vCPU starts without timestamp trapping; the tool-less loop explicitly clears it, including Host-owned workers. Exec resets the guest image on the same vCPU while retaining the actual consumer's TSD bit. This avoids propagating an armed state into a worker with no callback consumer. New Host-worker and retained thread/fork/exec controls exercise those contracts.

Only subscribed CPL3 timestamp #GP(0), or genuine RDTSCP #UD under the deterministic CPUID profile, reaches `handle_rdtsc_event`. The unsubscribed guard precedes fault-frame access. Other exception vectors/opcodes, LOCK and instructions longer than 15 bytes remain ordinary guest faults. The private decoder recognizes legal ignored legacy and REX prefixes and fetches no byte beyond a completed instruction. It follows the active four-level page tables and checks user/present/NX permissions at every level, rather than treating supervisor RAM accessibility as executable permission. The actual KVM page-boundary control distinguishes a two-byte instruction ending before an NX page from a three-byte instruction requiring that page. This is not a repair or proof of every existing mmap/mprotect permission model or unsupported high-address mode.

The callback uses the current KvmGuest, current process/thread state, global RPC, failure subscription, handler driver and consuming process supervision. Scratch visibility is restored on success and error. Nonreturning process actions, tail injection, and signal actions needing a syscall return frame refuse before mutation in this private timestamp context. Ordinary returning injections remain available; the new clock control exercises actual getpid plus refused fork/exit_group and a real awaited RPC. No public API is added.

Completion restores the saved user GPRs, stack, selectors and flags, changes only architectural timestamp outputs (zero-extended EAX/EDX and RDTSCP ECX), and advances RIP by the decoded length. Intentional returning FS/GS-base injection is retained. Successful retirement clears the fault-added RF bit. A saved TF produces the existing typed #DB terminal boundary at the next timestamp RIP before another guest instruction runs. This preserves the backend's existing unsupported guest debug-exception behavior; it does not add guest SIGTRAP delivery. New actual guest assertions cover prefix lengths, full output registers, unaffected RCX for RDTSC, stack/ordinary flags and the single-step boundary.

The real branch clock source is unchanged. `CountedVcpu::run` finishes its guest-only PMU interval before exposing the timestamp exit. Callback/RPC/injected host work does not open another interval. The retained prepared Hermit callback performs its real prehook, one `add_rdtsc`, shared-clock RPC and real posthook; those bytes are context from the unlanded timer slot, not a current-main qualification. ## Scope and remaining gap

The public `run_with_tool` vmcall path normally executes CPL0 real-mode snippets; CR4.TSD does not intercept CPL0 RDTSC. That path remains byte-identical. Its timestamp interception gap is explicit and is not disguised as a refusal, synthetic event, new API or stepping engine. Existing public vmcall/default-Tool neighbors are selected to guard preservation, not to claim timestamp coverage. The current 74-cell signature uses the CPL3 ELF path. No whole-backend, whole-timer, generic signal-delivery or scheduler-completion claim follows from this port.

Prefix acceptance, page fault priority, host CPUID behavior, RF/TF completion, current callback injection cleanup and consumer-local lifecycle admission all require the focused qualification and independent source review.
