A supported source-level sequence for the race is: the leader starts worker W; W registers an unstarted nested Tool thread C and remains in its callback; the leader exits naturally and takes W and C in its join batch; W's callback fails while C's gate is still pending. The leader may be joining W while W discards C. This is derived from the real ownership code, not a newly measured interleaving.

W publishes its real cause before cancelling pending gates (`vm.rs:2014–2016`). Cancellation captures C's exact registered gate before sending `CancelAfterFailure` (line 1881). If discard owns C, it physically joins C and drops only bare `RunAborted` on the fatal path (lines 1944–1964). If the leader already owns C, discard returns `Ok(false)` (line 493); the captured registration lets W's cleanup finish. The leader then caches C's returned marker and `teardown_result` adds its worker TID (lines 527–589).

This ordering does not add a join cycle: all pending gates are cancelled before discard joins, the handle-taking lock is released before physical joins, and the registered fallback avoids requiring W to take a handle already owned by the leader. W does not join its own group (`vm.rs:3290`, `3325`). When W returns, the leader can join C and drain later batches. This does not promise completion if a consuming Tool hook itself never returns.

For the ordinary public returned result, the real cause is retained before the cancellation marker exists. `RunFailure::publish` does not select a derived `RunAborted` as a real cause (`failure.rs:77`). After owned joins and GlobalState ownership recovery, public completion calls `failure.complete` (`runtime.rs:2197`; `failure.rs:120`). `Error::complete_after_failure` traverses worker, cleanup and shared aggregates, removes derived marker nodes and preserves genuine other causes (`error.rs:315–400`). Thus the cached marker does not become a separate cause in that final result. The intermediate results remain unequal.
