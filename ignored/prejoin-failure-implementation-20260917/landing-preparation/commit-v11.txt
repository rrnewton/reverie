Publish fatal KVM Tool failures before joining children

[hermit2, degraded-unresolved, gpt-6-astra, devbig014, role=impl]

Plain Language Summary and Project Impact

A failed KVM worker could leave a Tool RPC and a joining owner waiting on
one another. Publish the first typed failure before worker retirement and
child joins, wake every subscribed handler, and consume constructed child
state without starting the guest. This advances the production KVM backend
by making fatal runtime cleanup complete while preserving ordinary syscall
errors, cancellation, successful exit status and lifecycle hook order.

Task: kvm-lane-to-full-determinism-and-parity

Keep the first typed cause paired with its process/thread identity, retain
secondary cleanup errors separately, and return GlobalState on failed Tool
completion so Hermit can consume scheduler cleanup. Add a nondefault native
test support feature for combined production-path controls in Hermit.
