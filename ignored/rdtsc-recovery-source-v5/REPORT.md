# V5 timestamp terminal completion and public-loop ownership

Author source/caller preparation only. Nothing in V5 has been compiled or executed. V4 remains frozen with 40 accepted phases and 31 selected passes; both actual independent V3 source reviews remain changes requested. This candidate addresses the shared F1 source finding and Claude F2. F3 fixed-CPUID/subscribed-RDTSCP policy remains separate, with root preparing the actual native/ptrace/KVM witness. No CPUID, decoder, timestamp register writeback, branch accounting, Detcore scheduler or public API changes occur here.

The complete frozen response design remains unchanged. Its statement that the ClockTimestampTool exit-refusal assertion would remain unchanged was inconsistent with the actual Guest API. guest.rs documents that injected exit/exit_group never return and describes tail_inject as an optimization. Keeping an ordinary-exit refusal solely to preserve our own new unlanded assertion would impose a false contract. V5 therefore keeps both ordinary and tail explicit terminal injections, retains the original fork refusal, and replaces that obsolete ExitGroup(77)==ENOSYS assertion with execve==ENOSYS. Its exact returning getpid, three timestamp records, RPC/branch-clock and result assertions are unchanged. All historical test bodies and the measured V4 ownership fixture remain unchanged. Four new declarations add actual terminal/lifecycle, refusal, sibling and public-entry controls; one existing signal-hook refusal declaration is also selected because its private tail predicate becomes request-aware.

F1 requires the whole route: the private tail predicate accepts only SYS_exit/SYS_exit_group for Timestamp; ordinary injection admits those same two syscalls, including the concrete executor's second check. Every other nonreturning injection and every returning tail remains refused, including fork/vfork/clone/clone3, exec/execveat and signal-based terminal requests. SignalGuard, prepared signal, pending child start and post-effect notification gates remain unchanged. A successful real executor exit produces DoesNotReturn, and the timestamp driver now accepts only TailInjected { result: Ok(_), image_replaced: false, process_exited: true }. It hides scratch through the normal fallible path, requires an actual pending take_exit, publishes a real group exit when appropriate, and enters unchanged retirement/worker/consuming-hook supervision. It does not resume or write back the interrupted timestamp. Other tail outcomes remain errors; no refused operation becomes synthetic cancellation.

The new real static-ELF controls cover tail Exit(23), tail ExitGroup(29), ordinary inject of both calls, and a real consuming-hook EIO. They require one timestamp, exact thread/process hook statuses, empty successful output and no continuation into a second timestamp. Ordinary injection has an explicit panic if control returns to the Tool. The cleanup mode requires the complete exactly typed SharedFailure(EIO), not primary() flattening. Returning uname/getpid and fork/exec tails require exact ENOSYS with no resumed callback or child/image start; an actual initialized guest-memory marker must remain unchanged, so a mistakenly executed uname cannot pass. These are executable proposed assertions, not measured successes.

The sibling control creates a real Tool-owned clone3 worker. The worker parks in a real RPC within RDTSC; the leader reaches actual exit_group(17) and releases the worker's terminal RPC, then waits for the worker's consuming exit-hook acknowledgment before performing its original exit_group. The worker exits with 0; the leader/process with 17. Exact per-task exits, one worker timestamp, two starts and one process hook are required. The gates do not hold a mutex across an await. This proves only the planned backend/Tool ordering. It does not execute Detcore, a real ThreadExited response, the add_rdtsc charge or GlobalTimeLowerBound. The separately retained DETCORE-WITNESS-PLAN makes that coverage gap explicit.

F2 adds an explicit set_rdtsc_interception(false) at public run_with_tool entry, matching the other non-consuming loops. A real KVM control uses both initially armed and disarmed hardware CR4.TSD/backend states, executes real-mode RDTSC followed by an actual getpid vmcall and HLT, and requires cleared ownership/CR4 plus exactly one real syscall. Its Tool requests timestamp callbacks and panics if that unsupported public loop dispatches one. The test establishes entry ownership, not an ELF-to-real-mode image reuse theorem or public CPL0 trapping capability. Existing vmcall/default-Tool controls remain selected unchanged.

No test, guest, runtime, source-review or parity credit is claimed. All prior raw warning refusals, fault-helper failures, old pthread count failure, RIP diagnostic failures and actual independent review findings remain bound. Qualification can reveal a source or test defect and must stop on its first unaccepted phase. The exact new caller preserves original per-phase guards and limits, fresh artifact retention and raw skip audits. Actual current-Hermit composition coverage remains additional required evidence, not implied by these component controls.
