# Current-H39ac timestamp cancellation witness: preparation, not execution

The backend sibling control is not a Detcore composition witness. The independent native review explicitly asks for actual current-Hermit cancellation before and after timestamp charge/clock observation. No such run has occurred. H39ac source is retained in rdtsc-h39ac-same-run-v3/composition/hermit; its existing binary uses V3 production and cannot qualify the new terminal correction. A later owned composition must preserve H39ac bytes, bind V5 Reverie and its actual ignored Cargo.lock, and emit fresh source-bound Hermit/test-harness/manifest-plan binaries through the already reviewed build pattern. No build or guest launch is authorized by this document.

Actual paths, not an assertion that all interleavings are reachable:

* lib.rs:1337-1389 enters pre_handler_hook before add_rdtsc; prehook updates branch time and can trace events. lib.rs:601-618 yields only if its existing end_of_timeslice has expired. lib.rs:764-810 then awaits a real resource_request. Cancellation of that pending request can return ThreadExited before the timestamp charge. The prehook is not unconditionally a scheduler grant.
* After add_rdtsc and the existing INFO record, TraceSchedEvent can itself await when scheduling-event recording/replay is enabled (lib.rs:1352-1367). Then guest_clock_time always calls thread_observe_time -> global_time_lower_bound -> send_and_update_time (syscalls/time.rs:96-105; tool_global.rs:3222-3245). GlobalTimeLowerBound itself only reads the coordinator time (1273-1275); it is not an invented yield. The generic admission and final sender guards (930-986 and 1445-1457) can return ThreadExited. Reaching the RPC in source does not prove a peer can be scheduled within that particular await.
* After the clock returns, post_handler_hook may yield due to the real updated deadline (lib.rs:624-645). A cancellation there is after charge/clock, with no guest timestamp result yet written by the KVM driver. That is distinct from cancellation during GlobalTimeLowerBound.
* A leader's real Exit resource request logically removes siblings before its physical exit_group (tool_global.rs:1527-1557). send_and_update_time:2729-2738 tail-injects the actual Exit on ThreadExited. Normal syscall cancellation status and group publication remain owned by those existing paths.

Prepare one raw static two-thread guest (no libc timestamp census): leader clone3 creates a worker, then waits on a shared ready word through a real futex. Worker sets ready, performs the real futex wake, and enters a labeled finite RDTSC/RDTSCP sequence with explicit failure exits if it returns past the expected cancellation point. Leader performs actual exit_group(17). Retain exact ELF, labels, code bytes, all output, full trace/INFO and status. Use the established safehermit/observer/verify/log-file guards and original CPU/wall/output limits for each attempt. A normal exit status alone is never a hit. Do not add a Tool that fabricates ThreadExited, nor a mock scheduler/Guest, nor mutate production clocks to force a point.

Coverage predicates must use actual current-source trace order and task identity. A before-charge hit needs timestamp callback/prehook evidence for the worker's labeled instruction, real timeslice/resource wait, leader logical removal, and terminal response/tail exit before that callback's inbound-rdtsc INFO. An after-charge hit needs exactly one real add_rdtsc/INFO for that instruction, the actual clock request/response where observable, then terminal response before timestamp user continuation. Distinguish TraceSchedEvent cancellation before clock, GlobalTimeLowerBound terminal response, and posthook cancellation after clock; do not aggregate these under one label. Exact consuming cleanup/status and no extra callback/result must also hold. A failed KVM first attempt under the predecessor may establish the old defect only if it reaches the same point, not merely because it exits nonzero.

The ordinary strict sequential execution may exclude a concurrent peer grant during the non-yielding clock request; source alone does not settle every await boundary. Start with the actual strict deterministic configuration and its retained schedule/trace; if it hits only one point, report the other as unexecuted. Any bounded recorded-schedule/replay successor must be source-bound and separately prepared from the actual first trace, retaining its clock/turn effects. No seed sweep, instruction-count tolerance, comparator exemption, forced tombstone or unbounded retry is authorized here. A particular fixed schedule and complete launch caller cannot honestly be frozen before that first source-bound composition/trace exists. This remains a concrete evidence obligation, not component success credit.
