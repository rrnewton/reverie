## Original trace/chaos callers and the remaining coverage gap

* Trace replay: `--verbose trace-replay --strip-times --isolate-workdir`, forwarding `--base-env=empty --env=HERMIT_MODE=tracereplay`.
* Chaos trace replay adds `--chaos` and uses `HERMIT_MODE=tracereplay_chaos`.
* Chaos wrapper run uses `run --isolate-workdir`, forwarding `--chaos --base-env=empty --env=HERMIT_MODE=chaos --max-timeslice=1000000`.
* Chaos preemption replay uses `chaos-replay --isolate-workdir`, forwarding `--chaos --base-env=empty --env=HERMIT_MODE=chaosreplay`.

These are source-declared Buck identities, dependent on external fbsource build definitions; no Buck target resolution or local runnable/bounded command is claimed. No committed validation-DAG payload selects `hermit-verify trace-replay` or `hermit-verify chaos-replay`. The existing bounded run/record/chaos/analyze nodes above therefore do not discharge those wrapper routes. This is a coverage limitation to preserve in the eventual linear continuation, not a new landing or full-DAG gate.

`tests/util/hermit_verify_trace_replay.sh` is a different historical shell helper: it extracts only `finish syscall` lines and uses `git diff -w`. No new filter or weaker replacement was introduced. `hermit_analyze_e2e.sh` also compiles its own fixtures and invokes a shell analyzer; it was retained as source history, not executed or substituted for the current bounded Nextest node.

V5 removes active CHAOSRAND/SCHEDRAND filtering while retaining those records and producers. A trace/chaos replay or analyze phase that formerly hid their differences may now diverge. Existing wrapper command-construction tests prove strict argv, not unchanged analysis/replay success.
