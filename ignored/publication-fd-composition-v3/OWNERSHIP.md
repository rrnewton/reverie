The source paths below refer to this isolated successor. The complete predecessor ownership report remains applicable except for the stdin-specific transitions described here. A stable entry identity distinguishes the logical inherited slot; it is not an inode, a proof of OFD exclusivity, or a process generation.

| Path | Entry and ownership transition |
| --- | --- |
| elf.rs, `LoadedStaticElf` construction | Each initial loaded image has its own `stdin_entry_id`, including when stdin is absent. vm.rs assigns configured stdin before initial executor publication; runtime.rs assigns its capture fallback before `ElfExecutor::new`. Native fixture construction supplies a fresh identity too. These existing assignment sites need no new adapter. |
| executor.rs, `FileTableState::try_from_elf` | Initial/fork table creation clones required owners into staged files and copies the entry identity. A successful constructor gives local and authoritative owners distinct host descriptors referring to the same OFD. |
| `FileTableState::install` | Same identity plus same presence retains the exact local stdin File. A changed entry stages its required clone together with changed mapped entries before changing any local owner or metadata. Failure leaves all old handles and IDs intact; partial staged owners enter the existing retirement scope. |
| `FileTableState::update_from_elf` | Used by ordinary mutating writeback, accept writeback and exec. Preparation clones all required mapped files and any changed inherited stdin first. Only after success does it move the unchanged authoritative stdin File into the next table, replace the table and queue displaced owners. It does not take the old authoritative stdin early to manufacture a successful preparation. |
| elf.rs, `insert_file(0, ...)` | Return both an old mapped owner, if any, and the inherited stdin owner, if any. `take_stdin` invalidates the inherited identity. Existing callers queue the returned owners through FileRetirement. No final File destruction is added inside this method or either executor guard. Ordinary mapped descriptor insertion and entry-ID creation are otherwise unchanged. |
| executor.rs, `close`, `close_range` | Closing inherited fd 0 uses `take_stdin`, marks the standard slot closed, and retains existing metadata cleanup and retirement. Range closure reaches the same close operation. Closing a later mapped fd 0 removes that mapped owner; inherited stdin is already absent, so no fallback descriptor is resurrected. |
| dup, dup2, dup3 and received/opened fd 0 | Destination insertion creates a new mapped entry. Replacing inherited fd 0 retires the inherited owner through the caller's existing scope. A dup made earlier still retains the old OFD. No dup is used as an imported-OFD isolation guarantee. |
| fork / thread construction | `try_clone_for_fork_locked` carries the identity with its cloned stdin. Fork creates a separate FileTableState; a thread shares the authoritative table and receives its own local handle. Later installation retains that local handle while the entry is unchanged and observes closure/replacement when the shared entry changes. This does not establish cross-task epoll registration portability between different host descriptor numbers. |
| exec | `inherit_process_state_locked` carries the previous stdin owner and identity, discarding the new image's temporary loader stdin through deferred retirement. CLOEXEC removes the owner and changes the identity. Writeback retains the unchanged authoritative owner; displaced local, temporary and authoritative owners still retire after both guards. |
| exit | `release_files_on_exit` takes/invalidate this executor's stdin, detaches its table and queues local ownership after releasing both guards. A surviving sibling retains the old table. The registry/current-image behavior is unchanged. |

The identity field exists even for absence so every new image has a distinct initial slot identity without requiring callers to mutate two public fields in existing pre-publication setup. Matching requires both identity and presence. Production assignment of a new inherited File occurs before table publication; after publication, guest close and mapped replacement use the explicit take/insert paths. Replacing a File by arbitrary direct struct mutation after publication is not an authorized runtime interface. The loader's replacement image identity is superseded by the inherited process state during exec.

The old `insert_file` returned at most one mapped File. Its successor returns a Vec of displaced owners because fd 0 may also hold the inherited backing File. Every existing call site already consumes an iterator through `file_retirement.retire`, so no caller silently drops the extra owner. The common path returns an empty or single-owner vector. This is an internal ownership change; no Tool or Guest method changes.

The accept failure control uses real paths in this order: listener/client and regular sentinel setup; sibling replacement A0→A1; main first install clones A1 with allowance one; its real A0 retirement reaches the existing unlocked probe; that probe first checks live fstat ownership and simultaneous availability of both actual mutexes, then replaces A1→A2 through the sibling's execute path; main performs real host accept; second install sees A1/A2 mismatch and returns EMFILE with allowance zero. The accepted staged socket survives until both guards are released. The listener is unchanged and the sentinel is regular, so the observed socket cannot be a retired listener substituted for the accepted connection. The action is keyed to the old sentinel raw descriptor and guarded to run once even if that host number is later reused for the accepted socket. Both faulted and successful neighbors use this setup.

The direct real-EMFILE child continues to leave exactly one host descriptor slot free while two mapped entries require installation. Its explicit stdin duplication as an exhaustion probe remains valid; the production install need not duplicate unchanged stdin. It still verifies full original stdin/mapped state, positions, flags, identities, real epoll operations and the successful post-limit-restoration installation. Its direct table lock does not itself prove retirement ordering; the real executor retirement controls provide that separate observation.

No measured new failure or pass is asserted here. The intended first baseline failure is the actual `EPOLL_CTL_MOD` return after the implicit install at entry to execute, before later handle/readiness/DEL assertions. An explicit intervening getpid before that decisive MOD is deliberately avoided: host descriptor reuse could make the old implementation accidentally revisit a prior integer fd. The subsequent F_GETFL/getpid path checks both authoritative and local stability only after the same-oracle MOD has succeeded.
