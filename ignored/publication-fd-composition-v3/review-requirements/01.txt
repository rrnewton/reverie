  Concrete counterexample: run with pipe-backed stdin, create epoll, `EPOLL_CTL_ADD` fd 0, then `EPOLL_CTL_MOD` fd 0. The MOD call’s preliminary install creates a different host fd before retiring the ADD fd. Linux epoll registration identity includes the descriptor number and open-file description; using a different duplicate cannot modify the original registration and yields `ENOENT`. The same applies to DEL. The existing epoll preservation control covers descriptors in `files`, not inherited stdin ([executor.rs:24083](/home/newton/work/dev-hermit/worktrees/slots/kvm-setitimer-reverie-20260918/ignored/publication-fd-composition-v2/source/reverie-kvm/src/executor.rs:24083)).   Required correction: give inherited stdin an entry identity and preserve its existing local and authoritative host handles when that identity is unchanged. Clone before mutation only when stdin’s logical entry changed. Add a pipe-backed actual executor control exercising ADD → synchronization → MOD → DEL on fd 0.
