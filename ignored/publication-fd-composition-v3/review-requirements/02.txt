The common mechanism is explicit in `FileTableState::install` (executor.rs:1658): it currently clones stdin unconditionally and clones ordinary entries only when their per-entry markers differ. Every fallible clone precedes state replacement. `stage_clone` (elf.rs:511) decrements a test-only executor-local clone allowance; at zero it returns EMFILE before cloning. This is not a count of accepts, retired files, or authoritative writebacks. The later `try_from_elf` snapshot (executor.rs:1620) is a separate clone operation and must not be mistaken for installation.

The install-error control must retain its partial-clone proof. Open a third regular guest descriptor through the fixture's real open path before recording the original local handles. Create a sibling, and close/reopen all three slots through its actual `execute` path, checking that each reopen returns the same guest slot. The existing fixture already supplies a, b, and c; reopening c, including at the same inode, still produces a new entry marker. Do not issue another main-executor syscall before the faulting getpid, since that would synchronize away the stale entries. Then the existing `Some(2)` permits two genuine changed-entry clones and the third fails. No original local entry should have been installed, and the two staged clones must still be observed alive while both actual mutexes are obtainable. The next uninjected getpid must succeed. Merely changing `Some(2)` to `Some(1)` and the expected retired count from two to one would remove the existing two-owner partial-cleanup check.

The accept case requires an ordered setup, not a timing guess. `execute_accept` (executor.rs:1867) releases the first table guard and explicitly drains retirement at line 1882, then calls the real `accept_socket`, then reacquires the table and performs the second install at line 1893. Only after that second install succeeds does insertion and `try_from_elf(...).expect(...)` writeback occur. `accept_socket` (executor.rs:8686) actually calls libc::accept4 and wraps its returned owned descriptor. The existing connected client makes that host accept ready.

A concrete deterministic arrangement is:

1. Set up the original listener and connected nonblocking client, plus one ordinary regular-file sentinel. Create the sibling before enabling the main executor's clone fault. Keep the listener and stdin entries unchanged throughout this setup.
2. Use real sibling close/reopen to replace the sentinel at the same guest slot. Call the old local entry A0 and this authoritative entry A1. Record the old local raw descriptor and the entry markers. Record the authoritative guest-key set after setup; subsequent replacements must keep that set unchanged.
3. Enable the main executor's existing `Some(1)` allowance. The first install clones exactly the changed sentinel A1, consuming that allowance, and retires its old local A0 owner. This creates a real nonempty batch even after unchanged stdin ceases to retire.
4. Extend the existing cfg(test) retirement observation with a one-shot action keyed to that exact A0 raw descriptor. First preserve fstat-valid ownership and the existing separate-thread check that both actual mutexes can be held simultaneously. While still at this actual first-install drain, perform a second real sibling close/reopen of the sentinel, producing A2. Use the sibling executor and a cloned GuestMemory handle; its retirement queue and clone-fault counter are separate. Do not mutate the maps directly or enqueue an artificial retired File. The callback returns only after the peer mutation is complete, without sleeps or a race-dependent deadline.
5. Main now performs real host accept on the unchanged listener. It owns the returned socket as a staged File. Its second install sees local A1 versus authoritative A2 and attempts a clone with allowance zero, returning EMFILE before insertion or writeback.
6. Preserve every existing failure assertion: returned EMFILE, unchanged authoritative guest-key set, actual S_IFSOCK owner observed in deferred cleanup, client EOF, and both guards obtainable while that owner remains alive. The sentinel is regular and the listener was not replaced, so the failed path's observed socket cannot be a retired listener substituted for the accepted socket. Require the one-shot callback to have run exactly once. A useful direct discriminator is local sentinel A1 versus authoritative A2 immediately after failure, before any new main syscall: first installation committed, second installation did not.
7. Preserve the successful neighbor, with actual accepted guest descriptor, CLOEXEC, and close. Running the same two sentinel generations without fault injection also checks that the second install can succeed. Later cleanup callbacks must not repeat the sibling mutation.

This seam is available in the existing real cleanup path, not an invented drain helper. `drain_unlocked` takes the actual retired owners out of its short queue mutex; `destroy` keeps them alive while calling the probe and holds no queue mutex (elf.rs:460–499). `observe_unlocked_retirement` (executor.rs:25212) already obtains both table and transaction mutexes in the same spawned checker before releasing either. Preserve that check when adding the one-shot action. `thread_child_with_signal_observation` shares the authoritative file table and signal transaction but obtains a fresh retirement queue through `try_clone_for_fork_locked` (executor.rs:2334–2379; elf.rs:741–828). GuestMemory is cloneable with synchronized shared storage (memory.rs:25–61). The eventual Rust implementation still needs compilation and review; these are source-level reasons the ordered test setup is feasible.

Leaving `Some(1)` on an entirely unchanged table would not preserve this control: both installs would skip clones, then a later snapshot/writeback could fail or panic. A result observed there does not establish accepted-socket cleanup on second-install error. Changing the assertion to accept that later failure, reducing the test to a synthetic queue drain, relying only on nonempty observations, or counting a socket unrelated to the accepted connection would move the goalposts.

The real EMFILE child retains a stronger independent boundary. It already replaces two regular entries through a sibling, then forbids another parent syscall before directly testing install (executor.rs:25786–25834). Under its actual reduced RLIMIT_NOFILE it fills descriptors, frees exactly one slot, proves one clone succeeds and a simultaneous second clone fails, then releases that probe so install again has one free slot (25866–25923). With stable stdin, the two changed ordinary entries still require two clones. The first consumes the one slot and the second returns actual EMFILE. Deliberately cloning the authoritative stdin File as the exhaustion/probe source does not require install to clone unchanged stdin.

GOALPOST-MOVING REVIEW RULE

Adversarial reviewers must look explicitly for goalpost moving. We are extremely skeptical of any goalpost moving. YOU DO NOT CLEAR THE BAR BY SIMPLY LOWERING THE BAR.

Treat each of these as an explicit review target:
- weakening an assertion so a test passes
- widening a tolerance · adding an exemption · skipping a case · relaxing a comparator
- renaming or relabelling so a failure reads as a pass
- deleting a check rather than satisfying it
