`Mapping` owns one `Arc<EntryGate>`. Cloned handles share it; constructing another Mapping or taking a snapshot creates a fresh gate. Failure attribution is an optional private `FailureContext` on each GuestMemory handle and follows handle cloning, not all Mapping aliases. Custom Debug omits that context. The private integration interfaces are `GuestMemory::entry_gate() -> Arc<EntryGate>` and `set_failure_context(Option<FailureContext>)`.

All synchronous admission goes through the root-owned `EntryGate::copy_blocking(origin)`. Admission occurs before translation, permission/address-state and backing locks. Nested admitted helpers reuse `&CopyAccess` through the actual byte read, write, zero, discard, scalar/prefix copyout and operand probe, so a closer cannot make an admitted copy deadlock on reentry. Admitted helpers never acquire the allocation mutex. Existing enclosing allocation ownership remains permitted for snapshot/mmap; the closer must preserve the reviewed rule that it does not acquire that mutex. Memory helpers capture gate failure without publishing Tool failure, polling callbacks, or joining workers.

Both actual MemoryAccess adapters acquire short admission for each nonempty vector portion. They separate ordinary access/layout faults from the gate's retained failure. Gate poison observed at admission, before ordinary fault/partial handling, or after actual bytes produces EIO even when earlier bytes have already transferred. Effects remain intact; no successful prefix/full count is returned after observed poison. Typed methods return the retained Error cause. Empty trait operations still return zero. Healthy Accessible Tool writes, Writable copyout, scalar rejection, normal EFAULT and partial-prefix behavior retain their existing predicates. This is a checked boundary for observed poison, not a claim that an arbitrary later failure can retroactively change a completed call; the root-owned driver still has its pending-failure boundary checks.

Sparse backing-fd snapshot copying and retained host kernel operands do not hold long copy leases. The sparse helper and backing-creation/drop code are byte-identical. Snapshot fallback's actual byte reads and writes each acquire admission, and snapshot checks retained source poison before and after its work. Snapshot remains the existing allocation-serialized copy with its existing backing-lock scopes; this adds no global snapshot atomicity, independent-view entry exclusion, host-futex lease, remap/TLB, or shared-fork guarantee.
