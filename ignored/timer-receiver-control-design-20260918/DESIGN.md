# Bounded next receiver/control design, not implementation approval

Base: authored frozen-v3 SOURCE.patch e418322f4861a5148d3d52285d1b41028506113d17bd7f2e627e338a3a5029a4 on Reverie f97b7be1de4e2ef10ecc24cee5d8cc47f2fd254f. This note does not amend that component or its reviews. Existing own ordered primary grounding is reused with its exact identities. No new execution was performed for this design. Coordination is with the Hermit author, who owns scheduler wait membership, wake decisions and original syscall continuation.

A per-process receiver snapshot is feasible using existing authoritative state, but does not by itself implement deterministic recipient choice, repeated hook turns or interruptible native I/O. The first implementable seam should expose a coherent observation and bind a single actual selection to it. It must not simply remove sole_signal_receiver, or treat an external operation that happens to finish first as the eligible receiver.

## Source facts

`TaskLifecycleTable` in elf.rs binds task/process generations to weak SharedThreadSignalState endpoints. Registration clears an old numeric-TID endpoint; retirement removes it; exec rebinds the endpoint. The thread state contains the actual blocked mask and full admitted dequeue identity. There is no need to mirror masks in a second registry. However, callback site, prepared selection and process action currently reside in the executor, and KvmGuest's stack/notification/observation guards are local. The registry cannot currently tell whether another thread is at an eligible Tool callback or executing native work.

Existing lock order is lifecycle → process signals → thread signals. Lifecycle/process locks alone do not make all masks atomic: rt_sigprocmask, frame entry and sigreturn update a thread mask under that thread's lock. A coherent multi-member read must hold the actual relevant thread guards simultaneously, with fixed acquisition order, after validating their live generations/endpoints. It must audit other lock holders before implementation, and must release every guard before Tool callbacks or awaits.

Current `observe_parked_signal_impl` performs up to64 selections, releasing to asynchronous dequeue/structured Tool hooks between them. Actual selection prefers a thread-private pending signal over a process-shared signal. Thus a chosen alarm recipient does not imply that the next removal is SIGALRM, and a snapshot taken before the first hook cannot authorize all later selections after other hook turns run. The current FIFO proves ordering of actual removals and ownership of their acknowledgments; it does not freeze eligibility or determine the removing thread.

`KvmGuest::inject` executes `executor.execute` synchronously before it awaits notification or completion. `read`/`write_without_sigpipe`/`recvfrom` can invoke blocking host calls; the concurrent ppoll route can block in libc::poll; raw futex can block in a host syscall. No current API interrupts that specific operation from another Guest or returns its exact partial result through an asynchronous completion owner. A captured stdout write is a different path: it appends to CapturedOutput synchronously. This distinction must survive qualification.

## Proposed small interface and state seam

The following are proposed responsibilities, not final public spelling or a new user flag:

1. A process receiver observation returns one backend-issued snapshot identity, the full SignalProcessId, and every live member's full SignalTaskIdentity, authoritative blocked mask, and exact backend phase. Phases distinguish a usable CallbackSignalSite from guest execution, native injection in flight, callback notification/observation in flight, prepared selection, pending process action, unstarted task, and retirement. Unknown/in-flight is represented, never omitted. The snapshot includes a process eligibility revision covering membership, endpoint, mask and phase changes. The caller must not derive that revision from numeric TIDs or an arbitrary caller nonce.
2. To make that observation real, publish callback/phase identity beside the existing authoritative thread state, and advance its revision when eligibility changes. Scope transitions are owned by the actual callback/injection lifetime, including nested reborrows, cancellation and panic. A callback drop cannot leave a usable stale site. Native execute is marked in-flight before entering the synchronous call and changes only after the actual result is owned. No generic global channel or guest-mask copy is needed.
3. Hermit selects a full-generation member using its deterministic process policy at an actual scheduler control boundary. It must prove which guest/callback operations may progress there, retain original wait membership and Ivar ownership, and not pick by host completion order. This policy is not supplied by Reverie's FIFO.
4. A selected Guest consumes a one-use backend admission tied to that snapshot and its exact current CallbackSignalSite. Under lifecycle → process → all relevant thread locks, the backend revalidates the full member/mask/phase observation and chosen identity, then performs **at most one actual pending selection** before releasing the locks. A changed observation returns a distinct pre-removal stale result, with no queue/journal/resource change; the scheduler must reconsider rather than pretending the original choice succeeded. If the backend finds no eligible signal, it returns that actual result. An observed private signal remains private and precedes shared pending according to the existing selection rule.
5. That single selection retains the current irreversible-dequeue journal, owner callback, typed terminal failure and acknowledgment rules. Tool suppression, replacement, reblocking and caught/fatal preparation use the real event/domain. After a non-caught step, the result returns the actual step to Hermit before another selection. A subsequent shared selection needs another valid scheduler control/admission after any hook turns. No lock, mask snapshot authority or unconsumed assumed alarm removal spans a Tool hook.

This is additive to the existing single-receiver interface until a separately reviewed integration migrates it. Existing defaults and other backends retain their current behavior; no claimed capability is manufactured. Precise lifecycle publication/drop placement and a Rust borrow-safe implementation for holding multiple thread guards still need source review before code. Snapshot validation must include authoritative bytes as well as revision to avoid trusting an incompletely updated revision counter.

Process-alarm publication and receipt remain distinct from selection. Generalizing publication from any same-process live callback can reuse the shared pending queue and full-generation process validation; it must preserve standard-signal coalescing, full SI_KERNEL bytes, disposition/pending-generation facts, signalfd readiness errors and post-commit receipts. It cannot use the selected thread's mask as a substitute for all members' state. The current receipt has a single blocked field, so its meaning must be explicitly reconsidered at that API seam rather than silently relabelled. An alarm may remain shared pending with no currently eligible receiver. Publication does not start the next periodic interval; actual shared-SIGALRM consumption does. This note does not yet settle the generalized receipt shape or signalfd descriptor ownership across divergent thread file tables.

## Blocking host I/O is a separate missing capability

A registry read can inspect the authoritative mask of a worker blocked in native I/O without owning its borrowed Guest. It cannot run that Guest's hooks/frame or interrupt the operation. A proposed general timer path still owes a generation-bound operation owner that can request interruption, collect the real terminal/partial result exactly once, and return control to the same Guest before signal frame construction. Queued pre-operation requests instead owe preservation/reacquisition of the original resource grant. These are different states.

A complete design must identify concrete syscall classes and preserve their actual partial-count, EINTR/ERESTARTSYS, restart and ignored/blocked semantics. Marking a worker ineligible until its host call happens to finish is not a solution; waiting for an empty pipe read may deadlock the timer. A shared queue wake alone does not interrupt libc::read. Changing all backing OFDs to nonblocking would also require a separate proof because flags and aliases are guest-visible. No host-signal-based interruption, async framework, replay format, resource exemption or new refusal for an already accepted guest is selected here.

The practical next decision is whether Hermit's actual finite affected paths are still queued before native execution or have entered these calls. The author is tracing that distinction. Snapshot plus one-selection control can be reviewed independently, but it must not be described as completing the latter case.

## Finite controls for the proposed seam

- Two live processes, one armed parent: unrelated process membership must not fail the parent's generation validation or alter its selected pending set.
- Two same-process threads with opposite SIGALRM masks: snapshot lists both exact identities; deterministic selection reaches the unblocked member's real handler. Reverse masks and preserve the process queue/coalescing behavior.
- Change mask, replace endpoint by exec, retire/reuse TID, or introduce a newborn between snapshot and consume: original admission is stale before removal; all pending/journal/wait state remains intact. Consuming a token twice must not remove another event.
- Begin a native call or check out a stack after snapshot: stale before-removal refusal, never a fabricated parked site. Exercise actual callback cancellation/panic so no site remains usable.
- A higher-priority private signal precedes shared SIGALRM, and its real hook changes eligibility/needs another guest's turn: return the first step, then obtain fresh admission; preserve domain and notifications on every real removal.
- Actual signalfd/rt_sigtimedwait consumption while another control is pending must retain FIFO owner and shared-domain periodic rearm notification, including later copyout EFAULT; no reserved pending event disappears or is acknowledged twice.
- Distinct actual captured write, ordinary file/pipe write, and blocked external read controls retain original syscall outputs/partial counts and signal/restart results. The blocking case cannot qualify through the captured append route. It remains pending the separate operation-interruption design above.

No declaration, modeled scenario or source trace in this note is a runtime pass. The original component and Hermit failures remain evidence; no comparator/assertion/count/timeout change is proposed.
