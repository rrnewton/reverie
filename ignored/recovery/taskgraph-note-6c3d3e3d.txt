Exact fix:
- statfs and fstatfs on captured stdout/stderr and their dup, F_DUPFD, proc-fd, O_PATH, and fork aliases now query the capture owner's private pipe keeper, not ambient supervisor fd 1/2.
- Existing fstatfs canonicalization still clamps free counts and clears host-allocated f_fsid. Pipefs type, page sizes, zero counts, name length, flags, and spare fields come from a real private Linux pipe.
- Logical descriptor/path validation remains before copyout: closed or invalid fd returns EBADF, missing proc-fd path returns ENOENT, and a live capture with bad output returns EFAULT without modifying the buffer.
- Noncapture descriptors, ordinary-file replacement into guest fd 1, and synthetic-proc EACCES behavior remain on their prior paths.
- The exposed keeper accessor is deliberately named statfs_carrier and documented as metadata-only. Its read endpoint must not be reused as the future dup/reopen carrier because that would make a virtual O_WRONLY alias physically readable.
