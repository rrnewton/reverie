What changed

- Captured stdout and stderr now retain private read and write pipe endpoints at host fd 3 or above. The read keeper prevents POLLERR or HUP on the private O_WRONLY descriptor carrier. Guest identity remains the fixed synthetic FIFO identity and does not come from the host pipe inode.
- dup, dup2, dup3, F_DUPFD, F_DUPFD_CLOEXEC, O_WRONLY proc-fd reopen, and O_PATH proc-fd reopen no longer consult or retain the supervisor object occupying physical host fd 1 or 2. Dup-family aliases share virtual status; proc-fd reopen receives a fresh status description.
- File-table snapshot clones use F_DUPFD_CLOEXEC with minimum fd 3, so snapshots do not retain a closed physical standard slot.
- poll, ppoll, and raw select on an implicit captured output use the private O_WRONLY carrier and report exactly POLLOUT or the write fd-set, even when supervisor fd 1 or 2 is closed or reused.
- Captured O_PATH aliases now return EBADF for writev, current-position pwritev2, and lseek, matching scalar write behavior.
- O_RDONLY and O_RDWR proc-fd reopens are host-validated, discarded, then fail closed with ENOSYS. Captured bytes live in the bounded memory sink rather than the identity pipe, so exposing a read end would otherwise produce false EAGAIN, false EOF, or an unbounded wait. Linux access mode 3 retains the host FIFO EINVAL result.
- Captured epoll ADD, MOD, and DEL fail closed with ENOSYS before host epoll mutation. Registering the root-owned carrier would outlive the guest's final alias close and produce stale POLLOUT.
- Captured F_GETPIPE_SZ and F_SETPIPE_SZ return ENOSYS without reading or mutating host pipe capacity; O_PATH returns EBADF. Captured writes bypass that pipe, and forwarding these calls exposed host default and quota variability. Ordinary guest-created pipes retain existing host forwarding.
