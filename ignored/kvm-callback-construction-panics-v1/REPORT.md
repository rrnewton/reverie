# Callback construction panic retention

This is a source implementation packet for the concrete callback-construction P1. It is not an independent review or execution verdict. A Tool callback constructor can synchronously use its Guest, transfer a terminal error into `SharedHandlerSignal`, and then panic before returning its future. The prior driver accepted an already constructed future, so it could not retain that signal-slot outcome on this path.

The new private `drive_handler_completion_from<B, F, T>` takes a synchronous `FnOnce() -> F` factory, with `F: Future<Output = T>`. It invokes that factory inside its own `catch_unwind`; it does not wrap construction in an async block. On success it delegates to the existing `drive_handler_completion`. On construction panic it first takes the signal outcome through a poison-safe mutex lock, then separately catches destruction of the owned failure-notification future. The original constructor payload precedes any failure-future destructor payload. The selected outcome stays outside that destructor catch.

In the frozen `after/reverie-kvm/src/runtime.rs`, the complete signal mapping is at line 1779, the factory entry point at line 1801, outcome recovery at line 1824, and the separate destruction catch at line 1833. The existing driver now shares the same mapping for every variant: ParkedFatal, ParkedCancelled, ParkedRetired, ThreadCancelled, ThreadRetired, TailInjected with all fields, and RuntimeError. Static comparison confirms that its remaining body is byte-identical after removing the old local mapping and changing those two mapping references. Its ordinary failure/callback/child-start ordering is unchanged.

The appended declaration `runtime::callback_completion_tests::constructor_panic_recovers_owned_signal_before_failure_future_destruction` uses the real factory driver. Its constructor moves the only strong owner of a SignalEffects error into the actual shared signal slot and then panics while holding its mutex. No callback future is created or returned. The failure future's destructor requires that the poisoned signal slot has already been emptied and that the error allocation still has its owner. The test then checks the original error allocation, full typed error tree, dequeue records, publication metadata, raw result, and context allocation using the existing exact assertions. It requires zero callback polls/destructions, zero failure-future polls, exactly one failure-future destruction, and no pending-child gate release. It compares original constructor and destructor payload allocation addresses and ordering. The scenario runs with and without failure-future destructor panic. The returned completion future must be Send.
