# Child completion is an additional commit protocol

Append-only clarification after freezing REPORT.md c078791826f1e3f166615ff12f1513091cad58e14d1f1d0f3dbd4c2f42afbc26 and API.md 31273ea52e550407c143448f18bb50b579cd2674e703abd043ff7002bade569e. Those files and their first readback are unchanged. This is source design, not an implemented API or measured child-exit result.

The current backend lifecycle callback cannot simply be renamed as the missing scheduler handshake. In Reverie000c vm.rs:2175–2201, the worker first stores `ChildCompletion`, sends the numeric completion notification, and then awaits `on_backend_child_wait_event`. Thus parent-visible completion can precede that callback. Hermit v27 has no override. In its actual CLI configuration (`hermit-cli/src/lib.rs:2406`), `backend_reports_physical_process_exits` is true only for SaBRe. `begin_physical_process_exit` (scheduler.rs:2244–2259) consequently does not install that barrier for KVM. The daemon's existing empty-run-set check (scheduler.rs:1193–1201) cannot wait on a barrier that was never inserted. These are source facts, independently checked here after the scheduler author's message.

A correct H3 composition therefore requires a **new generation-bound completion rendezvous**. The scheduler author proposes: finish the real consuming exit hooks and acknowledge accounting; retain the actual terminal record in a run-owned staged completion before making the completion cell/notification parent-visible; send a staged record to the global owner; join it with the previously committed logical/accounting identity; then authorize the backend commit of waitability and pending SIGCHLD under the same short scheduler phase fence. Release the real parent completion notification after that commit. No stage may await progress by the parent guest, borrow its callback, manufacture an exit grant, or charge a new guest turn. Failed backend execution remains a failed run, not a SIGCHLD exit status.

This ordering requires explicit production changes to the current callback placement and completion-cell publication. It is **not** provided by the publication-only `publish_child_exit` method in API.md. The final paired interface must bind a staged-completion identity/owned handle and a one-shot commit acknowledgement, not an arbitrary newly reconstructed record. That handle lives outside the child's destroyed callback state and cannot be reopened by numeric PID. Its fields must preserve full parent/child generations, actual status/cause, guest UID and accounted CPU provenance. Staging can follow an acknowledged deregistration only if the new logical completion ticket already prevents the daemon from exiting or advancing past the missing record.

Waitability/SIG_IGN/SA_NOCLDWAIT policy must be resolved at the committed parent-state boundary rather than copied from a host-arrival-time sample. The backend commit must expose either the full completed waitability/publication transaction or a typed terminal failure retaining irreversible effects; it must not wake a parent with an incomplete signal transaction and call that success. Standard coalescence still permits one pending SIGCHLD for several independently waitable completions. Suppressed SIGCHLD is a valid publication result, not missing completion accounting. The exact staged-notification/commit interface and its startup, cancellation and final-join ownership are further design work coordinated with the scheduler author; this addendum does not approve it by implication.

The first finite positive obligation is ordinary caught normal-child exit with unchanged child identity, CLD_EXITED, actual status and waitpid status, including publication while no parent callback is arbitrarily borrowed. Preserve negative-before evidence and actual full canonical comparisons. Killed/core, stopped/continued, orphan/reparenting and broader job-control support are not inferred from that case. Parent reported a separate unchanged-source normal-child control is being measured; no result from that run is authenticated or claimed by this artifact.

The publication readiness distinction remains exact: setting a signalfd carrier makes a readiness observation possible; it does not resume guest instructions, choose a receiver or authorize removal. Actual signalfd consumption requires its own current single-use selection permission and real dequeue journal/ack. Parent completion notification similarly exposes a committed wait state; it does not itself deliver SIGCHLD.
