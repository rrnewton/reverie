# Process-directed pending publication without a borrowed Guest

Author proposal, source only. Reverie base `000c15a1161ea2d58749431b5ddaaa97f7aa37d5`, tree `a12d56466eed51cdd7d12087b5fafa9d66d8c864`; Hermit context is the separately bound frozen v27 source. No code, build, probe, guest, cache, index or ref was changed. This is not independent approval or a runtime result.

## Result and finite boundary

The smallest useful backend addition is a run-owned, explicitly installed process-publication endpoint. It resolves the **current** signal state and authoritative file table for a full process generation, then publishes pending state and updates virtual signalfd readiness as one synchronous transaction. It needs neither an available Guest callback nor a fabricated scheduler grant. A process handle alone does not fix H1/H2: deterministic authorization of shared removal and the real continuation of an interrupted wait are separate, required parts of the composed change.

The current H3 hole is concrete. `ElfExecutor::record_child_completion` (executor.rs:2336) inserts waitable status or accepts auto-reaping; it does not queue SIGCHLD. The child worker separately invokes `on_backend_child_wait_event` after storing completion (vm.rs:2175–2201). That event contains numeric parent/child identities, status and waitability. Hermit v27 has no `queue_child_exit_signal` caller or implementation of that hook; its scheduler Exit grant inserts a `ChildExit { child, parent }` timed key (scheduler.rs:4050–4072; scheduler/timed_waiters.rs:35–51). KVM dispatch only inserts `sigchld_ready` and potentially requeues a deferred parent (scheduler/parked.rs:480–488), without backend signal publication. That key cannot reconstruct UID, CPU time or the cause/status of every actual completion. Wait readiness and pending SIGCHLD must remain separate effects, with authoritative provenance carried to the scheduler commit point.

## Existing state that can be used safely

| Existing owner | Available information | Boundary |
| --- | --- | --- |
| Shared `TaskLifecycleTable` (elf.rs:137–365) | Live task generation, process generation, TGID, weak thread signal state, process exit state | No current process-signal/file-table registry; numeric lookup alone can select a reused identity. |
| `ProcessSignalState` (signal.rs:358–437) | Dispositions, shared pending, pending generations, signalfd mask aliases, real removal journal/ack/failure | Exec constructs a replacement Arc; retaining the old Arc is incorrect. |
| `SharedThreadSignalState` (signal.rs:440–539) | Current mask, private pending, alternate stack, dequeue identity and acknowledgement wake | It does not contain callback phase, saved registers, a borrowed Guest or a resumable wait. |
| Authoritative `ElfExecutor::file_table` (executor.rs:1074,1241,1605,4161) | Current owned Files, descriptor aliases, closed/replaced descriptors, CLOEXEC and signalfd membership | An executor's installed `state.files` snapshot can be stale relative to shared-table mutations. |
| Executor/runtime local fields | Callback nonce, prepared signal/frame, process action, pending exit, guest memory and registers | These are not safe to access through an unrelated callback or a weak signal-state pointer. Publish must not borrow them. A later phase snapshot needs explicit owner publication. |

`GlobalTool::Request` is serializable (tool.rs:119–151); it cannot carry an Arc control endpoint through `StartNewThread` or another ordinary RPC. A default non-RPC installation hook is the appropriate boundary. Runtime already creates G, a weak failure reporter and the root executor before entering the guest (runtime.rs:2554–2628). Install here, before `handle_thread_start` and the first instruction. An interested Tool must wait for installation before its scheduler starts using the endpoint. Setup rejection must use the retained-G failure/cleanup path. Other backends report unavailable during setup; they must not discover this after accepting a timer arm. The existing pre-G Host-thread/observed-dequeue refusal remains unchanged.

## Ownership and lifecycle proposal

Extend the existing shared lifecycle registry with a process entry keyed by `(tgid, process_generation)`. An entry contains weak access to current process signals and the authoritative file table, full live member identities/thread states, an internal binding revision, and a stable process transaction guard. Executor/driver owners retain the strong state; the endpoint does not keep a dead guest process alive. The registry and endpoint are run-owned, never host-global. The endpoint does not retain a strong G; close it before `Arc::try_unwrap(G)` at completion. A retained endpoint then returns `RunClosed` without touching old state.

| Transition | Required update |
| --- | --- |
| Root setup | Register the real process/task generations and current backing state before installation releases startup. |
| Fork | Register a fresh process generation and independent pending state before the child start gate opens; preserve inherited disposition/mask and empty child pending state. |
| Thread creation | Register the new full task generation and startup phase before it can execute or remove shared pending. Share the process transaction guard. Existing pending-at-clone refusal can be removed only with the recipient protocol below. |
| Exec | Under the same transaction, replace backing signal/thread Arcs and file-table contents, increment the internal binding revision and invalidate stale phase authorizations. Preserve the surviving process generation, pending signals and mask; preserve existing caught-action reset/CLOEXEC behavior. |
| Task/process retirement or failed preparation | Retire only the exact generation. Last retirement closes the process entry. Old handles cannot reach a later numeric PID/TID. Cleanup follows the same transaction order as publication. |

The exec update is mandatory: `LoadedStaticElf::inherit_process_state` (elf.rs:621–744) constructs `ProcessSignalState::after_exec` and a replacement thread Arc while keeping lifecycle identity, and `replace_after_exec` (executor.rs:2769–2795) installs the new image/table. A registry of initial Arcs would publish into abandoned state. Public process generation need not change on exec; an internal binding revision resolves this distinct issue.

## Synchronous publication and readiness

The proposed interface and outcomes are in `API.md`. It has two narrow operations: alarm publication and committed child-exit publication. It does not expose arbitrary guest-memory access, generic syscall injection, delivery or a generic host-signal channel.

1. The Tool determines the causal event at its committed scheduler boundary: the current timer arm/expiry, or an immutable child completion matched to committed lifecycle state. Host worker completion arrival order alone does not choose publication order. Child completion from all causally participating work must be reconciled before selecting the next guest turn; the scheduler author owns that fence.
2. Resolve/upgrade a process binding under lifecycle lock, release that lock, then acquire the authoritative file table, stable process transaction guard and lifecycle lock, in that order. Revalidate generation, binding revision and liveness; acquire process and needed thread locks afterward. A failed lookup or changed binding is a **before-commit** result. Never wait for the file table while holding lifecycle.
3. Preflight the complete event, pending capacity/generation and all current virtual signalfd carriers. Pin actual File ownership/aliases under the authoritative table; do not reopen numeric host descriptors later. Alarm requires exact SIGALRM/SI_KERNEL metadata; child publication constructs complete SIGCHLD metadata from the supplied completion record. No timer metadata is substituted for child metadata.
4. Publish/coalesce shared pending using existing standard-signal semantics. Preserve the first siginfo. SIGCHLD explicit SIG_IGN suppression remains distinct from default-ignore, SA_NOCLDWAIT/waitability and alarm Tool observation. The result describes process pending/disposition/coalescence, **not the publishing thread's mask**. Actual member masks belong to selection, not publication acceptance.
5. Compute readiness from the committed pending state. Release lifecycle/process/thread state locks, retaining the process transaction guard and pinned carrier ownership through bounded nonblocking carrier refresh. Release all locks before returning, invoking a Tool hook or awaiting anything. No normal guest I/O runs while holding this guard.
6. Before-commit rejection has no pending, carrier or removal effect. After pending commit, any refresh failure returns the committed receipt plus typed failure; never roll back pending, retry it as an uncommitted event, or return an ordinary success/errno that hides the committed effect. The existing terminal failure path must preserve first cause, secondary cleanup evidence and G. Do not re-enter the Tool failure callback from the endpoint while its caller holds the scheduler lock: poison backend control, return the typed outcome, complete the scheduler's terminal transition with its lock-held helper, then wake subscribers after unlocking. A publication receipt is not a removal acknowledgement and cannot rearm ITIMER_REAL.

The scheduler must process one source intent synchronously through receipt recording and intent consumption in that same lock section. This provides the proposed no-retry-ambiguity boundary. If the paired daemon instead needs a retry after an await/unlock, add a generation-bound publication ID and retained result; coalescing is not idempotence after a dequeue. A post-commit panic/error cannot be reconstructed as an untouched intent.

Backend serialization is necessary even with the scheduler fence. Existing `refresh_signalfd_readiness_for_signal` (executor.rs:7787) snapshots pending under locks and performs eventfd updates after unlocking. With a new out-of-callback producer, a dequeue or disposition change can intervene and an older snapshot can install stale readiness. The new stable transaction guard must cover **all** competing pending/readiness changes: the two publication paths, existing deferred/kill sends, the three actual consumers, SIG_IGN flushing, signalfd create/update/alias/close, exec rebinding and retirement. Mask changes, signal-handler entry/rt_sigreturn and phase changes also invalidate eligibility snapshots under that guard; masks do not themselves determine signalfd mask readiness. Existing public/default paths participate in the internal serialization even when they do not opt into scheduler selection.

When a path needs both file-table and signal locks, the order is `file table → transaction → lifecycle → process → thread`. Paths needing no table can start at the transaction, but cannot acquire a table afterward. Refactor helpers to avoid recursive acquisition. Pinning and allocation happen before irreversible mutation. `set_signalfd_ready` (executor.rs:7464) uses poll(0) and nonblocking eventfd operations; errors stay visible. The implementation audit must include direct executor/frame mutations such as `enter_signal_handler`, `restore_signal_thread_state`, `prepare_captured_page_zero_fault`, and teardown, not just the new publisher.

This guard does not certify physical quiescence. Some existing table-mutating dispatch can hold the table over native I/O. An unknown blocked host call must not be presented as a safe scheduler phase. The named-FIFO raw read is another explicit unsolved physical-blocking path; neither this mutex nor a journal wake interrupts it.

## Recipient, wake and continuation requirements

Publishing pending state is safe without an arbitrary callback. Selecting which member removes it is a different operation. `take_signal_event` (executor.rs:7831) currently prefers private pending, then shared pending under lifecycle/process/thread locks. In a multi-member process, whichever host worker gets there first otherwise wins. Relaxing `sole_signal_receiver` or the pending-at-clone check by itself is unsound.

The composed scheduler/backend change must therefore provide a fresh snapshot containing full process/member generations, image binding revision, current mask/disposition, pending generation, and owner-published execution/continuation phase. Callback nonces are included only where a callback exists; a true return-to-user boundary has its own actual owner phase. The scheduler matches this against its committed membership and chooses a permitted recipient using its deterministic policy. A single-use authorization is checked at the actual shared removal under the transaction lock. It must bind the selected task, current phase, consumer and pending generation. Stale exec/exit/mask/phase changes cannot consume it. An intervening private signal keeps private-first ordering; it cannot silently redirect shared authorization. Revoke unused authorization at phase exit, and require another deterministic decision before another shared removal.

This applies to return-to-user, signalfd and rt_sigtimedwait consumers, preserving their different mask rules. Actual removal still appends the existing full-owner/domain journal before later readiness or copyout failures, and existing acknowledgement ordering remains mandatory. The short scheduler fence may end after that removal and its acknowledgement; it must end **before** the actual Tool signal hook, which may issue scheduler, replay or priority requests. Holding a global fence across hooks can deadlock.

The publication endpoint need not invent a second generic wake channel. The scheduler already owns typed control Ivars and exact blocked-continuation identities. After publication, it can wake the selected supported continuation through that protocol without granting ordinary resources or charging a guest turn. A readiness notification only makes an owner eligible to inspect state: it neither resumes guest instructions nor authorizes a signalfd/shared-pending removal. Those require the real continuation and current single-use removal authorization respectively. Publication with all members blocked leaves pending state intact; an ignored/suppressed observation cannot finish a wait as EINTR. Actual readiness/timeout that wins on the original wait while a hook runs remains recorded against that same wait and must preserve its result while delivering any prepared caught frame. Polling retries and real resource grants retain normal accounting. Existing prepared-caught SA_RESTART/partial-I/O rules remain separate requirements; timed futex restart also needs its own exact Linux-family policy and preservation of the original deadline, not a renewed relative timeout.

Two existing wake mechanisms are **not** substitutes: `SignalDequeueWake` (signal.rs:442; executor.rs:3762–3831) wakes the next real removal owner after acknowledgement, and `GuestThreadGroup` SIGURG (vm.rs:425 onward) is terminal cancellation. Neither can make an arbitrary pending Guest future borrowable or convert a physically blocked native operation into resumable I/O. Driver phase publication and supported continuation service must be implemented explicitly; an AtomicWaker that merely repolls the same pending RPC is insufficient.

## Existing limits and child provenance

Virtual signalfd is currently restricted to one-thread processes: creation/update rejects live siblings (executor.rs:7558), fork rejects any existing signalfd (prepare_fork/fork_child), and thread creation rejects signalfd or shared pending (prepare_thread/thread_child). Dup aliases within one supported file table share the mask Arc and OFD. The endpoint must refresh those real aliases. A cross-process inherited signalfd carrier cannot be treated as a private readiness bit: current code explicitly refuses that case. This proposal does not silently remove that separate limitation, add new blanket timer refusals, or count it as fixing H2. The shared-pending thread restriction is directly in H2 scope and needs the selection/startup work above.

For H3, carry an immutable completion with exact parent and child process generations, actual exit cause/status, guest UID and accounted guest user/system CPU time in the signal ABI units. Parent generation is fixed by the committed parentage relation, not by reopening a numeric PID after the child exits. `BackendChildWaitEvent` and the numeric mpsc notification do not currently supply this whole record. The scheduler/child-lifecycle author must establish its producers, including final nonleader exit, exit_group, signaled/core deaths and failed backend execution. A backend failure is not a child exit status. Current `queue_child_exit_signal` accepts only CLD_EXITED/status 0..255 and its signalfd encoder fills child payload only for that case; genuine killed/core causes require corresponding typed encoding, not retagging them CLD_EXITED. These are explicit implementation obligations, not established current support.

Waitability and SA_NOCLDWAIT remain independently committed. Explicit SIG_IGN can suppress SIGCHLD publication even when blocked; auto-reaping cannot erase a required pending notification merely because a waiter no longer exists. Standard coalescing means several child completions can produce one pending SIGCHLD while each child's wait state remains correct. Disarm leaves pending ALRM; actual **shared dequeue**, including a coalesced first non-timer siginfo, controls periodic rearm. No receiver choice, fake hook, synthetic RNG event or host timeout is introduced to make a comparison pass.

## Finite implementation and validation sequence

1. Implement and unit-qualify registry lifetime, installation, exact-generation publication and serialized carrier refresh. Test no Guest callback exists; stale/reused process, exec rebinding and closed run; before/after-commit failures; blocked/ignored/coalesced ALRM and SIGCHLD distinction; supported dup/close/reuse signalfd aliases and forced snapshot/refresh races. Verify unchanged unopted paths and no strong-G retention. These are planned controls, not declarations or executions.
2. Compose the scheduler's committed child/timer event records and short phase fence with backend phase registration and actual shared-removal authorization. Require positive multi-member recipient/mask changes, startup/exit/exec transitions and private-first controls. Do not remove the old refusal before this positive path exists. Preserve all three dequeue consumers and failure-after-removal evidence.
3. Integrate each supported wait continuation with its actual wake, timeout, hook, partial result and restart behavior. Keep waiting for child completion independent from signal delivery. Include a handler blocked in its own RPC to prove the fence is not held across hooks. Test physical blocking/FIFO as its distinct prerequisite, without broadening accepted errno or reclassifying a timeout as progress.
4. Execute the original main-red timer/child expectations with unchanged comparisons, original resource limits and actual same-source inventories. Retain all old failures. A passing endpoint test does not establish full timer, SIGCHLD, multithread or record/replay parity.
