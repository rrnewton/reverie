This is an unexecuted experimental unit module, not a production change. It belongs inside vm.rs's existing tests module in a new source snapshot copied from qualified V6. The original V6 source, artifacts and active H39ac composition must stay unchanged.

The probe uses the real existing CPL3 static ELF loader and guest exception transport. Its baseline executes one CPUID then a distinct privileged HLT sentinel, checking all four result registers against the installed indexed table. The armed run must stop at the earlier CPUID RIP, with error-code-zero #GP and unchanged input leaf/subleaf and result-register sentinels. It observes feature-MSR query, exact state read/write counts and readback. A distinct backend remains unarmed while the first is armed, then the first is disarmed and must again reach the later HLT with correct table registers. An unrelated CLI still faults when CPUID faulting is armed.

These are three sequential disposable backends, each with the separate VM Reverie normally uses. This is not a same-VM multi-vCPU test. No callback, Tool accounting, CPU-policy repair, decoder, cancellation or scheduler behavior is implemented or qualified by this probe. It tests transport feasibility on the actual running kernel; source from another kernel cannot substitute for its result.

There is no unsupported-capability success or skipped branch. Missing feature/query/activation or an unexpected exit is a failed probe, preserving the first result. Before execution, prepare the existing bounded cold library-harness compile/list/test caller in the owned slot, bind the complete source and actual lock/dependency graph, and require a fresh retained ELF plus one exact selector. Use the established 600 CPU / 900 wall compile and 30 CPU / 60 wall test limits, 16 GiB memory / zero swap and output/free-space guards. No build or guest is authorized or claimed by this source-only document.
