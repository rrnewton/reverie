# Five-phase hardware probe qualification plan

This is prepared but **not authorized for execution yet**. Work is confined to the isolated source/caller under `ignored/cpuid-transport-probe-v1`, the proposed fresh target `target/cpuid-transport-probe-v1-cold-v1`, and the existing qualification lane lease after separate authorization. Live Reverie source, HEAD, index and branch must remain unchanged. No timestamp, Hermit, scheduler or CPUID policy implementation changes are included.

After approval, use explicit `PYTHONOPTIMIZE=0`, `python3 -B`, and record optimize=0/debug=true before invoking the preserved outer driver, which contains assertions. Do not invoke Cargo ad hoc. Admit the absent target using `qualification-v1/admit_target.py`: create one owned 0700 empty directory, import no artifacts, and bind its device/inode/owner. Then follow the complete `RUN-ORDER.json`:

1. `metadata`: the original observer/lease machinery executes `cargo metadata --offline --locked --format-version 1` on this exact source and its retained V6 Cargo.lock. Require accepted terminal accounting and source identity. Run the preserved `bind_dependencies.py` only after that result; it follows this actual graph from reverie-kvm and hashes the real external files/symlinks. Do not infer a fresh graph from a historical manifest.
2. `compile`: `cargo test --offline --locked -p reverie-kvm --lib --no-run --message-format=json`, two jobs. Require raw zero, no structured compiler diagnostic, one actual KVM library test ELF and unchanged inputs. Run `retain_artifacts.py` after acceptance. Require Cargo fresh=false, the exact manifest path and owned target, bytes different from the actual V6 lib harness, ELF magic and a distinct-inode 0555 retained copy. This whole-crate unit harness is the artifact; there is no claim of a separately linked integration rlib.
3. `format`: check both the test-only vm.rs include and new module with the bound nightly rustfmt and existing 2024/skip_children options. No source mutation during qualification.
4. `list-lib`: list the actual retained ELF. Record its actual full inventory and require the exact selected name once. Do not assume an inventory increment or count inventory as execution.
5. `probe-01`: run only `vm::tests::cpuid_fault_transport_probe::actual_cpuid_faulting_preserves_instruction_and_is_owned_by_one_vcpu`, with `--exact --test-threads=1 --nocapture -Z unstable-options --format=json`. The JSON reader must see exactly one started/ok declaration and a suite with one pass, no failure/ignore/measured case. Inspect full raw stderr separately for actual hardware observations and any skip/unexecuted message; libtest success alone is not a hardware proof.

Metadata and compile retain the established **600 CPU seconds / 900 wall seconds**; format, list and the one test retain **30 CPU seconds / 60 wall seconds each**. All phases retain 16 GiB memory, zero swap, 16 MiB lethal stderr, 64 MiB live stdout samples, 16 MiB phase reads, the 100 GiB free-space floor and the unchanged observer 137c9b42. Toolchain/nightly standard libraries, loader inputs, environment/config absence, full source/lock, SCM identity and lane inode/token are authenticated by the original helpers. No capacity, warning, comparison or result-accounting exemption is added.

Stop at the first unaccepted phase, retain its raw status and all stdout/stderr/accounting, and do not run later phases or retry with altered limits. Missing hardware support is a failed probe, not 77, skipped or expected-failure success. Final readback must distinguish five phase receipts, one selected declaration, five real guest entries across three disposable separate-VM backends, and the observed inventory. It must retain source/ELF identity before/after, actual MSR counts/states, all five fault sites/result registers and original lease terminal evidence. A failure halfway through earns no coverage for later steps.

The proposed experiment measures only transport feasibility on this kernel. It does not demonstrate a public CPUID Tool hook, one-time nondeterministic instruction accounting, fork/exec/worker lifecycle interception, CPUID policy parity, same-VM multi-vCPU isolation, full Hermit parity or timestamp cancellation. Those remain separate work. No new repeat, sweep or additional hardware probe is implied by this plan.
